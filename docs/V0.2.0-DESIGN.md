## 1. 定位转向(Q1 = B 增强)

| 维度 | v0.1.0 现状 | v0.2.0 目标 |
|---|---|---|
| **scope** | "web + mobile, backend / frontend, any N-end split" generic | **mobile-first**(Android / iOS / Flutter / RN / Harmony 5 stack first-class default),保留 N-end generic 抽象不删 |
| **抽象层** | `template/frontend-a/` 单 placeholder | `template/{android,ios,flutter,rn,harmony}/` 5 完整骨架 |
| **角色模型** | generic coordinator + N dev | 同(N-end 仍支持),但 default `sulde-init` 推 coordinator + 2 mobile dev(android+ios)|
| **design-source** | "pencil / figma / etc." 占位 | **Pencil MCP first-class default**,Figma / Sketch 等 optional |
| **enforcement** | UserPromptSubmit skill-trigger only(1 hook) | **11 hook 全覆盖**(协调端 + Dev + git path) |
| **README 信号** | "any N-end split" | **mobile-first banner**,N-end 在 "Beyond mobile" 子段保留 |

**理由**:v0.1.0 `.sulde-config.yaml.example` 已含 `stack: mobile-android | mobile-ios` 字段 → 设计原本 mobile-ready,只是默认示例单端;v0.2.0 把"mobile-first"作为 first-class default,不破坏 backend / web 等其他场景使用。

## 2. Enforcement scope(Q2 = C 全面 enforcement)

### 2.1 11 hook 完整清单

| # | Hook 类型 | 拦截路径 | 防 | 来自 |
|:-:|---|---|---|---|
| 1 | PreToolUse(Write) | `{frontend}/.ai-workspace/tasks/*.md` | 协调端 Write task md 缺 baseline 段 → 凭印象起草 | Freebeat `check-task-md-baseline.py` |
| 2 | PreToolUse(Write) | `{frontend}/.ai-workspace/handoff/*.md` | Dev Write handoff 缺 5 段 → 不实证 verify | sulde-cc 新设计 |
| 3 | PreToolUse(Bash) | `cd <frontend>/` | 协调端 cd 子端目录 → 子端 CLAUDE.md 注入污染 context | Freebeat `block-subdir-cd.sh` |
| 4 | PreToolUse(Bash) | `git commit` 无 `git as-*` | Dev 不强制身份 → AI 痕迹 / 历史混乱 | Freebeat `settings.local.json` PreToolUse |
| 5 | UserPromptSubmit | skill 触发词 | 协调端 / Dev 不读 skill 凭印象 | sulde-cc v0.1.0 已有(skill-trigger.sh)|
| 6 | UserPromptSubmit | 性能问题词("慢/卡/优化/perf")| 凭印象写 perf fix → 必先 diagnose | Freebeat `perf-gate` |
| 7 | SessionStart | cat CLAUDE.md(head -60)| session 启动不读规则 | Freebeat `cat CLAUDE.md` |
| 8 | pre-commit(git hook) | 主分支保护(main / develop)| 直接 commit 到 protected branch | Freebeat pre-commit § |
| 9 | pre-commit | 分支名格式(`dev/<author>/<slug>`)| 分支命名不规范 → 协作混乱 | Freebeat pre-commit § |
| 10 | pre-commit | 强制 `git as-*` alias | commit author 不明 | Freebeat pre-commit § |
| 11 | pre-commit | AI 痕迹 .claude/ / CLAUDE.md / .ai-workspace/ 不进 git | 对外交付暴露 AI 痕迹 | Freebeat pre-commit § |

**不抽**(项目特定):
- ❌ Freebeat `lint` failed(scripts/lint 是项目级 lint script,内容因项目变;sulde-cc 提供 hook 钩子,lint 内容用户自填)
- ❌ Freebeat `worktree` 拦(Freebeat 特定 worktree 路径)
- ❌ 协调端 Write pen-truth / ADR 拦(Freebeat 本 session 没在 Freebeat 实证 PreToolUse;§0.5.5/§0.5.6 在 skill declarative 层 — 留 v0.2.1+ enforce)

### 2.2 enforcement_level 全局开关(Q5 = B 加)

| Level | PreToolUse(Write) | PreToolUse(Bash) | pre-commit | UserPromptSubmit | SessionStart |
|:-:|:-:|:-:|:-:|:-:|:-:|
| **strict** | exit 1 阻塞 | exit 2 阻塞 | exit 1 阻塞 | stdout 提醒 | 注入 |
| **balanced**(default) | exit 1 阻塞 | exit 2 阻塞 | exit 1 阻塞 | stdout 提醒 | 注入 |
| **lenient** | stdout 警告 不阻塞 | stdout 警告 不阻塞 | exit 0 + 警告 | stdout 提醒 | 注入 |

**default = balanced** — file write + git path 硬拦(凭印象核心路径);prompt + start 软提醒。
**onboarding**(团队新装 sulde):暂用 lenient,熟悉后切 balanced。
**CI / batch script**:用 lenient 防阻塞自动化。
**严格期**(发版前):切 strict。

### 3.3 sulde-common.sh API

```bash
# Source by every entrypoint
# Outputs (exported vars):
#   SULDE_CONFIG_PATH   — .sulde-config.yaml absolute path(empty if not found)
#   SULDE_PROJECT_ROOT  — project root (dir containing .sulde-config.yaml)
#   SULDE_ROLE          — coordinator | dev | both | unknown
#   SULDE_FRONTENDS     — newline-separated list:name=path:stack
#   SULDE_ENFORCEMENT_LEVEL  — strict | balanced | lenient
#
# Functions:
#   sulde_find_config()                          # walk-up CWD找 .sulde-config.yaml
#   sulde_load_config()                          # set exported vars
#   sulde_get_field <yaml-path>                  # 读取 .sulde-config 字段(grep-sed 简单 yaml parse)
#   sulde_get_field_default <yaml-path> <default># 同上 + default
#   sulde_match_frontend_path <file_path>        # 判断 file_path 是否在某 frontend 下
#   sulde_get_frontend_subpath <file_path>       # 返回 file_path 在 frontend 内的相对路径
#   sulde_silent()                               # 检测项目无 .sulde-config.yaml 时,exit 0 静默
```

### 3.4 enforcement.sh API

```bash
# Source by check-*.sh
# Reads SULDE_ENFORCEMENT_LEVEL
#
# Functions:
#   sulde_exit_or_warn <severity> <reason>
#     severity: hard | medium | soft
#     reason:   stderr message
#
#     Behavior matrix:
#                   strict   balanced   lenient
#     hard (write)  exit 1   exit 1     stdout
#     medium (bash) exit 2   exit 2     stdout
#     soft (prompt) stdout   stdout     stdout
#     注入 (start)  返回     返回       返回
```

由 Agent 调用 `template/<stack>/scripts/pre-commit-installer.sh` 安装 `.git/hooks/pre-commit`:

```bash
#!/usr/bin/env bash
# .git/hooks/pre-commit(由 sulde install)
# 内部 source sulde lib

source "${SULDE_PLUGIN_ROOT}/hooks/lib/sulde-common.sh"
sulde_load_config

# 4 类检查
source "${SULDE_PLUGIN_ROOT}/hooks/lib/check-branch-protect.sh"   # 主分支保护
source "${SULDE_PLUGIN_ROOT}/hooks/lib/check-branch-format.sh"    # 分支名 dev/<author>/<slug>

source "${SULDE_PLUGIN_ROOT}/hooks/lib/check-ai-traces.sh"        # AI 痕迹禁进 git

# 可选项目 lint(由项目配置声明，Agent 读取并执行)
LINT_CMD="$(sulde_get_field_default 'enforcement.lint.cmd' '')"
if [ -n "$LINT_CMD" ]; then
    eval "$LINT_CMD" || sulde_exit_or_warn "hard" "Lint failed"
fi

exit 0
```

```yaml

#
# Copy from `.sulde-config.yaml.example`. All v0.2.0 new fields are optional
# (sensible defaults). Only required: enabled / role / frontends / docs_hub.

# ─── v0.1.0 已有(保留)─────────────────────────────────────────────

frontends:
  - name: android

  - name: ios

design_source:
  mcp: pencil                     # pencil | figma | sketch | custom

team:
  - alias: as-a

  name: my-mobile-app

# ─── v0.2.0 新增(全 optional + sensible defaults) ─────────────────

# Dev 自发修复敏感清单(项目自填,无 default — 因项目特定)
scope_sensitivity:

  sensitive_scaffolds: []         # e.g., [AppTopBar, AdaptiveBaseActivity, AdaptiveScaffold]

  index_path: ./docs-hub/ADR/INDEX.md
  frontmatter_schema: ./docs-hub/ADR/_frontmatter.schema.yaml
```

### 5.2 sensible defaults 矩阵

| 字段 | default | 何时 override |
|---|---|---|
| `enforcement_level` | `balanced` | CI / batch → lenient;严格期 → strict |
| `enforcement.task_md.required_sections` | `["§起草前 baseline 实证", "## §0 baseline"]` | 项目用英文 sentinel → 改 `["## Baseline"]` |
| `enforcement.handoff.required_sections` | `["改动文件清单", "## §verify"]` | 项目段标题不同 → 改 |
| `enforcement.branch.pattern` | `^dev/[^/]+/.+$` | 项目用 `feature/`/`bugfix/` 前缀 → 改 |
| `enforcement.branch.protected` | `[main, develop]` | 项目用 `master` / `release` → 改 |
| `enforcement.ai_traces.forbidden_paths` | `[".claude/", "CLAUDE.md", ".ai-workspace/"]` | 项目允许 .claude/ 进 git → 改空 |
| `session_baseline.claude_md_inject_lines` | `60` | 项目 CLAUDE.md 短 → 改 100;长且只想要 index → 改 30 |
| `build_verify.<stack>` | 每 stack 内置 default 命令 | 项目命令不同 → 改 |
| `scope_sensitivity.sensitive_files` | `[]` | **项目首装时必填**(用 `/sulde-add-sensitive-file <path>` 增量) |

### 6.2 `configure-sulde` skill(1 skill 复用 4 commands)

```
skills/coordinator/configure-sulde/
└── SKILL.md
```

#### SKILL.md spec

```markdown
---
name: configure-sulde
description: Use when user types `/sulde-init` (first-time setup) or `/sulde-add-{sensitive-file,scaffold,skill-trigger}` (incremental config). Interactively guides the user through filling `.sulde-config.yaml` fields, generates the file (or appends to existing), and verifies the result. Mode = command name suffix; falls back to `init` if no mode given.
---

# configure-sulde

## Mode dispatch
- `/sulde-init [project-dir]` → mode=init
- `/sulde-add-sensitive-file <path>` → mode=add-sensitive-file
- `/sulde-add-scaffold <name>` → mode=add-scaffold
- `/sulde-add-skill-trigger <regex>` → mode=add-skill-trigger

## Mode: init(对话式 7 步)
1. Detect existing `.sulde-config.yaml`(confirm overwrite/append)
2. Q1: project name(default = dir basename)
3. Q2: role(coordinator / dev / both,default coordinator)
4. Q3: stack 多选(default [android, ios],可加 flutter/rn/harmony)
5. Q4: design source MCP(default pencil,可选 figma/none)+ file 路径
6. Q5: team(每个 frontend 1 个 alias,Q4 选了几 frontend 就问几次)
7. Q6: enforcement_level(default balanced)
8. 生成 `.sulde-config.yaml` 写入 project root
9. 若 role: coordinator → 提示 mkdir docs-hub/ + 跑 `coordinator-baseline.sh`
10. 若 frontend stacks → cp `template/<stack>/` 到 user_project/<stack>/
11. 输出 "next steps":
    - `/sulde-add-sensitive-file <path>` 加敏感字段
    - `/clear + /assign` 派 task md
    - 装 git pre-commit hook:`bash <frontend>/scripts/pre-commit-installer.sh`

## Mode: add-sensitive-file
- Args: <file-path>(必填)
- Read existing `.sulde-config.yaml`
- Append to `scope_sensitivity.sensitive_files: [...]`(去重)
- Verify yaml 仍 valid
- 输出确认 + diff

## Mode: add-scaffold
- 同上 mode pattern,append 到 `scope_sensitivity.sensitive_scaffolds`

## Mode: add-skill-trigger
- Args: <regex> <skill-name> <reminder>
- 同 pattern,append 到 `skill_triggers`
```
