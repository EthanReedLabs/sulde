## 2. 本轮源码修复

- 仅允许当前有效首次 legacy→stable 迁移的精确逆向；后续 stable 更新使其
  不再符合条件。不是通用降级、force install 或任意历史回滚。
- 原 committed journal/snapshot 保持不可变；逆向使用独立类型的事务，仍共用
  唯一 active owner、部署锁和 generation fence。普通安装拒绝未结束的逆向。
- 独立维护宿主/持有源码 worker 复用既有原生决定接口；草稿和旧安装回执不
  产生新的逆向权限。只有持久化启动后的同一事务可进行机械恢复。
- 租约目录永久绑定 canonical path/device/inode；审批后目录整体替换，或恢复时
  用空目录代替原 scope，均在恢复写入前拒绝。
- 修复 active 发布后、fence 尚未创建即崩溃的清理路径：恢复后重新读取匹配的
  fence 再清理，不能沿用恢复前的空观测。
- 旧 snapshot 目标按 canonical path 匹配，避免 macOS `/var` 与 `/private/var`
  别名导致正常逆向误拒绝。
- 持有源码清单补齐直接依赖 `hooks/lib/kb_cli.py`；没有放宽未密封模块拒绝器，
  也没有把其他无关 Hook 模块纳入清单。

正常入口实际经过 shipped prepare CLI parser → prepare_bundle → held BOOTSTRAP
→ operation_context/execute_operation → 真实事务恢复消费者。进程清单、CLI 和
scheduler 使用隔离外部边界夹具；不是实际人类审批、实际 production launchd 或
用户宿主停止演练。生产控制器与闭合 dispatch 本身未替换。
