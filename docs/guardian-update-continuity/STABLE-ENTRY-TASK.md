## 一个交付与明确限制

实现 POSIX Codex 的缓存外 Hook 启动入口，复用现有 Guardian、严格恢复
分类和独立观察器，不新增授权层。旧的已冻结缓存绝对命令不能假装热迁移。
本轮不安装生产、不推送、不合 dev/main、不运行付费模型，不清理真实旧资源。
Windows 保留原路由并单列未验收。新旧证据各自保留，不覆盖前轮结论。

- 独立复核者：只读审查集成及关键反例，不兼任实现者。

宿主命令固定为缓存外 bin/sulde-codex-hook，产品根遵循 SULDE_HOME /
portable SULDE_KB_HOME / HOME/.sulde 的既有规则。包只携带当前 run-hook.sh、
_recovery_defer.py、_hook_observer.py 必要字节；正常仍转发当前 intent-guardian
codex-hook。不可变包身份与静态入口绑定，不猜最新目录。发布先准备校验再

安装器复用现有事务：首次 registry mutation 之前准备新入口；bootstrap

发现旧缓存命令或覆盖未知时，在任何生产变更之前拒绝；新会话 canary、
peer JSONL、无心跳、最近 generation 正确均不能构造全体旧调用者迁移证明。
本轮不新增 --force / 人工勾选已排空 / 伪造迁移回执。缺少宿主退出/原位
重载及防新旧调用者竞态的证据时，正式首次迁移保持明确待办。

## 验收顺序与停止条件

正常对照 → 外部边界注入 → 真实 CLI/入口 → 受影响模块 → 集中集成复核。
验证未启动入口在缓存删除后仍可达（新稳定命令，不偷换旧命令）；Read 保守
降级、Write/unknown 拒绝；坏包/摘要漂移/无解释器不得静默放行物质动作。
验证发布失败旧指针保留、失败/硬退出恢复、六事件唯一且无用户级重复注册。
分清 synthetic/隔离入口与真实宿主信任验证，后者未做就不称生产已就绪。

既有 130 项和 B 两项只覆盖旧源码范围，按输入等价复用；改变消费者须重测。
正常热路径交叠配对至少五组，median 增量预算 max(20ms,5%)，P95
max(50ms,10%)。超预算先优化，不改预算。已知阻断未关闭前不重复昂贵全量；
达到新冻结源码边界后按影响矩阵决定全量。相同失败两次无新证据换方法。

每包先独立自测和提交，协调端统一集成同一分支后独立复核；不自标 accepted。
证据写唯一目录，Optimus S3-C-repair 下归档，源/命令/实际输出/退出码/
身份范围及自排除摘要齐全；普通测试不修改历史证据。

## 集成复核中的兼容性要求（不扩授权）

坏 launcher 但原 runtime 可验证时，缓存外入口必须保留既有 native recovery
路由；不能因为稳定包不再位于原 cache/scripts 而一律改走普通拒绝分类器。
仅在正常桥失败后验证受保护 manifest、runtime 与 adapter 身份，再复用原恢复
授权/执行链；验证失败仍严格降级，不新增宽泛的恢复命令白名单。
正常成功热路径不得增加整树扫描。旧稳定 bootstrap 以其密封的预期摘要核验，
不同源码版本升级不能要求旧入口等于新代码的重新渲染结果。
