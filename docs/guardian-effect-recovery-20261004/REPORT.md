## 根因校正

原问题不是简单的“verifying 未终结”。只读回放显示原 attempt 已进入
`unknown`，经历八轮重探，最新 intervention 为 `abort`。abort 不证明外部效果
成功或失败，普通 HumanGrant 也不能替代效果证据。

后续命令实际经 SSH 在远端创建目录，被旧分类器误认成目标不明的本地写入。
旧、新命令的目标地址字面量不同，但没有验证 SSH 配置与实际远端资源，不能据此
宣布二者互不相关；不同命令摘要同样不是不同资源的证明。

源会话还证明：`verification_kind=unsupported` 仍可反复申请重探，形成没有可满足
验证契约的恢复循环。停止后又没有“绑定新证据→重新审查”的有限恢复入口。

## 已修复

1. SSH 运输边界：直接调用及 env/sudo/doas/command/exec/nohup/timeout 包装的
   受支持形状不再把远端路径当本地路径。明确远端建目录是 external_write，明确
   删除保持 destructive；不可证明的操作保持 unknown，不伪造 read。
   SSH 资源保持 unresolved-remote-target；命令摘要仅作调用标识。
2. 阻断原因区分已证明同一目标、显式依赖、资源身份未证明。HumanGrant 路径也采用
   同一解释，不再把“不能排除冲突”说成“已经证明相同”。
3. unsupported 重探在原生审批展示前、审批 CAS 和最终裁决入口均被拒绝；报告和卡片
   列出缺失的验证基础。保留既有密封内容摘要维护重查与历史 unsupported 事件重放。
4. `prepare-effect-recovery` 只开启审查：必须 unknown、最新裁决 abort、具有绑定
   的验证契约和可证明的资源身份，并且出现未用于既往 abort 的新证据基础。
   完整绑定摘要用于 CAS，独立证据摘要用于判断新颖性；重复历史行、操作 nonce 和
   循环回旧证据均不能冒充新事实。
5. 重用现有合同锁、追加式事件、投影重放和原生 effect-intervention 决策通路。
   准备不授权、不转移会话权限、不结算债务。旧轮次 takeover 不再被新轮次消费。

新 API 不接受任意新目标或“已成功”的自述；证据绑定仍须经既有严格 CAS
`resolve_attempt_target` 生产者链生成。ready 字段表示最低验证契约可用，
不是“验证已完成”、远端可达或宿主已提供该读取工具的证明。

## 尚未完成与下一阶段

生产原 attempt 仍是 unsupported + 不透明资源身份；本轮不修改它、不宣布解除阻断。
本轮解决的是分类、解释、无效重探与有限恢复机制，不是伪造远端事实的 supersede。

下一阶段需要独立批准发布/安装，然后为原操作确定可核验远端资源和后置条件，
准备只读验证适配/绑定。只有获得真实证据后才能经新入口开启审查、原生确认并
独立结算。缺失绑定时保持明确阻断；无需让人复制摘要或手工移动账本。

新恢复事件投入生产前需确认 Codex/Claude 实际加载的消费者都包含本轮隔离语义；
旧代码能读取新增字段不代表理解新的授权时效规则。不得混合新写者、旧消费策略
后宣布生产闭环。没有本轮生产安装或远端探测授权，故在源码交付边界停止。
