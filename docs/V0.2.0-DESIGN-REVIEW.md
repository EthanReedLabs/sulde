## 2. Claude Code 协议合规 review(subagent 1 摘要)

### 🔴 P1 阻塞(协议层错,P1 实施一开始就翻车)

#### C1. PreToolUse hook JSON 格式错

**问题**:DESIGN §4.2 stdout JSON 用 `{"decision":"block","reason":"..."}`,但 Claude Code 协议要求 **`hookSpecificOutput` 包装**:

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "..."
  }
}
```

**影响**:check-task-md-baseline.sh / check-handoff-verify.sh / check-subdir-cd.sh / check-git-commit-alias.sh **4 个 PreToolUse 子 hook 全部要改输出格式**。

#### C2. SessionStart "stdout 注入 context" 协议不存在

**问题**:DESIGN §4.2.7 期待 `cat CLAUDE.md | head -60` stdout 直接注入到 Claude context。**Claude Code 协议无此机制** — SessionStart hook 只能输出 statusMessage 给用户看,无法注入任意文本到 Claude context。

**影响**:DESIGN §3.2 session-start.sh entrypoint + §4.2.7 claude-md-inject.sh 都需重设计 — 改为:
- 选项 A:hook 输出 statusMessage 提示用户 "请 Read CLAUDE.md"
- 选项 B:用 PreToolUse hook 的 `hookSpecificOutput.additionalContext` 字段(但触发时机不同)

#### C3. exit code 2 与 exit code 1 协议无区别

**问题**:DESIGN §2.2 区分 exit 1(write 拦)vs exit 2(bash 拦),但 Claude Code 协议两者都是 blocking。

**影响**:`enforcement.sh` `sulde_exit_or_warn()` 不能依赖 exit code 区分语义;改为统一 exit 1 或 0,**用 stderr message 区分**。

### 🟡 P2 中等

#### C4. `.claude-plugin/plugin.json` 缺 `hooks` 字段声明

**问题**:v0.1.0 plugin.json 只有 `skills` 字段,无 `hooks` 字段;Plugin v2 协议应在 plugin.json 显式声明 hooks 路径。

**修正**:加 `"hooks": "./hooks/hooks.json"`(待 verify 实际字段名)。

#### C5. hooks.json matcher 字段示例缺

**问题**:DESIGN §3.2 hooks.json 例子 hooks 数组无 `matcher` 父级,实际协议 PreToolUse 数组每项需 `{"matcher": "Bash|Write", "hooks": [...]}` 分组。

**修正**:hooks.json 内 PreToolUse 拆 2 个 matcher 条目(`"Bash"` 和 `"Write"`),分别 dispatch 到 pre-tool-use.sh(内部再 case 分发)。

#### C6. SKILL.md frontmatter 字段 `user-invocable: true` 非协议字段

**问题**:Claude Code Skill 协议 frontmatter 必填 `name + description`,`user-invocable` 是 mattpocock skills 系列自创(可能非协议字段)。

**修正**:确认 Claude Code Skill v2 协议字段后,DESIGN §8 SKILL.md frontmatter 段更新。

## 4. 新需求:跨平台路径支持(2026-05-24 用户补充)

### 痛点

用户场景:**1 个 sulde-cc 项目被多个 contributor 在不同 OS 上开发**(macOS + Linux + Windows),或同 1 个用户跨 OS 切换。

**当前 V0.2.0-DESIGN.md 假设 Unix-like 单一 OS**:
- 所有 hook 是 bash script(`*.sh`)— Windows native cmd / PowerShell 不可跑
- 路径用 `/Users/eric/...` 风格 — Windows 是 `C:\Users\...`
- shell 命令(`grep -rn` / `find` / `mv` / `cp`)— Windows native 无,需 Git Bash / WSL
- `.gitignore` LF line ending — Windows checkout 可能转 CRLF 致 hook 跑不起

### 跨平台兼容矩阵

| 组件 | macOS | Linux | Windows native | Windows WSL2 | Windows Git Bash |
|---|:-:|:-:|:-:|:-:|:-:|
| sulde hook(bash .sh)| ✅ | ✅ | ❌ | ✅ | ✅ |
| sulde hook(Python)| ✅(需 python3)| ✅ | ✅ | ✅ | ✅ |
| sulde hook(Node)| ✅(需 node)| ✅ | ✅ | ✅ | ✅ |
| `.sh` line ending | LF | LF | CRLF(checkout 自动转) | LF / CRLF mixed | LF |
| Path separator | `/` | `/` | `\`(but `/` works in many cmds) | `/` | `/` |
| Claude Code CLI 支持 | ✅ | ✅ | ✅(via Node) | ✅ | ✅ |

### 设计候选

#### A. Hook 全部 Python 化(主推)

- 所有 `hooks/*.sh` 改 `hooks/*.py`(`pre_tool_use.py` / `user_prompt_submit.py` / `session_start.py`)
- `hooks/lib/sulde_common.py` 用 `pathlib` + `yaml`(`pip install pyyaml`)
- `hooks.json` command 改 `"python3 \"${CLAUDE_PLUGIN_ROOT}/hooks/pre_tool_use.py\""`
- pre-commit hook(git-side)保留 `.sh`(git hooks 只能 bash;Windows checkout 时由 Git Bash 跑)

**优点**:
- ✅ Windows native 跑(假设 Python 已装,大多数 dev 机器有)
- ✅ yaml parse 用 pyyaml(防 B2 盲点 grep-sed 碎)
- ✅ `pathlib.Path` 自动 OS-aware 路径分隔符
- ✅ subprocess 调用 native command 隔离 OS 差异

**缺点**:
- ⚠️ 引入 Python 依赖(用户机器需 Python 3.6+,但 mac/linux 自带,Windows 99% dev 装过)
- ⚠️ Freebeat `check-task-md-baseline.py` 已是 Python(本 session 实证可行)— sulde-cc 现有 bash skill-trigger.sh 需重写

#### B. PowerShell + bash 双套 hook

- 每个 hook 维护 `.sh` + `.ps1` 双版本
- `hooks.json` 用 OS detection 分发(`if [ "$OS" = "Windows_NT" ] then .ps1 else .sh`)

**优点**:每端 native shell
**缺点**:维护 2 套,重复 bug,**不推荐**

#### C. Node.js hook(JS / TS)

- Claude Code 本身用 Node,假设用户已装 Node ≥ 18
- `hooks/*.js` 或 `hooks/*.mjs`

**优点**:Claude Code 用户必有 Node;npm yaml library 成熟
**缺点**:JS 写 system-level hook 不如 Python 直接;sulde 现有无 Node 代码

#### D. 限制 sulde 仅 Unix-like

- README 明确:"sulde-cc requires macOS / Linux / WSL2 / Git Bash";Windows native cmd 不支持

**优点**:0 实现成本
**缺点**:**违反用户新需求**,不可

### 推荐:**A 全 Python**(替代当前 bash 设计)

理由:
1. 跨 OS 完美 + Python 装机率 ~99% on dev machines
2. yaml parse 鲁棒(防盲点 B2)
3. `pathlib` 防路径分隔符 bug
4. Freebeat 本 session 已实证 `check-task-md-baseline.py` 工作 ✅
5. shebang `#!/usr/bin/env python3` 跨平台

### Schema 跨平台 awareness

`.sulde-config.yaml` 新增 per-OS build_verify(若需要):

```yaml
build_verify:
  android:
    build_cmd:
      unix: "./gradlew :app:assembleDebug"
      windows: "gradlew.bat :app:assembleDebug"
    install_cmd: "adb install -r app/build/outputs/apk/debug/app-debug.apk"  # adb 跨 OS,无需分支
```

或更简洁:全用 unix 风格 + Windows 文档说明 "请用 Git Bash / WSL2"。

### 影响范围

| Section | 修订 |
|---|---|
| §3 hook 架构 | bash → Python(3 entrypoint .py + lib/*.py) |
| §4 hook 行为 | 11 子 logic 改 Python class / function |
| §5 schema | 加 per-OS build_verify(选)+ README 加 OS 兼容说明 |
| §7 template 5 stack | scripts/pre-commit-installer.sh 保留 .sh + 加 README "在 Windows 用 Git Bash" 说明 |
| ROADMAP | P1 工时调整(Python 重写 ≈ bash 同工时,~10-12h)|
