## 自动链的观察范围

[R1-native-posttool.json](R1-native-posttool.json) 来自最终全量中的真实宿主执行。每次原生工具退出码均为 0，工具动作计数总共 4；项目和第三方 Hook 失败被观察为非零/异常，Sulde 内层运行时失败在非阻塞适配器返回前记录。工具成功、Hook 结果、审计送达是独立字段；`business_effect` 仍为 `unverified`，审计不结算业务效果，也不触发重做。

新会话→恢复同一会话→同一会话切换 worktree→另一新会话，事实数依次 4、8、12、16。其中 12 条为三类来源失败，另 4 条是外层适配器正常返回的不同阶段事实，并非同一失败重复入账。首次 3 个问题在恢复时各增至 2 次；新 worktree 形成独立的 3 个指纹；另一会话在原 workspace 将既有 3 个问题各增至 3 次，同时原始事件的 session/lane 仍分离。重复定义/重复聚合不虚增事件，问题历史保留。B 批的独立验证关闭与复发重开测试在最终全量继续执行；本次刻意注入的未修复 fixture 问题保持 open。

缓冲上限 2,048 条、数据库容量约 16 MiB，数据库等待 50 ms。stderr 只用于内存内分类，持久层只保留允许的结构化事实；有身份时记录模块和 artifact 内容哈希，解释器启动前无法取得时为 unknown。记录器不可用输出独立告警，真实脚本缺失、解释器失败、异常、超时、策略拒绝、正常及记录器故障由真实子进程定向测试覆盖；未知效果不补成功，失败采集不重放动作。

入口核验：CLI 的真实 JSON 输出及 transcript 未给出 Hook 完成事件。app-server schema 有 `hook/completed`，但通知属于连接的 app-server 进程，不能把实验实例当作当前 Desktop 的订阅器；[官方 Hook 文档](https://developers.openai.com/codex/hooks/)及[App Server 文档](https://developers.openai.com/codex/app-server/)支持事件合同与连接语义。本机只读检查未发现运行中的 Desktop/已检查应用目录中的安装，默认控制 socket 不存在，因此没有 Desktop 自动链证据。本轮没有增加代理客户端或更换用户启动方式。

源码级 R1 修复可交回复核；所有宿主/生产问题仍未整体关闭。合并前需审阅这些限制，核对届时最新 dev、源码/依赖/环境及测试证据适用性，再明确批准 task → dev。dev 前移只重验受影响范围；dev → main 另需发布级集成验证、相关 worktree 干净及明确发布确认。推送不包含在开发授权中。

正式安装计划：从最终干净发布提交重新 prepare；显式选定并预检同一解释器和目标 venv；verify 内容身份与当前预状态；先完成独立候选 UI/调度验收。只读核对生产 generation、事务和恢复终态、既有同步回执，给出精确目标与回滚范围，经原生人工确认后执行。失败保留/恢复原 generation，不盲重试未知效果。获得业务验证授权后再验新旧会话、worktree、Hook 三类来源、真实心跳/SELF、治理源、记忆口径及问题关闭/复发链。

源码、测试集合、依赖内容、解释器或相关环境改变使对应证据失效；报告文字、无关日志和 pyc 噪声不触发重复全量。生产账本、事实知识库、待处理候选及其他会话均未处置。[沉淀候选](R1-candidates.md) 仅供单写者判重，未入库。

新增发现（deferred）：报告文本写入在已安装 Guardian 中被判为破坏性动作，并暂停当前 lane；明确文件补丁也被暂停状态拒绝，`resume --help` 又被归为人类决定。已通过当前会话原生 PermissionRequest 恢复，仅完成报告交付；该分类根因仍 inconclusive，未修改生产 Guardian 或扩大 R1 实现范围。失败尝试不算报告写入成功。
