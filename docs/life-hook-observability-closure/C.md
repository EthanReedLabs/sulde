- 测试证据按实际源码、依赖清单、已安装 Python 依赖版本、测试集合、解释器和平台绑定；不再按整个 Git HEAD、index 或无关日志变化一律失效。随运行时交付的合同文档仍属于输入。

- 补齐既有恢复测试的 UTF-8 子进程边界。问题聚合 SQLite 故障作为诊断降级处理，不阻断生命体投影。
- 根据本机 Codex 0.153.4 实际协议接入 `hook/completed`，仅持久化白名单事实。宿主时间字段经实测为秒；实际错误条目可报告 exit 1，没有退出证据时保留 unknown。恢复会话的新 turn 与旧调用不会被幂等键误合并。模块身份未知时不能将定义文件路径当作执行模块。
- 包装器可读取实际存在的交付 manifest 内容身份。没有 manifest 或解释器无法启动时继续记录 unknown。

`host-sessions.json` 来自真实本机 app-server 和 Hook 进程：在全新隔离 HOME/CODEX_HOME 中安装第三方 Hook 原始副本，创建会话；中断仅指向本机不可用端点的测试 turn；重启宿主并恢复会话到另一真实 Git worktree。项目、用户、第三方 SessionStart 共存，分别产生失败/正常回执，六条通知全部送达独立记录器。没有真实业务工具动作。隔离配置中的 Hook 信任仅用于这些无业务副作用的测试脚本，不授予生产权限。

`latency.json` 保存同机前后样本。普通调用使用真实包装器和无副作用适配器，10 次新进程的中位数 26.262 → 76.606 ms，新增约 50 ms；最大值 27.192 → 94.363 ms。打包及实际 Codex 注册安装各测一次，779.044 → 732.008 ms。这不是性能提升结论，也不包含启动器、调度器或生产完整安装耗时。

另以同一依赖解释器测量完整隔离候选流程：基线准备 1.077 秒、验证 13.095 秒；最终源码准备 1.032 秒、验证 12.930 秒。两侧均实际通过。它包含启动器和真实调度安装入口 dry-run，但原生 UI 与系统调度仍未验，不能等同生产安装耗时。单次测量不构成性能提升结论。
