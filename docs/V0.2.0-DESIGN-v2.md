# Historical v0.2.0 Design Record

This file preserves the public architectural decisions behind Sulde's mobile-first `0.2.x` line.
It is not the current installation or runtime contract. For Community `0.3.0`, use
[`README.md`](../README.md), [`GETTING_STARTED.md`](GETTING_STARTED.md), and `sulde doctor`.

## Problem statement

A long-running multi-end project needs coordination state that survives Agent context resets. The
design chose project artifacts and deterministic gates instead of relying on one session to remember
everything:

- `.sulde-config.yaml` declares opt-in scope, roles, frontends, and enforcement level.
- A project docs hub stores shared rules and design/contract truth.
- Each frontend owns a bounded `.ai-workspace/` for tasks, handoffs, baselines, and resume notes.
- A task document carries verified intent and acceptance criteria from coordinator to Dev.
- A handoff carries results and objective verification evidence back to the coordinator.
- Project ADRs preserve recurring lessons.

## Mobile-first decision

The release validates Android, iOS, Flutter, and HarmonyOS templates because their build, install,
launch, log, and screenshot evidence differs substantially. The coordination method can be adapted
to other stacks, but the public repository does not claim unshipped templates are validated.

## Hook design

Three Claude Code lifecycle entrypoints implement the public gates:

- `PreToolUse`: task/handoff shape, frontend navigation, and commit identity
- `UserPromptSubmit`: skill-trigger and performance-measurement reminders
- `SessionStart`: bounded project context injection

The plugin is silent outside a project that explicitly opts in. Missing optional project state must
not block unrelated work. A policy denial uses the Claude Code hook protocol; diagnostic failures do
not masquerade as policy decisions.

Community `0.3.0` changed the launch layer while retaining those semantics:

- Python 3.10+ and PyYAML 6.0+ are the current contract.
- Hook commands explicitly select Bash and dispatch through `hooks/run-hook.sh`.
- UTF-8 is set before Python starts.
- `hooks/hooks.json` is the single hook registration path; the plugin manifest does not register it
  again.
- Downstream hook extensions register once in `extensions/registry.json` and are called by the
  existing entrypoints.

## Grace-period design

Initialization records a local start marker. During the configured grace period, enforcement is
lenient so a team can validate its paths and rules before enabling stricter gates. An explicit end
marker terminates grace. Marker state is machine-local and should not become shared project truth.

## Template design

`template/_project/` contains root documentation, scripts, docs-hub, and an empty knowledge kit.
Each stack template contains:

- a stack-specific `CLAUDE.md.template`;
- `.ai-workspace/` directories;
- stack verification command examples;
- a pre-commit installer.

Copy operations add missing skeleton files and preserve existing project content. A legacy project
maps Sulde configuration to its current directories instead of moving business source code.

## Extension design added in 0.3.0

The public framework exposes generators for a project skill, hook, doctor check, and knowledge
container. This turns the former fixed skeleton into a safe starting point for downstream forks
without publishing a private corpus or autonomous runtime.

Generators follow four rules:

1. Validate names and confine paths to the fork root.
2. Refuse to overwrite existing files or duplicate registry entries.
3. Keep one registration path per executable capability.
4. Require downstream review and tests; generation does not grant Agent authority.

## Knowledge design added in 0.3.0

The project knowledge kit is empty by default. Markdown and Git are truth; `INDEX.md` and search
results are derived. The local CLI supports deterministic dedup, redaction checks, lint, index,
lexical search, and creation of a human-reviewed sediment draft. It does not call a model, MCP,
network service, background Agent, or private Sulde repository.

## Out-of-scope decisions

The Community design intentionally excludes populated incident content, session/user memory,
cross-project retrieval, semantic/vector infrastructure, autonomous governance, L2/L3/L4 governance
tiers, self-repair, automatic approval, and commit/push/publish behavior.

These boundaries keep the public release understandable, self-contained, and suitable for teams to
complete with their own content.
