### §2.2 enforcement_level 全局开关(v2 修订:exit code 协议合规)

**v1 错误**:exit 1 拦 Write / exit 2 拦 Bash — 协议 exit 1 = non-blocking error(工具继续跑)。
**v2 修订**:

| Level | PreToolUse(Write) | PreToolUse(Bash) | pre-commit(git)| UserPromptSubmit | SessionStart |
|:-:|:-:|:-:|:-:|:-:|:-:|
| **strict** | exit 0 + JSON `permissionDecision:"deny"` | exit 2 + stderr | exit 1 阻塞(git 协议)| stdout 提醒 | additionalContext 注入 |
| **balanced**(default) | exit 0 + JSON `permissionDecision:"deny"` | exit 2 + stderr | exit 1 阻塞 | stdout 提醒 | additionalContext 注入 |
| **lenient** | exit 0 + JSON `permissionDecision:"allow"` + stderr 警告 | exit 0 + stderr 警告 | exit 0 + 警告 | stdout 提醒 | additionalContext 注入 |

**协议差异点说明**:
- **PreToolUse hook**:正路径用 JSON 决策(`exit 0 + hookSpecificOutput`),不是 exit code 区分。`permissionDecision: "deny"` 才是真正拦截。
- **Bash PreToolUse**:既可 JSON 决策也可 stderr,选 stderr(exit 2)因 Bash 命令多样 + 用户期望直接看 reason。
- **pre-commit git hook**:non-Claude-Code,仍按 git 协议 exit 0/1。

### §2.3 onboarding grace period(v2 新增,修 S2 + #23 marker file)

**v1 缺**:首装即 balanced → 写第一个 task md 就被拦,差体验。

**v2 修(2 次迭代)**:`.sulde-config.yaml` 加 `enforcement_grace_period_days: 7`(default)字段。

**初版用 mtime 检测**(已废弃):用 `mtime(.sulde-config.yaml) + grace_period > now`。**问题**:用户改 config 任意字段(改 sentinel / 加 sensitive_file / 等)→ mtime 重置 → grace 重启,可被(无意 / 故意)绕过 enforcement。

**v2 修订(#23 fix,2026-05-25)**:用 **marker file** 替代 mtime,一次性写入不复 reset。

实现:
- `sulde-init` / `sulde-migrate-from-v0.1.0` 完成时 → 写 `.sulde-grace-started` marker file 到 `project_root/`,内容:`{"started_at": "<ISO timestamp>", "grace_period_days": 7}`
- `enforcement.py` 启动时:
  1. 检查 `.sulde-grace-ended` marker → 存在 → 直接按 config `enforcement_level` 跑(grace 已主动结束)
  2. 检查 `.sulde-grace-started` marker → 存在且 `started_at + grace_period_days > now` → 强制 lenient
  3. 都不存在 → 按 config `enforcement_level` 跑(已有项目升级到 v2 但没跑 init,跳 grace)
- `/sulde-end-grace` command → 写 `.sulde-grace-ended` marker(空 file 即可)
- 两 marker 必加 `.gitignore`(cross-machine state 不应同步,且防 commit AI 痕迹)

显示:`sulde [grace: 5 days left → forced lenient mode]` stderr 提示(每 hook 触发显示一次,可关)。

**override**:用户主动 `/sulde-end-grace` command → 立即切真 `enforcement_level`(写 `.sulde-grace-ended` marker)。

### §3.1.1 Python 依赖 fallback 策略(#22 fix — breaking change 降级路径)

**问题**:Python 是 v0.1.0 → v0.2.0 唯一 breaking change。无 Python 用户(企业禁装 / 老 Windows / minimal container)若直接升级会卡死。

**v2 决策**(基于实证 trade-off):
- ❌ 不维护 bash + Python 双套(违 v2 跨 OS 核心决策 + 双套必 drift)
- ✅ **诚实化 + 优雅降级 + 退路明示**

**3 层 fallback**:

1. **install 时检测**(`/sulde-init` 第 1 步)
   - 跑 `python3 --version` 检测 Python 3.6+,缺 → 退出 init 并给 3 条退路:
     - "装 Python 3:macOS `brew install python` / Linux `apt install python3` / Windows `winget install Python.Python.3`"
     - "或继续用 v0.1.0(MIT,无 Python 依赖):`/plugin install skills@sulde-cc@0.1.0`"
     - "或选 enforcement-light:仅装 git pre-commit hook(bash,无需 Python),手动跑 docs-hub 规则"

2. **runtime 优雅降级**(每个 `hooks/*.py` 顶部)
   ```python
   #!/usr/bin/env python3
   import sys
   try:
       import yaml
   except ImportError:
       # Graceful degradation: hook becomes no-op + stderr warning
       # Does NOT block tool call (exit 0, no JSON)
       sys.stderr.write(
           "sulde: pyyaml not installed, hook enforcement disabled. "
           "Run: pip install pyyaml>=6.0\n"
       )
       sys.exit(0)
   ```
   → 用户工作流不挂,只是失去 enforcement(直到装 pyyaml)

3. **README + GETTING_STARTED 明示退路**(P4.2 / P4.6)
   - Quick start 第一段:`Prerequisites: Python 3.6+ with pyyaml. If unavailable, see v0.1.0 (no Python dep).`
   - 加 link 到 GitHub release v0.1.0 永久 archive(MIT grant 永久有效)

**判定线**:
- ✅ 装了 Python → 完整 enforcement(默认体验)
- ✅ Python 但缺 pyyaml → hook no-op + warning(可恢复)
- ✅ 完全无 Python → 用户主动选 v0.1.0 或 enforcement-light
- ❌ **不应**:升级 v0.2.0 后 Claude Code session 启动失败 / 工具调用挂死

### §3.3 sulde_common.py API(v2 Python rewrite + worktree 支持)

```python
"""
sulde_common.py — imported by every entrypoint.

Public API:
  load_config(start_dir: Path = None) -> SuldeConfig
    Walk up from start_dir (default: cwd) to find .sulde-config.yaml.
    Returns SuldeConfig dataclass or None if not found.

  SuldeConfig fields:
    config_path: Path
    project_root: Path
    role: Literal["coordinator", "dev", "both", "unknown"]
    frontends: list[Frontend]   # name, path, stack
    enforcement_level: Literal["strict", "balanced", "lenient"]
    grace_period_days: int
    raw: dict                    # full yaml parsed

  match_frontend_path(config: SuldeConfig, file_path: Path) -> Frontend | None
    Find which frontend this file belongs to (or None).

  get_frontend_subpath(config: SuldeConfig, file_path: Path) -> str | None
    Relative path within the matched frontend.

  is_in_grace_period(config: SuldeConfig) -> bool
    Logic (#23 fix — marker file, not mtime):
      1. If `.sulde-grace-ended` exists in project_root → return False (grace 已主动结束)
      2. If `.sulde-grace-started` exists → read started_at + grace_period_days from it
         → return True if started_at + days > now, else False
      3. Otherwise → return False (no init/migrate ran, no grace applies)

  silent_exit_if_no_config(start_dir: Path = None) -> None
    Exit 0 immediately if no .sulde-config.yaml found (non-sulde project safety, M4 fix).

  detect_multi_root(start_dir: Path) -> list[Path]
    For worktree / submodule / monorepo: return all .sulde-config.yaml paths reachable
    (walk-up + walk-down git roots). Use first match by default; warn if multiple.

Worktree / submodule / monorepo support (B3 fix):
  - walk_up_strategy: stop at git root (.git/ dir or .git file for worktree/submodule)
  - if multiple .sulde-config.yaml found in repo tree, log WARNING and use closest-ancestor
  - submodule case: respect parent .sulde-config.yaml even if submodule has its own
    (configurable via .sulde-config.yaml: scope_inheritance: parent | self)
"""
```

**yaml parsing**:用 `yaml.safe_load()`,nested list / dict 任意嵌套都稳。错误处理:yaml.YAMLError → stderr 友好提示 + exit 0(non-blocking,防 yaml 笔误把整个 hook 系统挂掉)。

### §3.4 enforcement.py API(v2 Python rewrite + i18n)

```python
"""
enforcement.py — sulde_exit_or_warn() helper, imported by every check_*.py.

Public API:
  sulde_exit_or_warn(
      config: SuldeConfig,
      severity: Literal["hard", "medium", "soft"],
      reason: str,
      reason_i18n: dict[str, str] | None = None,  # {"en": "...", "zh": "...", ...}
      hook_event: str | None = None,               # "PreToolUse" etc for JSON output
      tool_name: str | None = None,                # "Write" / "Bash"
  ) -> None
    Behavior matrix (v2 protocol-compliant):
                          strict           balanced        lenient
    hard (Write)         JSON deny + 0    JSON deny + 0   stderr + JSON allow + 0
    medium (Bash)        stderr + exit 2  stderr + exit 2 stderr + exit 0
    soft (prompt)        stderr + exit 0  stderr + exit 0 stderr + exit 0

    In grace period: forced lenient regardless of config (S2 fix).

  i18n resolution:
    1. read SULDE_LANG env (set by user shell or .sulde-config.yaml `lang` field)
    2. fallback: $LANG / $LC_ALL → en|zh|ja|...
    3. fallback: "en"
    If reason_i18n missing matched key → fall back to `reason` (positional, treated as default lang)

  Structured stderr (B1 fix):
    Format:
      ╔═══ sulde ═══ {hook_event}/{tool_name} ═══
```

### §5.3 multi-root / worktree / submodule 支持(B3 fix)

`sulde_common.load_config()` walk-up 策略:

1. 从 `start_dir`(default cwd)开始 walk up
2. 在每层检查 `.sulde-config.yaml`
3. 在每层检查 git boundary:`.git/` dir(普通 repo)/`.git` file(worktree)/`.gitmodules` 中的子目录(submodule)
4. 找到 `.sulde-config.yaml` → 停;走出 git root 没找到 → silent exit
5. **冲突检测**:`detect_multi_root()` 检测 git tree 内多个 `.sulde-config.yaml`,WARN 到 stderr 但用最近祖先

**submodule 行为**:
- `scope_inheritance: parent`(default)→ 走出 submodule 用 parent 的 config
- `scope_inheritance: self` → 用自己的 config(必有 `.sulde-config.yaml` in submodule root)

**worktree**:
- `.git` 是 file 指向 main tree → 跨 worktree share `.sulde-config.yaml`(若 main tree 有)

### §5.4 OS-aware build_verify(#21 fix)

per-stack 可选 `_windows` / `_linux` / `_macos` 后缀字段。`enforcement.py` 选择顺序:

1. `build_cmd_{os}`(精确 OS 匹配)
2. `build_cmd_unix`(macOS + Linux 共用)
3. `build_cmd`(fallback)

OS 检测:`platform.system().lower()` → `darwin` → macos / `linux` → linux / `windows` → windows / `msys|cygwin` → 视为 windows + Git Bash

### §6.3 cross-dir cp 权限(B4 fix)

**问题**:plugin 跑在 `${CLAUDE_PLUGIN_ROOT}`(~/.claude/plugins/...)只读;用户 cwd 是 project root 可写。configure-sulde cp template 从 plugin → project 需明确路径。

**v2 解法**:configure-sulde Python helper(skill 内部跑):

```python
"""
Helper used by configure-sulde mode init / add-frontend:

  copy_template(plugin_root: Path, project_root: Path, stack: str, target_subpath: str) -> None
    src = plugin_root / "template" / stack
    dst = project_root / target_subpath
    if dst.exists():
        prompt user: overwrite | skip | merge
    shutil.copytree(src, dst, dirs_exist_ok=True if merge else False)
    chmod_executables(dst)  # restore +x on .sh files (lost in some FS)
"""
```

权限处理:
- Read source from `${CLAUDE_PLUGIN_ROOT}` — read-only OK
- Write to project — user has write
- Restore executable bit on `*.sh` / `*.py`(shutil 默认丢 mode 在某些 FS)
- 若用户 chmod fail(Windows native)→ 提示 `git update-index --chmod=+x <file>` 后 commit 恢复
