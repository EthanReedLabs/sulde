## 沉淀候选（任务内保留）

证据 verified：模板及报告常量也可能携带操作员的历史批准/目标，公开或新实例初始化
时不能把它们当成可复用状态。AST 差异约束、权限章节一致性及真实报告/SELF 测试通过。

- 路由正例：新报告无本地来源却默认写“某人已批准”；新 SELF 初始就带旧目标/已晋级。
- 路由反例：原公开许可的作者署名、明确合成的身份负例、能力定义和权限规则。
- 执行合格例：公开投影为空状态，保留私有原文与权限约束，绑定转换摘要并实际复验。
- 执行失败例：只改人名却保留“已批准”，删除权限规则，或将模板默认值伪装为本地验收。

另有 unresolved 候选：包含只读 bootstrap 预览的组合调用被正式维护门禁拒绝。
路由正例为观察到的 exact compound invocation；反例为真实安装写入应保持其维护授权。
执行合格例是隔离核对分类/profile 原因后加正反例；失败例是换入口绕过、移除正式维护
授权或将被拒绝的调用记录为执行成功。根因仍 inconclusive，交独立守卫修复任务。
