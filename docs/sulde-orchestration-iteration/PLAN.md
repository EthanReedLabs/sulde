## 1. 目标与非目标

五项能力全部纳入，采用“1 个准备阶段 + 3 个实施阶段”：

| 编号 | 能力 | 实施阶段 |
| --- | --- | --- |
| C1 | 统一 Agent 启动适配与完整预检 | 1 |
| C2 | 启动幂等、防重复执行 | 1 |
| C3 | 升级保护运行中任务 | 3 |
| C4 | 增量用量采集与跨续接去重 | 2 |
| C5 | 有明确归属的状态恢复 | 2 |

编排补充随上述能力落实：任务与执行尝试分离、依赖就绪判断、有限并发、持久问题与回执、迟到消息隔离、统一状态来源、报告与验收分离。先映射已有实现，只补缺口，不假设所有能力都需要新建。

不纳入本轮：新建桌面或移动端、扩建远程环境、另建审批系统、另建竞争性任务账本、默认增加 Agent 数量、全自动规划器、无限重试、自动扩大权限，以及新增付费 Orca/Sulde 对照实验。

## 2. 架构约束

### 2.1 单一职责与事实来源

| 领域 | 复用的现有基础／职责 | 禁止的重复建设 |
| --- | --- | --- |
| 启动与宿主适配 | `runtime_provider.py`、`native_agent_broker.py`、`agent-runtime.py` | 预检与执行分别解析出不同配置；适配器自行授予权限 |
| 执行生命周期 | `execution_backend.py` 与现有 run 账本 | 另一个调度状态库独立判定相同执行是否成功 |
| 会话与任务归属 | 现有 session/lane 映射、`task_continuation_routing.py` | 从环境变量或缓存静默复活旧任务权限 |
| 人工决定与效果证据 | 现有 intent、approval、effect 机制 | 同一决定新增“编排批准卡”；回执替代独立效果验证 |
| 用量与状态展示 | 现有事件观测入口及其只读投影 | 统计缺失被升级成普通任务的授权故障 |
| 代际发布与恢复 | 现有候选安装、安装事务、launcher、恢复入口 | 新建与现有 deployment 相互竞争的发布管理器 |

表中是职责映射，不是全部能力已经存在或已经验收的声明。阶段 0 必须定位实际写入者、消费者、版本与缺口。

### 2.2 不变量

1. 明确区分业务任务、一次执行尝试、宿主 session、物理工作区与安装代际；字段命名服从 Sulde 已有契约，不机械复制 Orca 的 Run/Task/Dispatch 命名。
2. 状态恢复不转移旧 grant、approval receipt 或未结算效果；上下文恢复不等于授权恢复。
3. 派发是否发生采用三值语义：确定未执行、确定已执行、是否执行未知。未知不能当作不存在，也不能全局锁住无关任务。
4. 独立请求的观测或恢复故障，只阻塞对应请求及确有依赖的工作。
5. 区分执行结束、Worker 报告成功、独立验收通过、合并／发布完成，不压缩成一个成功标志。
6. 工作区隔离必须显式选择；并行能力不自动解决共享文件冲突。
7. 多宿主共享输入与结果契约，各自声明能力。不支持的能力明确拒绝或报告，不静默切换提供方。
8. 正常路径保持有界检查；深度扫描、账本重放与故障诊断不逐动作重复运行。

## 3. 阶段 0：冻结边界与测量基线

### 工作

- 映射上述五项能力和编排补充，分别标注“已有且可复用／已有但未接通／确实缺失”。
- 确认任务、run、执行尝试、session、工作区和代际的身份关联及事实所有者。
- 用既有脱敏样本复现报告契约不匹配、重复提交、迟到回执、双 session 和恢复歧义。
- 记录启动耗时、控制开销中位数与 P95、用量完整性、重复执行次数、人工恢复次数。
- 固定验收器、样本摘要、环境与性能测量方法；在实施前确定重复测量次数及噪声容差，不能事后放宽标准。

### 交付与退出条件

- [ ] 模块变更清单与单一事实来源表。
- [ ] 身份／事件／状态兼容约束。
- [ ] 基线数据与验收矩阵。
- [ ] 性能预算及比较方法已明确；无实测数据的收益保持“待测”。

本阶段不新增常驻服务，不启动新的付费对照，不把准备工作扩成独立平台建设。

## 4. 阶段 1：启动正确、派发不重复（C1 + C2）

### 工作

- 形成单一、版本化的启动描述，预检与实际执行共同消费同一份解析结果。
- 预检宿主能力、工作目录形态、来源绑定、输入、报告位置、验收器、配置优先级与必要依赖。
- 将派发请求身份与请求摘要绑定到既有执行生命周期；同请求恢复原尝试，内容冲突明确拒绝。
- 处理并发请求以及“已提交但确认丢失”的崩溃窗口；不能仅依赖内存去重。
- 回执与心跳绑定具体执行尝试和发送者，防止旧执行污染新尝试。
- 复用或补齐依赖就绪判断与并发额度，不默认提升 Agent 数量；共享写入范围冲突须串行或隔离。

### 验收

- [ ] 可预检的不合法配置在 0 次模型调用时被发现；不只测试纯解析器，还验证真实启动入口。
- [ ] 同请求重复或并发提交仅产生 1 次有效启动；同 ID 不同内容明确冲突。
- [ ] 崩溃／确认丢失后，先核对已有执行，不能盲目重发。
- [ ] 老尝试的完成回执与心跳不能改变新尝试。
- [ ] 明确没有执行的合法新请求仍能启动，不能因防重复而永久拒绝首次执行。
- [ ] 状态未知仅限制对应请求和实际依赖，不阻止无关任务。
- [ ] 启动描述不能绕过既有权限、宿主隔离或密封调用约束。

这不是任意外部效果的 exactly-once 保证；外部写入仍须按目标系统与现有效果协议验证。

## 5. 阶段 2：过程可观测、续接不串线（C4 + C5）

### 工作

- 增量读取用量与执行事件，处理追加、截断、轮转、重放及 fork/resume 历史；不同独立调用不得错误合并。
- 保存超时／退出前已观测的统计；明确完整值、下限和 unknown，不将缺失记录为零。
- 将问题、答复、完成回执接入现有任务通信与证据体系；中断后恢复原消息，不重复提问。
- 以精确的 session、task、run、尝试和 workspace 归属恢复上下文；展示缓存不能充当权限凭据。
- 统一生命体、doctor、CLI 的状态输入；消费者保留展示规则，不另行裁定执行事实。
- Worker 回执采用短摘要与报告引用，按需读取详情；完成后结束无效轮询，不自动扩大任务。
- 只采集完成指标必需的字段，不收集隐藏推理、密钥、完整 prompt 或无必要的原始工具输出。

### 验收

- [ ] 双 session 同项目不串任务，不继承旧授权。
- [ ] 重复采集不重复计数，独立执行不会被错误去重。
- [ ] 日志轮转、损坏和中断被明确报告，不产生伪造成功统计。
- [ ] 超时仍可回读已观测证据；统计不可用不阻塞普通任务。
- [ ] 已有问题可按消息身份续接，不额外创建相同问题。
- [ ] 执行结束、报告成功、验收通过、发布完成分别可查询。
- [ ] 结束任务不因旧缓存恢复为活动任务；无法确认的存活状态保持未确认。

新增样本、用量原始数据及性能证据保存到 Optimus 的任务专属目录。仓库保留脱敏方案、摘要和证据索引。阶段 0 解析实际挂载点并冻结具体目录；外接盘不可用时明确报告证据缺口，不静默换位置。普通统计失败不自锁，但缺少必要证据时不能宣称验收完成。

## 6. 阶段 3：升级不中断与发布闭环（C3）

### 工作

- 对候选做隔离安装，使用真实宿主链验证启动、消息、回执及恢复。
- 通过验收后切换新任务入口；进行中的任务按兼容性策略保留执行归属和所需代际。
- 处理共享数据 schema 的新旧兼容，不能只固定可执行文件而让共享状态不兼容。
- 候选失败时保留可工作的生产入口；恢复通道不得依赖已故障的普通 Hook。
- 回滚不得自动重放效果未知的任务或恢复旧授权。
- 无活动引用且满足保留条件后回收旧代际；安全撤销和不兼容升级采用明确停用／迁移策略，不无限保留旧版本。

### 验收与发布顺序

- [ ] 集成候选完成风险相称的完整回归。
- [ ] 真实宿主验证：运行中升级、失败候选、双 session、未知启动恢复和回滚。
- [ ] 新旧任务的消息、执行者与代际不串线，候选失败不破坏正常旧任务。
- [ ] 回滚可执行且有独立回读；安装成功不替代业务链通过。
- [ ] 正式安装具有届时有效授权，完成安装状态、真实运行链及效果结算验证。
- [ ] 完成资源清理、证据索引与已知限制报告，再标记对应范围 accepted。

每阶段独立验收，最终统一发布；不要求每个小修改反复正式安装。发布阶段确有必要的候选安装、切换与回滚试验不能省略。跨平台未执行的验证明确列为未验收，不宣称全平台完成。

## 7. 测试与证据复用

- 局部修改：定向单元、契约与反例测试。
- 跨模块修改：影响范围内的集成链；权限、状态迁移、代际路由变化增加并发与故障注入测试。
- 最终集成候选：完整回归和真实宿主 canary。
- 优先使用假执行器、已脱敏生产形态样本、确定性故障注入；仅对无法替代的宿主行为使用真实调用。付费模型调用需另行明确预算，不隐含在本文落盘授权中。
- 测试记录绑定代码树、配置、依赖／环境、样本摘要、验收器版本和测试范围。不因无关后台日志改变而废弃有效结果，也不能在相关输入改变后复用过期结果。
- 清理仅针对可重建派生明细；按 TTL、sourceVersion、generatorVersion 制定计划并验证。权威审计、未结算效果、未解决问题和必要验收证据不能作为普通缓存删除。

## 8. 收益、成本与测量口径

### 8.1 可验证收益

| 指标 | 目标／解释 | 限制 |
| --- | --- | --- |
| 可预检错误的模型调用次数 | 0 | 不能提前发现所有业务错误 |
| 同请求有效启动次数 | 重复或并发提交仍为 1 | 不推广为任意外部效果 exactly-once |
| 每个验收通过任务的 Token | 比较实施前后总输入、缓存输入、输出及有效成功率 | 包含失败尝试和协调开销；数据缺失明确披露 |
| 端到端完成耗时 | 比较中位数、P95 和失败恢复时间 | 并行缩短耗时不一定节省 Token |
| 人工干预 | 统计因基础设施错误产生的干预次数 | 必要人工决定不作为应消除的失败 |
| 控制面开销 | 同场景测量中位数与 P95，满足阶段 0 冻结预算 | 不用噪声内差异声称性能提升 |
| 用量完整性 | 完整／下限／unknown 分别计数 | unknown 不记为零，不只报告成功样本 |
| 升级影响 | 统计正常任务被打断、错误重放及消息丢失 | 安全撤销和不兼容迁移另行归类 |

当前没有证据承诺整体节省 30% 或 50% Token。一次不同模型的 Orca/Sulde 对照不能单独归因于 Harness；本方案最终收益需在可比输入、模型配置、验收器与范围下测量。

既有试验中，Sulde 完成模型工作后因报告契约不匹配无法正式收尾。阶段 1 要把这类可预检错误移到执行前，避免失败尝试浪费；这不代表完成正确任务本身不再需要 Token。

### 8.2 负收益与控制措施

- 身份和兼容契约更精确，会增加实现与测试成本：复用已有模块，分阶段验证，不并行建设第二套状态机。
- 新旧代际并存增加磁盘占用：按活动引用及保留策略回收，不提前删除运行中依赖。
- 持久消息和统计增加存储：限制字段、增量处理、清理可重建数据。
- 并行和重试可能增加 Token：并发有上限，不默认扩充 Agent，不自动重放未知效果。
- 终端复用可能带入旧上下文：明确任务边界和宿主续接能力，不能以省启动成本为由继承旧权限。
- 兼容迁移和状态歧义仍可能要求人工决定：明确缺失事实，不承诺完全无人介入。
