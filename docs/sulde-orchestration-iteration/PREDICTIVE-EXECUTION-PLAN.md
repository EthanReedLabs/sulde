# B：预测式执行与持续纠偏能力

## 1. 产品目标与非目标

让 Agent 在修改前预测影响，在修改中对照实际变化、识别假设失效并主动调整，最后由真实
行为证据确认结果。不能仅在任务结束时审查，也不能把生成风险表格或更多测试当成功。
不承诺预知所有缺陷，不访问或保存隐藏推理；只记录简短可核验的判断、依据、选择和结果。

核心流程：影响预测 → 逻辑修改 → 增量事实对照 → 必要的重新判断/最小验证 → 调整执行 →
独立确认 → 后续任务召回。预测不是权限合同，范围偏差不自动等同越权。

不新建逐动作审批控制面，不管理 Git 操作，不给普通 Hook 加全仓扫描或每工具模型调用，
不把质量缺口转换成外部效果债务，不制造跨 session 全局阻塞。

## 3. B0：既有能力接线和预算冻结

先审计现有 `agent-runtime.py`、`correction_intervention.py`、`test-evidence.py`、
`agent-experience.py`、事件观察/投影与宿主适配器，产出“已实现/未接通/确实缺失”矩阵。
复用既有身份、状态与持久化，不为新增名称再造调度、审批或日志系统。

冻结内容：

- 支持的运行方式：受管子任务、交互式任务分别说明接入边界。
- 什么事件触发重新判断，如何送达当前宿主，宿主不支持即时注入时如何在下一有效边界续接。
- 代码/测试/配置/依赖输入的证据身份和失效规则。
- 机械开销、模型调用/Token、每问题纠偏轮数、等待和累计时间预算；必须在实验前明确，

- B4 的公开场景与独立保留样本分离，避免对答案硬编码。

## 4. B1：修改前影响预测

复用现有任务工件建立版本化预测，绑定 task/run/session、合同版本与源码身份：

- 根因/实现假设、事实依据、置信程度与未知项；
- 预计触及入口、调用者、状态、持久数据、平台与相关验证；
- 保持不变的行为，可能新引入的问题和触发条件；
- 可选方案、当前选择理由、最小反证探针与恢复路径。

范围是语义影响而非仅文件数/行数；预测下限、上限和未知影响分开记录。
新增预测不覆盖旧判断；变化须说明新证据和修订理由，防止事后把实际结果改成原预估。
小改动允许轻量预测，不将完整跨阶段账本强加给单纯函数测试或普通只读动作。

## 5. B2：执行中的增量判断

机械收集只提供事实：增量 diff、相关调用/引用、入口与配置变化、运行反馈、已失效证据。
Agent 负责解释、反证和选择；不能只用关键词或文件计数代替语义判断。

触发节点：准备改变公共接口/状态迁移/共享资源前、完成一个逻辑改动后、发现新依赖时、
验证与预测矛盾时，以及进入昂贵测试/安装/交付前。信号未变化不重复调用审查。

要求处理以下情况：

1. 实际大于预估：必要依赖还是范围扩散；在授权内可调整预测，越过用户范围才请求决定。
2. 实际小于预估：实现更简洁还是遗漏入口/消费者；不能自动标记优化或失败。
3. 一行默认值改变但影响很大：按行为影响重新评估。
4. 新锁、等待、重试、持久状态：检查调用链、竞争、预算、中断及恢复。
5. 测试通过但未触及风险：补最小有效验证，而非立即重跑全量。
6. 重复修复无进展：重新评估根因与方案，不无限叠加补丁。

每次输出限定为：关键事实、假设变化、风险/反例、下一动作和证据引用。长日志留文件，
计数/耗时/差值由脚本计算；上下文仅取必要摘要，可按需回读原文。

## 6. B3：纠偏投递、执行与独立验证

复用现有 correction 通道，但不能把当前 `applied` 的“已送达/已中断”改称“问题解决”。
在兼容既有状态语义的前提下，明确区分发现、送达、处理、验证与关闭；先审计已有表示，
必要时做版本化扩展，不另建相互冲突的结果真源。

- 消息绑定确切 task、run、session、代码与问题身份；过期/重复/跨会话消息不能误作用。
- 指明事实、预测偏差、风险、最小下一步和成功条件，避免只有“请重新检查”的空提示。
- 机械确定的问题直接反馈；语义怀疑保留为候选，需依据或可复现反例，不能凭另一个 Agent
  的断言否定执行者。独立审查按冻结预算按需触发。
- Agent 仅在原授权内调整；预测/质量监督本身不生成新写权限，不继承他人授权。
- 监督端独立回读实际结果后关闭问题；执行者不能凭“已修复”直接结算。
- 监督器异常、消息丢失或宿主能力不足应显式降级；普通工作和修复入口不能因此全局自锁，
  同时不得生成无证据的 accepted 状态。
- 重复问题稳定指纹去重，有界纠偏；无进展或新决定交人判断，不通过多次重试稀释失败。

## 7. B4：真实行为验收

先 shadow 记录判断，验证识别与误报，再开放已授权的限定纠偏；不能仅在终态运行一遍审查。
至少覆盖如下场景，并记录发现时点、实际收到的反馈、Agent 后续动作与最终行为：

| 场景 | 需要证明 |
| --- | --- |
| 漏掉独立恢复入口 | 完成声明前指出缺口并推动真实入口验证/修正 |
| 小改动改变 observe 默认行为 | 识别语义影响，不依赖变更行数 |
| 新锁包含配额等待 | 在交付前识别跨作用域影响并调整方案 |
| 实际多出消费者 | 更新预测和验证范围，不静默扩散 |
| 少改代码但功能完整 | 能认可有证据的简化，不机械误报 |
| 旧性能/错误入口/伪并发证据 | 不接受无关或不足证据作为当前结论 |
| 无缺陷低风险改动 | 无额外人工阻断，预算内完成 |
| 双会话与过期消息 | 不串任务、不转移权限、不阻塞无关会话 |
| 监督器故障和预算耗尽 | 可继续安全诊断，准确披露降级，不能伪造成功 |

采用 A 的实际问题作已知样本，再加入不泄露缺陷位置的独立变体和正常反例。不能把故障答案
写进提示后宣称提前预测，也不能仅识别固定函数名。
确定性协议可用假 provider 验证；真实 Agent 的判断/调整必须通过已授权真实宿主运行证明，
未完成此层就只能称协议/接线通过。记录初始修复任务输入，避免把协调者事后发现当成自动发现。
对照保持任务输入、起始代码和环境可比，披露样本量与波动，不凭一次成功宣称普遍收益。

## 8. B5：经验反馈与成本校准

复用经验层记录命中、漏判、误报、预测范围偏差、实际修正、复发和成本。
verified 才能成为后续同类任务的策略依据；inconclusive 只提供诊断线索；未解决问题保留。
检查后续不同任务是否真的召回并改变动作，不能以经验记录文件存在作为防复发证明。

不收集隐藏推理、完整 prompt、原始工具输出、秘密和私人绝对路径进入经验摘要；任务原始
证据仅留授权的数据区。值得共享的结果按问题卡输出沉淀候选，由单写者流程判重入库。
复用已有 TTL/sourceVersion/generatorVersion 与清理入口，只清理可重建派生明细；
权威日志、未解决问题、有效聚合经验和待处理候选不得自动删除，不借本任务重建 GC 系统。
