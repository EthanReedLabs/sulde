# /import-codex-session — Codex 会话只读接力

参数可为空、`YYYY-MM-DD` 日期或 session id/文件名片段。整个流程只读；绝不编辑、格式化、移动、压缩或删除 rollout 文件。

## 1. 定位 rollout

只在 `~/.codex/sessions/*/*/*/rollout-*.jsonl` 中查找普通文件：

- 无参数：按 mtime 倒序取最新一个。可用 `find ~/.codex/sessions -type f -name 'rollout-*.jsonl' -print0 | xargs -0 ls -t | head -1`。
- 日期参数：只保留路径中对应 `YYYY/MM/DD` 的文件，再按 mtime 倒序取最新一个。
- 其他参数：在 rollout 文件名中按字面量匹配 session id 片段，再按 mtime 倒序取最新一个。不要用未经转义的参数拼正则。
- 没有匹配时停止并明确说明查找条件；不要猜测文件。

解析前输出选中的绝对路径，并确认它位于 `~/.codex/sessions/` 且文件名匹配 `rollout-*.jsonl`。

## 2. 宽容读取

先查看文件大小和行数。大文件先读末尾（例如 `tail -n 500`）；若目标、cwd 或关键前因仍不明确，再逐段向前补读，避免一次把整份大文件塞入上下文。

逐行独立解析 JSON；单行无法解析时跳过，不让整次导入失败。优先提取：

- 会话元数据中的项目 `cwd`；
- 用户消息里的目标、限制与追加要求；
- 助手的结论、已完成验证和最后状态；
- 关键工具/命令及其结果，尤其是失败、退出码、测试与 `git status`；
- 明确的 TODO、阻塞项和用户尚未回答的问题。

不要把推理草稿、重复进度播报、原始大段工具输出或疑似秘密复制进摘要。若尾部信息不足，继续向前读取，直到上述四类接力信息有证据或确认原文件没有。

## 3. 输出接力摘要

使用以下紧凑结构；不确定内容标为“未确认”，不要补写事实：

```markdown
## Codex 接力摘要
- 目标项目 cwd：...
- 做了什么：...
- 最后状态：...
- 未完成项：...
- 关键命令/验证：...

细节以原文件为准：`/absolute/path/to/rollout-....jsonl`
```

最后单独问用户：**“从哪里继续？”** 在得到回答前，不修改目标项目。

## 4. 铁律

- rollout 是只读事实源；任何情况下都不写回。
- 摘要必须给出绝对原文件路径，并包含“细节以原文件为准”。
- 解析失败行只计数并略过；若关键结论可能受影响，在摘要中说明。
- 未经用户确认，不把接力摘要中的未完成项自动视为获准实施。
