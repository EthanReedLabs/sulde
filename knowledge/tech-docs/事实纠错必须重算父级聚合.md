# 事实纠错必须重算父级聚合

## 原则

允许用户编辑或删除明细事实的系统，不能只更新明细行。所有持久化父级聚合、统计快照和决策输入必须在同一语义操作中同步重算，否则不同页面会展示互相矛盾的数据。

## 事务边界

一次纠错应在单一事务内完成：

1. 校验纠错值和目标记录。
2. 修改或逻辑作废明细事实。
3. 从当前有效明细重新计算父级聚合。
4. 写入纠错或作废审计事件。

不要通过“原聚合加差值”维护结果，删除、重复请求和历史脏数据会放大误差；优先从当前有效明细求和。

## 双模型迁移期

系统同时存在 legacy 展示模型与规范事实模型时，用户可见 legacy 行可以物理删除，规范模型应保留逻辑作废状态和审计事件。进度、模型证据和教练决策只消费有效规范事实，并排除与已作废或改动作记录不再匹配的旧分析证据。

## 验证

测试至少覆盖修改数量后的父级总量、删除唯一明细后的零值、逻辑作废记录仍可审计，以及进度和分析证据不再消费失效事实。
