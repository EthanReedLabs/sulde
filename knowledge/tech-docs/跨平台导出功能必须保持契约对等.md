# 跨平台导出功能必须保持契约对等

## 原则

共享 UI 暴露了导出入口，就必须在每个目标平台绑定真实实现。为通过编译而注入 no-op，会把平台缺失隐藏到用户点击时，属于功能不完整而不是合理降级。

## 对等契约

- 相同的数据筛选范围、排序方式和数量上限。
- 相同的序列化字段、空数据提示和错误语义。
- 成功返回可定位的实际文件路径，失败返回稳定的结构化错误前缀或类型。
- 文件先完整写入再原子替换，避免中断后留下可见的半文件。
- 使用平台原生且用户可访问的应用文档目录，不依赖额外存储权限。
- 平台 DI 测试或编译检查必须证明共享按钮解析到真实实现，而不是 fallback。

## 平台实现建议

Android 可使用应用外部文件目录下的 `exports` 或 `Download` 子目录；iOS 可使用沙盒 `Documents/Exports`。目录位置可以不同，但输出内容和调用方契约不能不同。

大批量记录应先设置上限，再在后台调度器完成查询、序列化和写入。导出诊断数据时还应保持与个人数据导出的隐私边界一致，不要因为平台差异扩大数据范围。

## 验证

- 空数据不创建无意义文件。
- 有数据时文件存在且可解析。
- Unicode、逗号、换行和引号正确转义。
- 写入失败不会被报告为成功。
- 两个平台的输出 schema 可由同一个解析器读取。
- 共享页面在所有平台均解析到真实 exporter。
