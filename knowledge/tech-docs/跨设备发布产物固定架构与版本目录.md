# 跨设备发布产物必须固定架构与版本目录

构建机架构不是发布目标真值。容器/二进制发布命令必须显式声明生产平台（例如
`linux/amd64`），并在产物 metadata 中记录 OS、arch、版本、commit、构建器和 SHA-256。

每个版本写入独立不可变目录；发布器只接收一个明确 manifest/path，不从共享目录按名称、
mtime 或 `latest` 猜包。上传前在目标架构 runner 或模拟环境做最小启动 smoke，并校验 manifest
与实际二进制架构一致。Apple Silicon 本机“构建成功”不能代替生产架构验收。

回归至少覆盖：默认 arm64 构建被拒、amd64 manifest/二进制不一致被拒、两个版本并存时
发布器只取显式目标。共享目录覆盖旧包或跨版本复用文件均判失败。
