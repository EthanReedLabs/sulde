# 用户可见模型输出的事实、叙事与清洗契约

## 问题原型

模型返回的 JSON、parser narrative、内部动作码或提示词回显被直接当聊天回复。某条实时路径做了清洗，
缓存回填、融合结果或最终 UI 却仍泄漏；简单字符串替换又因大小写、重叠短标记和词内命中产生误伤。

## 原则与机制

结构化结果是业务事实载体，不是用户叙事。系统先验证结构化字段，再由受控模板/生成器派生自然语言；
原始 telemetry 与最终用户 outcome 分开。动作码在分类源边界映射为领域语言，UI 清洗只是最后防线。
清洗规则覆盖生成、融合、缓存写读和渲染，采用完整词边界、大小写不敏感和最长标记优先。

## 根因与证据

根因是把“parser 成功”“模型有文本”和“用户得到可理解结果”合并为一个状态，并只在单一路径修补。
已验证故障包括裸 JSON、内部诊断码、关键帧编号、提示词回显和内部动作名从不同回填路径出现；多层
契约与严格评测可阻断。已排除“全部删除结构化数据”——日志、评测和业务逻辑仍需结构化字段，只是
不能原样承担用户沟通。

## 适用边界

- 所有聊天、教练反馈、通知和用户可导出文本均适用。
- 开发者专用诊断面可展示内部字段，但必须显式隔离、脱敏且不进入产品回复。
- 清洗不能猜测事实或把低置信错误包装得更自然；证据不足应明确表达不确定。
- 自由文本中的普通子串不得因碰巧包含短标记而被替换。

## 判定样本

### 路由正例

- **输入**：主路径回复自然，但缓存命中后出现 JSON、内部动作码或 prompt 片段。
- **预期**：apply
- **原因**：用户可见契约没有覆盖所有生产路径。
- **来源**：observed

### 路由反例

- **输入**：受限开发诊断页展示脱敏结构化 telemetry，产品用户无法访问。
- **预期**：skip
- **原因**：这是明确隔离的开发证据面，不是用户输出。
- **来源**：constructed

### 执行合格例

- **做法或输出**：结构化事实通过 schema/语义校验后派生叙事；动作码在源头映射；生成、融合、缓存
  和渲染共享 forbidden-marker 检查；最终 outcome 与 telemetry 分栏；严格 fixture 零泄漏。
- **预期**：pass
- **原因**：事实可审计、用户可理解，所有回填路径一致。
- **来源**：observed

### 执行失败例

- **做法或输出**：只在一个 composable/view 中 `replace("pose", "动作")`，长标记先被短标记破坏，
  缓存或通知仍显示内部内容。
- **预期**：fail
- **原因**：局部字符串修补既不完整也不安全。
- **来源**：observed

## 正确做法

1. 定义结构化事实 schema、最终 outcome schema 和用户叙事三层对象，不复用同一字符串字段。
2. 在分类/解析源边界把内部枚举映射到领域词汇；保留原码仅供受控 telemetry。
3. 实时、融合、缓存写入、缓存回填、通知和 UI 渲染共享同一清洁度策略。
4. 标记匹配大小写不敏感、完整词边界、最长优先；裸 JSON/prompt/关键帧编号用结构检测而非仅替换。
5. 严格评测以最终用户 outcome 为主，并读底层 telemetry 验证字段来源，不反过来展示 telemetry。

## 取舍

多一层叙事模型和清洗会增加代码，但避免 UI 各自猜测。受控模板可降低生成成本；需要自然表达时，
生成器仍只能消费已验证事实并受输出门禁约束。

## 消费与防复发

parser、融合器、缓存、消息模型、通知、UI 和严格评测共同消费。回归覆盖实时/缓存/离线/通知、大小写、
重叠标记、词内子串、裸 JSON、提示词回显和低置信降级。
