# 跨端大模型下载与平台能力门禁

## 问题模型

跨端应用常把模型管理界面和 ViewModel 放在共享层，但把下载器、文件系统和推理引擎放在平台层。某个平台若仍注入占位实现，共享 UI 看起来功能完整，点击后却只会固定返回“不支持”。这种失败不是网络问题，而是能力契约与界面可达性不一致。

模型下载和模型推理也必须作为两个独立能力。文件成功落盘只证明下载链路可用，不能证明推理后端、硬件加速、内存预算或流式输出可用。

## 能力门禁

为每个平台维护显式能力矩阵：

| 能力 | 下载 | 完整性校验 | 文本推理 | 视觉推理 | 语音识别 |
|---|---|---|---|---|---|
| 平台实现 | 独立验证 | 独立验证 | 独立验证 | 独立验证 | 独立验证 |

共享 UI 只能展示已由真实实现提供的入口。依赖注入配置应纳入静态检查：生产图中禁止把可交互入口绑定到 `Noop`、`Stub`、`Unsupported` 实现。若下载可用但推理未完成，界面必须准确表达该边界，不能把“文件已下载”升级成“模型已就绪”。

## iOS 大文件下载实现

数 GB 模型应使用 `URLSessionDownloadTask`，让系统把响应流式写入临时文件。不要使用 data task 后把完整响应装入 `Data`，也不要在下载完成时复制出第二份同尺寸文件。

推荐落盘事务：

1. 下载前检查目标资产大小加固定安全余量。
2. 使用 Wi-Fi/昂贵网络策略配置 session。
3. 在 delegate 中上报真实已接收字节和服务端总字节。
4. 完成回调内把临时文件移动到同容器的 `.part` 路径。
5. 对 `.part` 做精确大小或哈希校验。
6. 校验通过后原子移动为正式文件；失败立即删除 `.part`。
7. 模型目录放在 Application Support，并排除 iCloud 备份。
8. Flow、Task 或页面取消时，同时取消 download task 和 session。

移动临时文件而不是复制，既减少 I/O，也避免完成瞬间要求接近两倍可用空间。若产品要求后台续传或取消后恢复，应进一步使用 background session、resume data 或 HTTP Range；没有实现恢复能力时必须明确说明取消会重下当前资产。

## 状态机约束

下载状态至少区分：等待、下载中、校验中、可用、网络失败、空间不足、完整性失败和取消。进度总字节未知时不得伪造百分比；校验阶段也不应伪装成持续下载。

多资产串行下载时，每一阶段必须展示资产类型，并在启动下一资产前复查本地完整性，避免重复下载。最终成功条件是所有声明必需的资产均通过校验，但“推理可用”还要额外依赖对应运行时的加载和真机推理证据。

## 验证闭环

1. 编译目标平台的真实设备架构，而不是只编译模拟器。
2. 真机安装采用 install-only，再用可持续附着的调试器启动。
3. 观察点击后立即出现真实字节进度，并记录下载 started/failed/ready 日志。
4. 用错误网络、空间不足、取消和字节不匹配覆盖失败分支。
5. 完整下载后重启应用，验证文件识别与跳过重下载。
6. 单独加载推理后端并生成 token；下载证据不能替代推理证据。

## iOS 本地文本推理生命周期

下载完成后，平台实现必须把同一个推理服务实例贯穿模型加载、聊天初始化和流式生成。仅检查文件存在，或让 `isReady()` 永远返回 false 的占位实现，都会让界面长期停留在“模型未加载”。

推荐约束：

1. 用 Kotlin/Native cinterop 对接 llama.cpp 的窄 C ABI，明确管理 backend、model、context、sampler 和 generation state。
2. `loadModel(path)` 必须串行化；相同路径已加载时直接成功返回，不能重复映射大模型。
3. 流取消时必须在不可取消清理区释放 generation state，避免 KV cache 或 sampler 泄漏。
4. 启动探针与聊天初始化共用 DI 单例。探针生成首 token 后保留 session，让聊天直接复用。
5. 不要在低内存设备上卸载后立即重载 GB 级模型。文件页可能仍在回收，第二次 `mmap` 会失败，甚至触发系统终止。
6. 硬件后端必须由真机数据选择。旧款统一内存设备全量 Metal offload 可能因为大量跨后端 graph split 比 Accelerate 更慢；显式 GPU/NPU 目标不能替代首 token、持续吞吐、峰值内存和 CPU 占用测量。

iPhone X + 1.03 GiB Q4 模型的实测基线：CPU/Accelerate 路径完成真实加载与生成，首个非空 token 约 4.88 秒。该数据只证明文本推理可用；视觉投影层、视频 VLM 和 ASR 仍需独立门禁。

构建系统也必须把静态推理库作为 cinterop/link task 的显式输入，否则原生 archive 更新后 Gradle 可能错误命中 up-to-date 缓存，把旧运行时继续打进 App。

## 可迁移原则

- 共享界面的存在不代表每个平台具备对应能力。
- 占位实现只能服务于不可达路径或明确禁用状态，不能进入生产可交互路径。
- 大文件交付要以文件事务设计，而不是普通 API 响应设计。
- 下载、校验、加载、推理、硬件加速是五个独立门禁，必须分别验真。
- 模型 ready 必须由“文件完整 + 运行时已加载”共同决定，且聊天和探针复用同一服务实例。
- 真机上的启动存活和用户操作 walkthrough 都需要证据；编译通过不能替代运行时闭环。
