# 半自动流程创建前必须展示完整链路

## 原则

一个功能若包含**系统做不了、需要用户去外部完成的人工步骤**(线下操作、
第三方平台动作、异步等待),必须在用户**创建/启动它之前**展示完整流程链路:
每一步是什么、由谁做、在哪里做、完成后回到哪里继续。

## 为什么

半自动流程的断点在系统边界之外,界面上没有任何线索能推断出来。用户创建后
只看到一个停在中间状态的任务,不知道球在自己脚下——表现为"功能都做了,
但用户仅凭界面走不通",反馈通常是"不知道怎么使用"而不是具体报错,
极易被误判为文档问题而非流程设计缺陷。

## 附则:表单类型切换必须重置关联字段

同一创建表单支持多种类型/模式时,切换类型要**重新初始化关联字段的默认值**——
残留上一类型的值会让新类型的流程在校验或执行时走不通,且用户无从发现
(字段看起来"已填好")。

## 自检

发布前用"第一次见到它的用户"视角走一遍:只凭界面(不看文档、不问人)
能否从创建走到终态?卡住的那一步,就是缺失的链路展示。
