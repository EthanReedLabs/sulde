# 结构化建档与安全约束贯通训练计划

## 目标

个性化训练应用不能把首次建档当作普通资料表。训练目标、时间预算、器械可用性和当前安全限制必须成为后续计划、训练执行和动态调整共同读取的结构化事实。

## 建档模型

至少采集以下维度：

- 主目标：例如肌肥大、力量、减脂、恢复规律训练、动作能力或综合体能。
- 训练经验、身体基础数据。
- 每周可训练次数与单次可用时长，并在写入前做范围校验。
- 明确可使用的器械类型。没有重量基线时保留未知，不猜测负重。
- 当前疼痛、活动受限和专业人员要求暂停训练等主动限制。
- 用户对安全筛查的显式确认。

建档完成门槛应检查基础资料和结构化环境事实同时存在。仅保存一半资料时，应用重启后仍应返回建档，而不是进入主流程。

## 约束贯通

同一份结构化事实应贯穿三层：

1. 周计划生成：器械过滤动作白名单；主动限制进入系统上下文和硬约束；暂停要求生成休息计划。
2. 今日训练决策：根据恢复、疼痛、器械变化和时间不足进行替换、降量或暂停。
3. 手动编辑与进阶：动作候选仍受器械约束；没有能力或重量基线时用 RIR、节奏和停止条件控制，不编造重量。

只在今日训练临时修正安全问题是不够的，因为用户会先看到并可能接受一份不合适的周计划。限制必须在计划生成前生效，今日调整只处理当天的新证据。

## 一致性与失败处理

- 枚举或稳定 code 用于存储，展示文案单独映射，避免本地化文本成为业务键。
- 新增枚举值采用向后兼容扩展，旧值保持可读。
- 建档附属事实写入失败时不得发出完成状态。
- 重试应按稳定 code 去重，避免重复创建主动限制。
- 详细重量档位允许后续完善，但“未知”必须保持未知。

## 验证清单

- 未确认安全筛查时，建档不会完成。
- 器械事实可被计划白名单实际读取，而不只是 UI 展示。
- 疼痛和暂停限制可在周计划请求中观察到。
- 暂停要求明确覆盖 7 日训练安排。
- 只有基础资料、没有环境事实时，启动仍进入建档。
- Android 与 iOS 使用相同领域事实和约束规则。
