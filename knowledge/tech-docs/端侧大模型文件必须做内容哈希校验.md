# 端侧大模型文件必须做内容哈希校验

## 问题原型

端侧运行时只按文件名、存在性或近似大小判断模型 ready，同尺寸损坏、错误版本和断点拼接错误都
能越过门禁；准备脚本、发布清单与设备缓存管理器还可能各自维护一套漂移的摘要。

## 根因与证据

字节数只能证明长度，不能证明内容身份；文件名和 mtime 更弱。已验证 fixture 中，同尺寸单字节
替换可通过大小检查但必然改变 SHA-256，截断/超长文件可由精确字节数先拒绝。临时下载、流式
摘要、原子替换和单一清单摘要组合后，失败不会破坏旧的可用模型。

## 适用边界

- 适用于端侧模型、词表、量化权重和其他大体积、内容身份必须固定的运行时资产。
- SHA-256 证明内容一致性，不证明来源可信；供应链签名和发布审批仍需独立执行。
- 发布方未给出可信摘要时只能标为未验证，不能用本次下载结果自签名后声称来源可信。

## 路由正例

- **输入**：模型文件大小正确但推理异常，ready 门只检查“约 4GB”和文件存在。
- **预期**：apply
- **原因**：近似长度不能识别同尺寸替换或错误版本，缺少内容身份门禁。
- **来源**：observed

## 路由反例

- **输入**：小型用户临时文本每次都由数据库直接生成，没有固定发布版本或共享资产身份。
- **预期**：skip
- **原因**：它不是需要按发布清单固定内容身份的端侧大资产。
- **来源**：constructed

## 执行合格例

- **做法或输出**：清单固定精确字节数和 SHA-256，临时文件流式校验后原子替换，失败保留旧模型。
- **预期**：pass
- **原因**：长度、内容身份和切换原子性都被独立验证且共享同一真值。
- **来源**：observed

## 执行失败例

- **做法或输出**：文件存在且大小接近文档中的“约 X GB”就写 ready，摘要字段留空或填占位值。
- **预期**：fail
- **原因**：门禁既不能识别损坏，也把未知完整性伪装成可运行状态。
- **来源**：observed

## 结论

文件大小相同不代表内容完整。端侧模型在进入 ready 状态或替换当前可用模型之前，必须同时通过精确字节数和已固定的内容哈希校验。

## ✅ 正确

1. 从可信来源独立获取并固定模型版本、字节数和 SHA-256。字节数必须是精确值，「约 X GB」一类的估算占位不能作为 ready 判据；发布方未直接提供时，可从下载源的 HTTP 响应头独立采集精确值（`content-length`，或托管平台的扩展头如 `x-linked-size`、`etag`），采集一次后固定进清单再使用。
2. 下载到临时文件，不直接覆盖当前可用模型。
3. 先检查精确字节数，再以固定大小缓冲区流式计算 SHA-256。
4. 校验成功后原子移动到正式路径；校验失败立即删除临时文件并报告独立错误类型。
5. 每次判断本地模型是否 ready 时重复校验，避免外部写入、损坏或同尺寸替换被忽略。
6. 断点续传测试必须使用目标文件的真实前缀与后缀，不能只构造同尺寸随机数据。

## 工程边界

- 多 GB 文件不能整体读入内存计算哈希；Android 使用流式 `MessageDigest`，iOS 可使用 `NSInputStream` 配合 CommonCrypto。
- 未经验证的哈希应保持为空，不能填写占位值制造虚假保障；这类资产只能明确标记为字节数校验，待哈希采集后升级。
- 字节数同理不能用估算值占位（补充：「约 X GB」场景）。ready 判断与发布清单中的字节数必须是精确值，来源采集后固定进清单，所有入口引用同一份精确值。
- 主机侧准备脚本、设备侧缓存管理器和发布清单必须引用同一份固定摘要，避免不同入口采用不同完整性标准。
- 哈希校验解决传输损坏和非预期替换，不替代模型来源签名、供应链审计与发布审批。

## 验证用例

- 正确文件通过。
- 字节数不足或超出时拒绝。
- 字节数相同但内容被修改时拒绝。
- 合法断点续传拼接后通过。
- 哈希失败后临时文件被删除，旧的可用模型不受影响。

## 消费与防复发

- 下载器、发布清单、设备缓存管理器、运行时 preflight 和交付验收引用同一资产 manifest。
- CI 生成同尺寸篡改、截断、超长、错误前后缀和中断恢复 fixture，并验证旧模型不被覆盖。
- 报告记录版本、精确字节数、摘要和来源标识；不得只记录“下载成功”或 ready 布尔值。
