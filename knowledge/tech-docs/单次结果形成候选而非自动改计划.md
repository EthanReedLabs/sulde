# 单次结果形成候选而非自动改计划

## 原则

长期计划产品不应依据一次表现直接修改后续处方。单次训练负责形成可解释候选，周期复盘负责聚合证据和提出正式变更，用户负责确认或拒绝有实质影响的调整。

## 单次候选结构

候选至少包含：

- 当前处方的人类可读摘要。
- 建议后的处方摘要。
- 形成建议的证据原因。
- 是否需要周期复盘确认。

候选应结构化写入决策审计记录，而不是只生成 UI 文案。界面明确标记“尚未生效”，避免用户把建议误解为已修改计划。

## 安全边界

- 明显动作问题可以候选降低负重、降低难度或回退变式。
- 轻微且可修正的问题优先保持负荷并加入技术目标。
- 单次稳定表现只形成小幅进阶候选，不自动加量。
- 缺少动作证据或执行事实时不形成实质变更。
- 周期复盘聚合多次执行、恢复与动作证据后，再由用户确认生成新版本。

## 可验证性

领域测试应固定输入证据并断言 before/after/reason、确认边界及持久化 delta。协议结构变化时升级决策协议版本，防止旧幂等键留下不完整审计记录。
