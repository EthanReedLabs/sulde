# Claude Code 思考模式使用规范

> 两端终端共用，按场景自动选择合适的思考强度。

## 一、4 档强度

| 档位 | 触发关键词 | 适用 | 推理深度 |
|------|----------|------|---------|
| 默认 | 不带 | 简单查询、读文件 | 1× |
| think | "think" | 标准修改 | 2× |
| think hard | "think hard" / "think harder" | bug 修复、新功能 | 4× |
| **ultrathink** | "ultrathink" | UI 还原、架构、复杂决策 | 8× |

## 二、Skill 自动触发（无需手动）

| Skill | 默认思考模式 |
|-------|------------|
| `/ui-impl` | ultrathink（5 阶段思考流程） |
| `/crash-fix` | think hard（4 阶段诊断） |
| `/code-review` | think hard |
| `/bug-hunt` | ultrathink |
| `/parallel-dev` | think |
| `/assign` | 默认 |

执行这些 skill 时已自动启用对应思考模式，不需要手动加关键词。

## 三、手动场景（需要主动加关键词）

### 必须用 ultrathink 的场景

```
ultrathink，{任务}
```

- 架构设计 / 技术选型决策
- 性能优化方案
- 安全审查
- 复杂代码重构
- 设计 + 业务冲突调解
- 新 skill 设计

### 适合用 think hard 的场景

```
think hard，{任务}
```

- 排查不明显的 bug
- 设计中等复杂度的新功能
- API 设计
- 测试用例设计
- 一般代码审查

### 用默认即可的场景

- 读代码 / 找文件
- 简单文本修改
- 命令查询
- 格式调整

## 四、9 个高效用法模式

### 1. 角色限定 + 思考强度

```
ultrathink，作为有 10 年经验的高级 Android 工程师，审查这段代码
```

### 2. 多步骤强制思考链

```
think hard，分三步：
1. 先列出所有可能的根因
2. 再排除最不可能的
3. 最后给出最终诊断
```

### 3. 对抗性思考（找漏洞）

```
ultrathink，假设你是审查者，找出这个方案的 5 个潜在问题
```

### 4. 自我批判循环

```
ultrathink，先给方案，然后批判自己的方案，再修改
```

### 5. 约束驱动思考

```
ultrathink，在以下约束下找方案：
- 不能修改 Store
- 不能引入新依赖
- 必须向后兼容
```

### 6. 根因追溯

```
ultrathink，对照截图差异，从根本原因找问题（不是表面症状）
```

### 7. 边界穷举

```
ultrathink，列出这个功能的所有边界场景
```

### 8. 显式权衡

```
ultrathink，给出 3 个方案，每个标注：
- 实现成本（小时）
- 维护成本
- 性能影响
- 风险
然后推荐最优
```

### 9. 反向验证

```
ultrathink，先假设你的修复是错的，找出反驳证据，没找到再确认正确
```

## 五、复合用法（实战最强）

```
ultrathink。

角色：高级移动端工程师 + 严苛代码审查者

任务：{具体任务}

执行流程：
1. 列出所有需要考虑的点（不少于 N 项）
2. 对每点分析根因
3. 给出 2-3 种方案，权衡利弊
4. 选最优方案，并自我批判：风险是什么？
5. 最终代码 + 验证步骤

约束：
- {约束 1}
- {约束 2}
- {约束 3}
```

这种结构化提示 = 完整"思考工作流"，比单纯加 ultrathink 强 3-5 倍。

## 六、关键技巧

| 技巧 | 说明 |
|------|------|
| **关键词放最前面** | 模型先看到才会切换思考模式 |
| **越具体越好** | "ultrathink 对比这两张图" 比 "ultrathink" 强 |
| **分步骤** | 1./2./3. 比一段话好 |
| **加约束** | 限制范围让思考更深 |
| **要求自我批判** | 单次推理不够时让它自己 review |
| **避免滥用** | 简单任务用 ultrathink 浪费 token，反而慢 |

## 七、Tab 键快捷切换

在 Claude Code 终端输入框内按 `Tab` 键可循环切换 4 档：
```
默认 → think → think hard → ultrathink → 默认
```

切换后输入框前会显示当前模式标识，直到下次切换。

## 八、永久默认（可选）

如果整个项目都需要更强思考模式：

```json
// ~/.claude/settings.json
{
  "thinking": {
    "default": "think_hard"
  }
}
```

不推荐设默认 ultrathink（消耗 token 大、响应慢）。建议按场景手动选择。

## 九、Token cost 结构

### 9.1 思考预算的实际开销

| 思考档 | 思考 token | 相对 cost | 典型场景 |
|---|:-:|:-:|---|
| 默认 | 0 | 1× | 读单文件 / 简单回答 / 翻译补全 |
| think | ~4K | 1.5× | 多文件交叉查询 / 配置修改 |
| **think hard** | **~16K** | **3×** | 新 Feature 开发 / UI 还原 / API 接入 |
| **ultrathink** | **~64K** | **8×** | 架构决策 / 根因追溯 / 复杂权衡 |

思考 token **不显示给用户但完全计费**。1 次 ultrathink ≈ 8 次默认任务。

### 9.2 `/parallel-dev` 的乘数效应

每开一个 subagent = 一份独立 prompt，包括：
- 项目 CLAUDE.md（协调端 / Android / iOS 各一份，每份约 17-20 KB）
- 相关 skills 注入（约 8 KB/次）
- 工具调用（Read 文件 / Grep / Bash）完整结果
- 思考预算（0 / 4K / 16K / 64K）
- 最终代码生成 output

**单 /parallel-dev 调用的 cost 近似**：

```
total = N_agents × (
    fixed_prompt (~30-50 KB)
    + reads_accumulated (设计稿 + PRD + yaml)
    + thinking_budget (0-64K)
    + output_tokens
)
```

**实测基线参考**（一次 3-agent Android /parallel-dev）：
- 3 agents × 约 10 分钟运行 → 单端 session jsonl 净增 ~12 MB
- 其中 Dev A ultrathink 64K × 1 + Dev B/C think hard 16K × 2 = 96K 思考 token 基线
- 加读取 + 代码生成，实际 input_tokens 累计每端约 800K-1.2M（5 min prompt cache 命中率影响巨大）

### 9.3 浪费陷阱 — 反模式交叉索引

| 陷阱 | cost 级别 | 引用 |
|---|---|---|
| 简单任务用 ultrathink | ×8 浪费 | 反模式:思考预算滥用 |
| 多 agent 全 ultrathink 不按矩阵 | ×3 浪费 | 反模式:并行思考预算未分级 |
| **协调端 Bash `cd` 子端 → CLAUDE.md 重复注入** | **数十次重复（实测 1MB+/session）** | **反模式:cd 子端导致 CLAUDE.md 注入** |
| 大文件整读（数千行 yaml / PRD）不 offset/limit | 单次 ~50K token | — |
| 同一 session 长期积累（> 20 MB jsonl）未 `/clear` | 每轮 cache miss 膨胀 | — |

### 9.4 省 token 清单（按收益排序）

1. **按矩阵严格分配思考预算**（§二 skill 自动 + §三 手动场景已明确）
2. **Bash 不 cd 子端**（协调端专属，避免子端 CLAUDE.md 重复注入）
3. **大文件用 Read offset/limit + Grep 指定行**，不整文件读
4. **session 24 MB 以上开新会话**（prompt cache 收益递减）
5. **/parallel-dev 前做文件交集检查**，避免失败重跑

### 9.5 量化诊断方法

任何时候想知道 "这个 session 花了多少" → 看 jsonl 体积：

```bash
ls -lh ~/.claude/projects/<项目目录>/*.jsonl
```

基准：同类任务 session 超过 10 MB 即警惕，超过 20 MB 应强制 `/clear` 或开新会话。
