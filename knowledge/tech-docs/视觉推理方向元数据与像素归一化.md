# 视觉推理方向元数据与像素归一化

## 问题

移动相机常把传感器方向的像素交给分析管线，同时用 rotation metadata 表达显示方向。
Preview 可能自动把人显示为直立，ImageAnalysis 和视觉模型却仍消费横向像素。因此“预览
看起来正确”不能证明模型输入方向正确。

常见症状是预览中的人直立但姿态骨架横向绘制；调用目标旋转或视觉 SDK 的 processing
options 后没有报错，真机 landmark 坐标却仍位于传感器坐标系。只改绘制坐标可能让覆盖层
暂时对齐，但模型依然在错误方向上推理。

## 五层方向契约

方向必须贯穿以下五层：

1. 传感器或视频解码后的实际像素宽高。
2. 相机/容器提供的 rotation 和 mirror metadata。
3. 视觉 SDK 实际接收的像素与 processing options。
4. 模型返回 landmark、mask 或 box 的坐标系。
5. UI 容器中的缩放、裁剪、镜像和坐标映射。

任意一层只更新 metadata 而下一层假定像素已旋转，就会产生方向漂移。API 接收了 rotation
参数也不代表内部 graph 在当前版本、任务类型和设备上真正应用了它。

## 归一化策略

1. 在分析入口记录原始宽高、rotation metadata、镜像状态和模型输入宽高。
2. 用非对称姿势或带方向标记的 fixture 验证 SDK 原生旋转能力，避免人体左右对称产生假通过。
3. 若目标设备证明 processing option 没有改变实际推理坐标，在单一输入边界显式旋转像素。
4. 像素归一化后把下游 rotation 归零，并保留“已归一化”契约，禁止重复旋转。
5. landmark 绘制只消费归一化坐标；Preview 的自动行为不能成为分析管线的隐式依赖。
6. 前置旋转会增加拷贝、延迟和内存，应在低端设备测量并保留更高效实现的替换点。

实时相机和文件视频必须分别验证。CameraX 的 `ImageProxy` metadata 与视频容器的 rotation
metadata 来自不同路径，修复其中之一不能推导另一条链路已正确。

## 证据与验收

- 前后摄像头、竖屏和横屏分别对比预览、模型输入和结果方向。
- 保存最小诊断摘要：原始/归一化尺寸、输入 rotation、镜像状态和首个非空结果。
- 设备上同时检查关键点位置与动作识别结果，不能只看骨架是否“像是直的”。
- 故意恢复错误方向，确认视觉回归或坐标断言会判红，再恢复为绿。
- 性能记录包含像素旋转耗时、分析帧率、内存与热状态。

## 可迁移原则

- Preview 与 ImageAnalysis 是两个独立管线。
- rotation metadata 不等于像素已经旋转。
- 第三方视觉 API 的方向行为必须由目标设备的输入输出事实验真。
- 方向归一化只能有一个所有者，并在下游使用明确的零旋转契约。
