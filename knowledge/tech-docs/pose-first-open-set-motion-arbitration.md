# Pose-first 的开放集运动理解与模型仲裁

## 问题原型

端侧视频清晰但 VLM 仍误判动作、产生轻微问题幻觉或延迟数分钟。仅加强 prompt 不能改变输入帧冗余、
时序丢失和动作闭集假设。用户关注某个部位时，系统还容易把关注点误当成异常证据。

## 原则与机制

先限制输入预算并保留原始时间戳，以同步逐帧 Pose 推理构建关节轨迹、相位和运动原语；开放集分类
允许 `canonical=null`，只有置信度足够才映射固定动作名。评分来自可解释轨迹和模式。VLM 读取选定
关键帧、Pose 摘要和用户问题，负责语义解释与不确定性补充；与高置信 Pose 冲突时，Pose 裁决，
同时直接回答用户关注点。高可见、规则评分 OK 的样本走确定性快速路径。

## 根因与证据

根因是把生成模型当成动作身份和定量评分的唯一权威，并把实时异步姿态模式直接复用于离线视频。
已验证改法包括：Pose 引导选帧、逐帧同步推理、时间戳保留、开放集原语、冲突仲裁和快速路径；
可见度充分的样本延迟下降且错误轻微诊断被压制。已排除“VLM 永远不用”——低可见、复杂上下文和
自然语言解释仍需要生成模型。

## 适用边界

- 适用于人体动作、康复或训练视频，且可获得可靠关键点/轨迹。
- 严重遮挡、多人、镜头移动或低置信 Pose 时不得强裁决，返回不确定或让 VLM 补充。
- 用户关注点影响解释优先级，不改变没有证据的动作或伤害结论。
- 历史趋势只比较同 canonical 或同运动模式且高可见的样本；存储失败不阻断当前分析。

## 判定样本

### 路由正例

- **输入**：清晰运动视频被 VLM 误命名或报告无轨迹支持的问题，Pose 置信度高且规则评分干净。
- **预期**：apply
- **原因**：存在可解释强证据与生成结论冲突。
- **来源**：observed

### 路由反例

- **输入**：低光多人视频关键点大面积缺失，VLM 只能给出低置信场景描述。
- **预期**：skip
- **原因**：Pose 不具备仲裁资格，应保持不确定。
- **来源**：constructed

### 执行合格例

- **做法或输出**：输入帧预算受控，Pose 带时间戳；未知动作保留原语而不硬映射；高置信冲突由 Pose
  裁决，回答仍覆盖用户问题；高可见 OK 样本不触发无增益的长生成。
- **预期**：pass
- **原因**：身份、评分、解释和延迟各由合适证据负责。
- **来源**：observed

### 执行失败例

- **做法或输出**：用户问膝部就输出“膝部异常”，或 VLM 一句话覆盖完整高置信轨迹。
- **预期**：fail
- **原因**：关注点被当成证据，生成结果覆盖可解释事实。
- **来源**：observed

## 正确做法

1. 先按时长/清晰度/变化量控制解码预算，再用 Pose 变化挑选关键帧。
2. 离线视频逐帧同步推理并保存媒体时间戳，不复用依赖实时回调顺序的模式。
3. 从轨迹提取开放集原语、可见度、相位和量化指标；低置信保持 null canonical。
4. 建立 `Pose strong / weak × VLM agree / conflict` 仲裁表，禁止自由覆盖。
5. 高可见且规则 OK 走快速路径；其他样本把结构化 Pose 摘要交给 VLM 解释。
6. 趋势基线只读取可比样本，写入失败记录 telemetry 但不阻断本次结果。

## 取舍

同步 Pose 增加本地计算，但减少无效帧和长生成；仲裁会牺牲少量生成自由度，换来可解释评分和稳定
延迟。Pose 覆盖不足时必须退回不确定，而不是假精确。

## 消费与防复发

视频预处理、Pose 引擎、动作分类器、VLM prompt、融合器和评测器共同消费。fixture 覆盖已知/未知
动作、遮挡、冲突、用户聚焦、快速路径和不可比历史。
