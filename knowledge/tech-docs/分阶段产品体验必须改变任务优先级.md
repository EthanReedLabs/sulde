# 分阶段产品体验必须改变任务优先级

## 原则

采集了用户经验等级，却让所有等级进入同一个页面，只替换标题或说明文字，不构成真正的个性化。阶段差异应落实到首屏任务优先级、信息密度和自主权。

## 推荐层级

- 新手：今天做什么、如何开始、动作怎么完成，减少同时出现的决策。
- 中级：今日任务之外展示完整周计划，便于安排训练日与恢复日。
- 高级：先展示处方执行、恢复状态和微周期上下文，再提供自主加练与完整动作目录。

## 数据边界

不同页面只能重排真实存在的数据。没有采集速度、功率、训练负荷或疲劳指标时，不能为了让高级页面显得专业而生成这些数字。应先展示已有的计划完成、组次处方、主观状态、营养重点和训练历史。

## 工程约束

- 经验等级必须映射到独立且可测试的页面策略，不能让高级等级落入中级 fallback。
- 共享组件可以复用，但页面编排和主操作必须体现不同目标。
- 完整能力入口应复用统一目录和导航，不要为每个阶段复制数据源。
- 路由测试应锁定每个等级的独立映射，防止后续重构重新合并成占位页面。
