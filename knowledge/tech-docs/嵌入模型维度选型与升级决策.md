# 嵌入模型维度选型与升级决策

## 问题原型

固定维度向量库同时面临两类问题：一类是为了提升检索质量而考虑更换嵌入模型，另一类是
模型已经变化、写入才暴露维度不兼容。前者容易把“更高维”误当成独立旋钮，后者容易在
每次正常写入前增加 schema 查询，或仅凭模糊的底层错误文案把不同故障都归成维度错误。

目标是同时守住三个不变量：模型升级有证据、成功路径没有不必要的诊断 I/O、异常转换
只发生在结构化 schema 明确证明维度不一致时。

## 原则与机制

### 维度不是可调参数

向量维度由嵌入模型的输出层决定(small 档 512 / base 档 768 / large 档 1024 /
在线大模型 1536+)。"要不要更高维"实际是"要不要换更大的模型",随模型一起变的
还有推理延迟、模型体积和相似度分布。

### 选型三角

1. **部署形态**:本地 CPU 推理 = 零 API 成本、零网络往返、毫秒级查询嵌入,
   hook/每轮注入类场景必须控制在秒级预算内;在线嵌入 = 按 token 计费 + 网络
   延迟 + 服务端维度契约风险
2. **检索规模**:万级条目的库,检索质量瓶颈在**混合架构**(词面 BM25 + 向量
   融合 + 分数门策略),不在向量精度的最后几个百分点——小模型与大模型在公开
   基准上差距为个位数百分点,而实际踩到的召回问题(串场/口头禅/归一化穿门)
   没有一个由维度不足导致
3. **成本是乘法**:维度翻倍 → 每条向量存储、嵌入耗时、每查询点积、内存全部
   翻倍;收益在中小规模上量不出来

结论模式:**本地小模型 + 混合检索**优先起步,大模型的门保持打开但要证据才进。

### 升级触发条件(绑定证据,不凭感觉)

检索质量数据(采纳率统计/召回日志)中出现**成规模的"词面能命中、语义不命中"
案例**——这是嵌入模型成为短板的特征信号。没有该信号时升维属于没有病症先吃药。

## 根因与证据

- 向量列采用固定长度 schema 时，集合维度在建表后就是存储契约；输出维度不同的模型
  不能直接向同一集合写入。
- 底层合并写入异常可能同时覆盖维度不匹配、字段漂移、空值、I/O 和其他运行时故障。
  错误字符串不能唯一证明根因，只有 schema 中的 stored dimension 与本次 incoming
  dimension 比较才是确定证据。
- 已验证的适配器回归表明：成功写入不读取 schema；维度不匹配在完成一次嵌入并触发
  底层写入失败后被确认；同维度失败和诊断失败均保留原始异常或既有迁移处理。
- 已排除“所有写入前都必须预检”和“看到笼统错误文案即可归因”两种假设。前者把低频
  故障成本施加给全部成功请求，后者会把不同根因伪装成同一种维度错误。

## 适用边界

- 适用于 schema 能暴露固定向量长度、且失败后仍可安全读取 schema 的向量存储。
- 若一次失败写入会不可逆破坏唯一数据，必要的安全预检不能移到失败后；应先设计事务、
  影子集合或可回滚迁移。
- schema 无固定长度、读取失败或 stored dimension 与 incoming dimension 相同时，证据
  不足以判定维度不匹配，必须保留原始写入异常及原有恢复分支。
- 维度确认不匹配只负责给出可操作错误，不授权自动删除、重建或迁移用户集合。
- 网络超时、权限失败、字段 schema 漂移和空值错误没有维度差异证据时不适用本诊断结论。

## 路由正例

- **输入**：更换嵌入模型后，固定维度集合在合并写入阶段失败；需要只在失败后读取 schema，
  确认维度并保留底层异常链。
- **预期**：apply
- **原因**：同时具备固定维度契约、写入失败、结构化诊断和原异常保留要求。
- **来源**：observed

## 路由反例

- **输入**：向量写入因网络超时失败，schema 显示维度一致，也没有模型切换证据。
- **预期**：skip
- **原因**：相似表象来自传输故障，维度证据明确不支持转换。
- **来源**：constructed

## 执行合格例

- **做法或输出**：正常写入不查询 schema；写入失败后才比较 stored 与 incoming 维度；
  仅在两者明确不同时抛出专用错误并把原写入异常设为 cause；同维度或诊断失败时继续
  既有迁移逻辑或原样抛出；远程路径只读取 schema，不物化整表。
- **预期**：pass
- **原因**：同时满足成功热路径零诊断、证据化归因、异常链完整和数据不被自动改写。
- **来源**：observed

## 执行失败例

- **做法或输出**：每次写入前查询 schema，或匹配模糊错误字符串后统一抛维度错误；
  schema 读取异常覆盖原始写入异常，并自动删除集合重建。
- **预期**：fail
- **原因**：增加成功路径成本、制造错误归因、丢失真实根因并越权修改用户数据。
- **来源**：constructed

## 正确做法

### 选型与升级流程

1. 换模型配置(全部库共用同一模型,一起换)
2. **全清向量表**——铁律:一库一维度。同一向量表混入不同维度的向量,
   会在存储层合并写入时直接崩库(实测教训),绝不允许新旧维度共存
3. 懒嵌入后台重建:清空后由预热/查询触发自动补嵌,期间检索退化为纯词面,
   可用不中断
4. **全部分数阈值重标定**:余弦资格门、融合分数线都绑定旧模型的相似度分布,
   换模型后整体平移、原值失义;用入档的标定样本对重新量(见 ap-0182)
5. 回归验证:泄漏对仍拦、真相关对仍放、同库召回不受影响

生产迁移中的清空或重建必须是显式、已授权且有备份/回滚的运维步骤，不能作为单次写入
维度错误的自动恢复动作。

### 写入失败后的诊断顺序

1. 在 embedding 和固定向量类型构造前取得 incoming dimension，但不查询集合 schema。
2. 执行 embedding、构造数据点并尝试底层写入。
3. 仅捕获该写入层声明的异常类型；保存原始异常对象。
4. 在异常分支读取集合 schema。远程或子进程适配器使用 schema-only RPC，禁止为了取
   维度物化整表。
5. schema 同时给出固定 stored dimension 且它与 incoming dimension 不同时，抛出包含
   两个维度和人工重建/迁移建议的专用错误，并显式链接原始异常。
6. schema 读取失败、维度未知或两者一致时，诊断异常只作调试留痕；随后继续原有字段
   schema 迁移判断，若不命中则原样抛出最初的写入异常。

```python
try:
    write(vectors)
except WRITABLE_BACKEND_ERRORS as original_error:
    try:
        stored_dimension = read_fixed_dimension_from_schema()
    except Exception as diagnosis_error:
        debug_log(diagnosis_error)
    else:
        if stored_dimension is not None and stored_dimension != incoming_dimension:
            raise VectorDimensionMismatch(
                stored_dimension, incoming_dimension
            ) from original_error

    preserve_existing_migration_or_raise(original_error)
```

判断依据来自 schema 数值，不来自特定后端的错误文案。专用错误应携带集合标识、stored /
incoming dimension 和“显式重建或迁移”的建议，但不能在异常处理器内自动执行这些动作。

### 配套设计

- 向量**不参与跨设备同步**(各端按本地模型自算)——换模型不产生迁移负担
- 标定样本对与阈值一起入档,升级时不用重新收集

## 取舍

- 失败后诊断让第一次真实维度错误付出一次 embedding 和失败写入的成本，换来所有成功
  写入不再持续读取 schema；适合失败低频且写入失败不破坏数据的路径。
- schema-only 诊断减少远程传输和内存占用，但需要适配器提供稳定的 schema 操作。
- 诊断失败时保留原异常意味着调用方可能仍看到较底层的错误；这比伪造一个确定的维度
  结论更安全，也为字段迁移、重试和排障保留真实证据。
- 模型升级会同时改变存储、性能和相似度分布，不能只重建向量而沿用旧阈值。

## 消费与防复发

- 向量存储适配器的设计评审检查：成功路径不得无条件读 schema；异常转换必须有结构化
  维度证据并保留 cause；维度错误不得触发自动删库。
- 回归测试至少覆盖六类场景：成功路径零诊断、确认不匹配、同维度正常写入、同维度写入
  异常、诊断本身失败、远程 schema-only 诊断且不物化整表。
- 模型升级清单同时检查集合重建、阈值重标定和回滚方案；不能把“配置已换”当成完成。
- 错误归类审查可联动 `ap-0223`；热路径诊断位置与任务范围治理可联动
  `work-model/failure-triggered-diagnostics-and-scope-freeze`。
