# 端侧文本推理连续请求的状态边界

## 问题

移动端通常长期持有本地模型和推理上下文，以避免每轮对话重复映射数 GB 权重。复用可以
降低延迟，但也容易把四种生命周期错误地合并：模型权重、会话上下文、单次生成事务和
流式输出缓冲。

典型表现包括：首轮生成正常而第二轮在 decode 阶段失败；两个入口并发请求后 token 位置
互相污染；取消后下一轮继承半份 KV 状态；中文 token 的部分字节被直接转换成平台字符串，
最终在 JNI/FFI 边界崩溃。

## 所有权模型

| 资源 | 推荐生命周期 | 关键约束 |
|---|---|---|
| 模型权重与只读元数据 | 进程或推理服务 | 可跨会话复用，加载和卸载必须串行 |
| KV / conversation context | 明确的会话 | 只能由一个生成事务写入，切换会话不能串台 |
| sampler / generation state | 单次生成 | 成功、失败和取消都必须走同一终止协议 |
| token byte buffer | 单次流式响应 | 只在形成完整 UTF-8 前缀后跨语言边界输出 |

模型权重复用不等于请求状态可以无条件复用。独立请求应从已知初始状态开始；连续对话若
保留 KV，也必须绑定稳定会话身份，并定义取消时是回滚到已提交前缀、清空，还是从历史
重新构建。禁止让半次生成成为下一次请求的隐式起点。

## 生成事务

拥有 native context 的服务层应把一次生成视为完整事务：

1. 校验会话身份和上下文版本。
2. 获取该 context 的独占写入权。
3. 按会话策略清理、恢复或校验 KV 状态。
4. 创建本次 sampler 与 generation state。
5. 执行 decode，并只提交完整、获准的输出增量。
6. 在成功、异常和取消路径统一释放请求级资源。
7. 释放独占权后才允许下一请求进入。

锁或 actor 必须放在资源所有者层，而不是要求聊天页、后台任务和探针各自遵守调用约定。
只保护单个 `decode` 调用也不够：prompt ingestion、token generation、KV 更新和 teardown
共同构成一个不可交错的事务。

## UTF-8 流式边界

BPE token 是字节片段，不保证每个 token 都是完整字符。正确桥接方式是累计 token bytes，
提取当前最长合法 UTF-8 前缀后再创建平台字符串，并把不完整后缀留给下一 token。不能逐
token 调用要求合法 UTF-8 的字符串构造 API，也不能用替换字符静默吞掉边界错误。

响应结束时若仍有非法残留，应记录独立错误并终止该响应，不能把损坏文本持久化。字符
拼接测试应覆盖跨 token 的中文、emoji、组合字符和取消发生在半个字符之后的情况。

## 验证

- 同一进程连续执行多轮请求，不能只验证第一轮。
- 并发触发前台对话、后台任务和启动探针，证明同一 context 不会被并行写入。
- 在 prompt ingestion、首 token、流式中段和结束前分别取消，下一请求都从已知状态开始。
- 构造跨 token 的多字节字符，确认中间片段不会跨 JNI/FFI 输出。
- 每轮记录会话身份、KV 策略、事务终态和 UTF-8 缓冲余量，不以“生成了文本”代替状态验收。

## 可迁移原则

- 权重、会话、生成和字节缓冲是四个不同的所有权层级。
- native 会话并发必须由资源所有者强制，不能依赖调用方自律。
- token、字节和字符是三种边界，流式桥接必须显式转换。
- 首轮成功不能证明长期会话、取消恢复或并发路径可用。
