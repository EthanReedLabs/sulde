# 用户操作的审计来源必须真实

当用户通过编辑器直接修改并保存业务对象时，不能复用默认系统更新接口。否则版本历史虽存在，但 actor、原因和确认状态是假的，可解释性与责任边界都会失效。

落地规则：调用支持原因的持久化接口；明确记录 `changeType`、`actor=user`、操作入口和用户确认状态；涉及越过预算或安全建议时，单独记录 override confirmation。展示层必须为该 change type 提供用户可读文案，不能退化成“系统根据证据更新”。

测试同时覆盖 repository 收到的审计字段和历史 presenter 输出，避免只修数据库或只修界面。
