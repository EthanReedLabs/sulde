# 订阅权益必须来自商店交易真值

## 原则

客户端不能用本地布尔值模拟订阅成功。每次启动和恢复购买都应从应用商店当前有效交易重新构建权益，以正确处理到期、退款、撤销和换设备。

## 交易状态

- `PURCHASED`：可以授予权益，但必须及时 acknowledge 或 finish transaction。
- `PENDING`：只展示等待确认，不能提前开放权益。
- 用户取消：保持原权益，不作为错误重试。
- 商店或商品不可用：明确降级，不创建假商品和假价格。
- 恢复购买：重新查询全部有效交易，不依赖上一次页面状态。

## 产品与数据边界

付费墙适合专业派生能力，例如自适应周期计划、深度动作分析和年度专业复盘。训练原始记录、导出、删除及隐私授权属于用户数据权利，不得被订阅状态阻断。

## 生命周期

商店连接通常是应用级单例，不能随单个付费页面 ViewModel 销毁。购买需要 Activity 或呈现控制器时，只在宿主可交互生命周期内登记引用，并及时清除。

## 验证

测试必须覆盖最高有效 tier 推导、取消不授予权益、pending 不授予权益、恢复购买、acknowledge，以及免费用户仍能访问自己的基础数据。
