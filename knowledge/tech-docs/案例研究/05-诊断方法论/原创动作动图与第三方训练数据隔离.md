# 原创动作动图与第三方训练数据隔离

## 场景

健身产品常同时需要大规模动作元数据、动作教学动图和模型训练语料。开源仓库可能把开放许可的数据结构与单独授权的图片/GIF 放在一起。直接克隆后整体送入训练或产品包，会把“仓库可访问”错误理解为“全部内容可商用”。

## 双流水线

必须把流程拆成两条：

1. **元数据训练流水线**：只提取动作名称、类别、器械、目标肌群、协同肌和许可允许的教学文本；剔除图片、GIF、媒体 ID、路径和媒体 attribution。
2. **原创动作资产流水线**：使用自有提示词、关键姿势、自有精灵表或独立授权的骨骼人体生成 Animated WebP/GIF，不把第三方动作媒体作为生成或训练输入。

两条流水线都要固定来源版本和哈希。元数据记录保留仓库、commit 和许可；原创资产保留提示词、作者/生成器、源精灵、动作规格、输出哈希和训练权限。

## 确定性训练集

训练/验证/测试集合应按稳定记录 ID 的哈希分桶，而不是每次随机切分。这样来源仓库更新后，旧动作不会在不同集合之间漂移，也能检查新增、删除和重复。

门禁递归检查 JSON 键，禁止媒体字段进入语料。仅检查文件扩展名不够，因为媒体路径和 ID 可能藏在结构化字段中。训练 manifest 应明确写 `mediaIncluded: false` 和 `mediaTrainingAllowed: false`。

## 原创动图规格

动作动图不是只有最终 GIF。可审计资产至少包括：动作 ID、视角、阶段、关键姿势、帧率、时长、主力/协同肌、源资产所有权、是否使用第三方输入、训练权限和专业复核状态。

先生成统一人物和器械的多帧精灵表，再由确定性本地脚本裁切并输出 Animated WebP/GIF。产品动作演示与肌肉图分层展示：动图回答“怎么做”，肌肉图回答“练到哪里”，避免颜色覆盖动作细节。

## 批量生产边界

先对一个代表动作完成视觉与运动质量试点，再按复合动作族扩展。器械、握法和单双侧变化仅在动作轨迹等价时共用动画；会改变动作路径或安全要点的变体必须单独制作。

元数据全量可用不等于动图全量完成。状态必须分别报告：语料覆盖率、动作族动画覆盖率、变体覆盖率和专家复核率，禁止用“流水线已建立”冒充“所有动图已完成”。
