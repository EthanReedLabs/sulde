# 动作到主力与协同肌群的可审计可视化

## 问题

训练产品不能给所有动作展示同一张肌肉图。用户看到深蹲时，需要直接理解股四头肌和臀大肌是主要发力区域，腘绳肌、内收肌群和竖脊肌承担协同作用；看到划船时则应切换到背阔肌、中斜方肌和菱形肌等对应区域。

但“看起来合理”的动作肌肉图存在两个风险：动作与肌肉关系由设计稿临时编写，脱离生产动作库；为了画满全身图，把局部或深层肌肉错误投影到另一套人体母版。

## 可审计结构

动作肌群可视化应由三层组成：

1. **生产动作事实**：每个动作 ID 明确主力肌和协同肌，不从页面文案反推。
2. **动作模式映射**：只有肌肉角色完全一致的动作变体才能共用一个视觉模式。
3. **同底图蒙版组合**：前后视图只组合已经与对应人体母版对齐的肌肉选区。

动作模式不是新的运动科学真值。它只是把生产目录中已经确认的结构化关系转换成可视资产。新增动作时若没有显式映射，应阻断构建，而不是自动继承名称相似的模式。

设计阶段先出现、生产目录尚未支持的动作必须标记为 `catalog_pending`。它可以用于评审肌群图和器械流程，但不能计入生产动作覆盖率；只有动作 ID、教学、处方和运行时能力一起补齐后才能转为 production。

## 复合动作全量覆盖

复合动作不应逐个图片补洞，而应建立动作族。一个可落地的通用范围至少覆盖：蹲、弓步/分腿蹲、登阶、腿举、传统/相扑硬拉、髋铰链、臀推、水平/上斜/垂直推、双杠臂屈伸、水平/垂直拉、正反握引体、直立提拉、壶铃摆动、翻举、抓举、借力推举、深蹲推举、负重行走、俯撑划船、土耳其起立、波比跳、雪橇推和前/侧向核心稳定。

器械、握法、站距和单双侧变化只在肌肉角色等价时共用图。传统硬拉与相扑硬拉、平板与上斜卧推、正握下拉与反握引体等会改变主力角色的变体必须拆分。组合动作应由多个已复核动作族合成；无法可靠分解的新名称进入待复核队列，不显示通用肌肉图。

## 角色表达

主力肌和协同肌必须同时用颜色、图例和文本区分，不能只靠颜色。主力肌表示动作主要负荷目标，协同肌表示参与完成或稳定动作的相关肌群。若生产数据没有“稳定肌”这一独立层级，设计层不得自行增加，以免形成不可追溯的医学或训练结论。

同一模式可以服务多个器械变体，但前提是生产目录给出的角色集合完全相同。例如杠铃后蹲、高脚杯深蹲和自重深蹲可以共享基础深蹲图；一旦某变体的肌肉角色发生变化，就必须拆分模式。

## 深层结构处理

深层或局部结构没有可靠全身注册时，应继续出现在文字角色列表中，并提供局部图入口，而不是强行绘制到全身图。这样既保留训练解释，也不会用错误位置制造虚假精确度。

## 生成与检查

生成流程应保持确定性：从同一人体母版的单肌肉资产提取选区，按角色着色并组合前后视图，输出固定尺寸图片、哈希和可见/局部结构清单。

自动门禁至少验证：

- 生产动作 ID 全覆盖且无重复；
- 主力与协同角色和生产目录逐项一致；
- 所有肌肉存在于图谱清单；
- 两类角色没有重叠；
- 图片尺寸、哈希和生成方法未漂移；
- 未完成专家复核时发布资格保持 false；
- 禁止跨人体母版投影。
- 复合动作族数量、变体发现信息、动作映射和生成资产必须一一完整；
- 设计已覆盖但生产能力未补齐的动作必须保持 `catalog_pending`。

资源生成和前端打包必须串行。生成器会重写 PNG 与清单；若与打包器并行，打包器可能读取到正在替换的文件，即使两个进程最后都返回成功，也不能视为稳定证据。

外部动作数据集可以用于交叉核对 `target`、协同肌和动作变体结构，但图片、GIF 与数据文本必须分开审查许可。代码或元数据采用开放许可证，不代表仓库中的第三方媒体可以直接商用。

## 产品体验

动作教学应把动作演示、对应肌群和语音关键点组合在一起。肌肉图回答“练到哪里”，视频回答“怎么做”，语音在动作过程中强调节奏、关节位置和安全边界。三者互补，单独一张肌肉图不能承担完整教学。

当页面的核心任务是查看动作练到哪里时，默认入口应直接进入“按动作/复合动作”，单肌肉解剖浏览作为次级切换。资产存在但藏在非默认分段控件后面，用户体验上等同于功能不可见。

## 可迁移结论

动作肌肉图不是装饰资产，而是生产动作知识的视觉投影。可靠方案的核心不是批量生成更多图片，而是保持动作事实、视觉角色、底图坐标和发布状态四者可追溯。无法注册的深层结构保持局部展示，无法确认的动作映射保持未知。
