# 自主训练也必须复用持久化执行处方

## 适用场景

用户从动作库临时发起训练，并自行选择组数、次数和组间休息。即使这不是教练计划内训练，也不能只把参数放在页面状态或导航 URL 中。

## 核心原则

自主训练应生成 session 绑定的持久化处方，并复用计划训练的执行队列、组间休息、下一组、恢复和总结链路。临时处方不得被激活，不能覆盖用户当前正式训练计划。

## 推荐契约

- 使用显式模式区分计划训练与自主训练，例如 `sets = 0` 表示按正式计划解析，`sets > 0` 表示创建自主处方。
- 临时处方至少持久化 exercise、sets、reps、rest，以及稳定的 set index 和 prescription id。
- workout session 直接引用临时 workout prescription。
- 完成一组时，从 session 绑定的 workout queue 获取目标，不能再次从“当前激活计划”反查。
- 允许动作替换时，应匹配替换后的 canonical exercise，或匹配经过审核的同类运行时动作类型。
- repository 只对明确标记为 self-directed 的 session 放宽“必须引用 active plan”的约束。

## 常见失败

只在 UI 和路由中传递组数，看起来可以进入首组，但完成后没有持久化队列，导致无法进入下一组、恢复训练或使用自定义休息。另一个隐蔽错误是临时处方创建成功后，完成组仍查询 active plan，最终静默退回默认休息时间。

## 验证标准

测试至少覆盖三组训练的首组完成、指定休息、下一组 index、进程恢复，以及临时处方未成为 active plan。跨平台项目还应同时通过共享逻辑、Android 和 iOS 编译门禁。
