# 编码原则集(Kotlin / Swift 习语优先级)

> 微观层:每行代码用什么语法、API、数据结构。
> 宏观结构层见 `设计模式实现.md`(GoF 23 + 现代模式两端实现)。
> 跨平台共享编码基线。

---

## 三大目标(优先级,有冲突时高优先级胜)

```
1. 最大复用    DRY,共享代码到公共 UI / 公共 Spec / 公共工具模块;改一处生效多处
2. 最少代码    用语言特性消除 boilerplate;一行能写的不写三行
3. 最佳性能    用平台原生能力(value type / inline / lazy / Flow)
```

冲突示例:
- 性能 vs 复用:Kotlin `inline fun` 内联性能好但每个调用点复制代码 → 体积换性能,小函数用 inline,大函数不用
- 复用 vs 最少代码:抽 `object` 单例复用度高但增加 boilerplate → 单例只 2-3 处用就别抽

## Kotlin / Android 习语优先级表

| # | 维度 | 首选(默认) | 次选 | 禁用 / 慎用 |
|---|---|---|---|---|
| 1 | 数据类 | `data class`(自动 equals/hashCode/toString/copy) | 普通 class + 手写 equals | Java POJO + lombok |
| 2 | 类型分支 | `sealed class` + `when` 穷尽 | `enum class`(无 associated value 时) | if-else 字符串判断 |
| 3 | 复用业务逻辑 | extension fn(就近 + 复用) | utility `object` | static class / 全局函数 |
| 4 | 异步 | `Flow` + 协程 | `LiveData`(legacy 兼容时) | RxJava / `Callback` 接口 |
| 5 | 大集合处理 | `Sequence`(惰性,大集合)| `List.map.filter`(中小集合) | for 循环手写中间 list |
| 6 | 单例 | DI 容器 `single { }` module | `object`(纯静态工具) | 手写 DCL / `getInstance()` |
| 7 | 序列化 | `kotlinx.serialization` | Moshi | Gson + 手写 TypeAdapter |
| 8 | 懒加载 | `by lazy { }` | 手写 backing prop + null check | volatile + DCL |
| 9 | Parcelable | `@Parcelize` | 手写 Parcelable | `Serializable`(性能差) |
| 10 | 空安全 | `?.` / `?:` / `let { }` | `if (x != null)` | `!!` force unwrap |
| 11 | 集合声明 | `listOf` / `mapOf`(不可变) | `mutableListOf`(需要时) | `ArrayList()` / `HashMap()` |
| 12 | 字符串拼接 | 模板 `"hello $name"` | `String.format` | `"hello " + name + "!"` |
| 13 | DI | DI 容器 module DSL | Property delegate | `Object` 全局单例 |
| 14 | 协程作用域 | `viewModelScope` / `lifecycleScope` | 自定义 `CoroutineScope` | `GlobalScope` |
| 15 | UI | **见下方 §Android UI 场景决策矩阵** | — | `findViewById` / kotlin-android-extensions / 无理由混合栈 |

### Kotlin 反例集(已踩坑,grep lint 防再来)

- ❌ `fun getXxx() { return xxx }` Java 风格 → ✅ 直接 `val xxx`
- ❌ SharedPreferences 字符串 key 散落各处 → ✅ 封 Repository
- ❌ callback 嵌套 ≥ 3 层(callback hell) → ✅ Flow + 协程
- ❌ `when` 不穷尽(漏 case 编译器不警告) → ✅ `sealed class` + when 强制穷尽
- ❌ `object` 单例 + 内部 mutable state(全局污染 + 测试不友好) → ✅ DI 容器
- ❌ 非 const top-level `val URL = "..."`(运行时初始化) → ✅ `const val URL = "..."`(编译期常量)

### Android UI 场景决策矩阵

agent 写 Android UI 时按场景选 Compose / XML + ViewBinding / 混合栈:

| # | 场景 | 首选 | 次选 | 关键技术原因 |
|---|---|---|---|---|
| 1 | 简单静态 UI(Splash / 错误页 / 设置项) | **Compose** | XML | 声明式更短,token 直绑,智能重组 |
| 2 | 列表(中小数据量,< 100 项) | **Compose `LazyColumn`** | RecyclerView | 免 Adapter / ViewHolder / DiffUtil boilerplate |
| 3 | 大列表 / 瀑布流 / 高频滚动 | **XML + RecyclerView**(StaggeredGridLayoutManager 等) | Compose `LazyVerticalStaggeredGrid` | RecyclerView 极致优化(对象池 / prefetch / nested-prefetch),1000+ 项滚动场景仍稍胜 |
| 4 | 复杂多层嵌套 UI(host + sub-page) | **Compose** | XML | 智能重组只重绘 sub-tree;XML measure/layout/draw 整树开销 |
| 5 | 视频播放 / Media3 PlayerView | **XML + ViewBinding 包 PlayerView** | Compose `AndroidView { PlayerView }` | 避免 AndroidView 包装层(SurfaceView 渲染同步开销) |
| 6 | WebView / 第三方 View 库 | **XML** | Compose AndroidView | 同 #5,避免包装损耗 |
| 7 | 高频手势 + 自定义绘制(波形裁剪类) | **Compose Canvas + Modifier.pointerInput** | 自定义 View(极致场景) | Compose draw scope + 状态驱动 redraw 控制粒度;高频手势 5 防同样适用 |
| 8 | State 驱动 UI(MVI / StateFlow) | **Compose + `collectAsState`** | XML + render(state) | 单向数据流天然契合;render() 手动 setText/setVisibility 是冗余 |
| 9 | 表单 / 输入 / 键盘 | **Compose `TextField` + `Modifier.imePadding`** | XML EditText | Compose 键盘适配是 modifier 链,与自适应基类兼容 ComposeView |
| 10 | 中等动画(列表插入 / 卡片翻转 / 点赞) | **Compose Animation API** | ObjectAnimator | 声明式简洁,enter/exit 内置 |
| 11 | 极致优化动画(60fps 复杂关键帧) | **ObjectAnimator + 预 alloc** | Compose Animation | XML Animator 极致优化生态成熟 |
| 12 | 设计稿对齐(token / fill / stroke / cr 直绑) | **Compose** | XML | 声明式 1:1 映射设计稿,token 改立等可见 |
| 13 | Dialog / BottomSheet | **Compose `Dialog` / `ModalBottomSheet`** | DialogFragment / BottomSheetDialogFragment | 简洁,无 Fragment 生命周期管理 |

#### 三大类决策原则(快速判断)

```
A. 默认 Compose(~80% 场景)
   - 简单/中等 UI、State 驱动、设计稿对齐、Dialog、表单、中等列表、中等动画

B. XML + ViewBinding(~15% 场景)
   - 视频播放(PlayerView)、WebView、第三方 View 库
   - 大列表 / 瀑布流(RecyclerView 极致优化)
   - 极致优化动画(ObjectAnimator)

C. 混合栈(~5% 场景,谨慎)
   - Compose 内嵌 AndroidView { PlayerView }(视频卡片在 Compose 列表)
   - 接受 < 5% 包装损耗
```

#### 与 MVI 架构契合度

| 架构现状 | 与 Compose 契合度 |
|---|---|
| MVI(StateFlow + reduceUser/Result) | ✅ **天然契合** — `state.collectAsState()` 直接渲染,免 render(state) 手动同步 |
| DI 容器 | ✅ Compose 通过 viewModel 注入接入 |
| 设计真值视觉对齐(token-based) | ✅ Compose Modifier + 颜色 token 直绑 |
| 键盘退散自适应基类 | ✅ ComposeView 嵌入自适应基类即可 |
| 高频手势 5 防 | ⚠️ Compose Modifier 体系也要遵守 |
| Media3 ExoPlayer | ⚠️ 用 AndroidView 包(< 5% 损耗) |

#### Compose 迁移前提 — 必读

若项目当前 0 Compose(基础设施未建),新功能直接写 `@Composable` 会编译失败。验证方法:

```bash
grep @Composable <feature 模块>/src/main → 0 命中 = 基础设施未建
```

**Action 序列**(协调端待派 task):

1. **Compose infra task**:dependencies(activity-compose / runtime / material3 / foundation)+ ComposeView host + MaterialTheme 接入颜色 / 字体 token
2. **Pilot 一个简单页 Compose 化**(如某选中态页 / Splash)验证 infra
3. **后续新 Feature 默认 Compose**,老页保持 XML 不强迫迁移

infra 落地前,Android 新功能仍用 XML + ViewBinding(过渡)。本表"首选"是迁移目标,**infra 完成后立即生效**,届时 agent 写新功能默认按本表 decision matrix 选 Compose。

## Swift / iOS 习语优先级表

| # | 维度 | 首选(默认) | 次选 | 禁用 / 慎用 |
|---|---|---|---|---|
| 1 | 数据类型 | `struct`(value type,栈分配,免引用计数) | `final class`(需引用语义时) | `class` 无理由继承 |
| 2 | 类型分支 | `enum` + associated values | protocol + concrete struct | if-let / guard let 串联 5+ 层 |
| 3 | 复用 UI 片段 | `@ViewBuilder` 函数 | View 子类型 | UIView subclass(纯展示场景) |
| 4 | 异步 | `async / await` | `AsyncSequence` | `completion: @escaping (Result) -> Void` callback |
| 5 | 协议返回类型 | `some Protocol` opaque(性能 > existential) | `any Protocol` existential | 泛型函数过度展开 |
| 6 | 序列化 | `Codable`(自动) | 手写 `init(from decoder:)`(特殊需求) | 手写 JSONSerialization |
| 7 | State 管理 | TCA Reducer + Effect(value type 安全) | `@Observable`(iOS 17+ 简单 case) | `@ObservedObject` + `ObservableObject`(legacy) |
| 8 | DI | TCA `@Dependency` | Property wrapper(自定义) | Singleton |
| 9 | Optional 处理 | `if let` / `guard let` / `?.` / `?? default` | `try?` | force unwrap `!`(除非真不可能 nil) |
| 10 | 集合操作 | `Array.map` / `filter` / `reduce` | `for in` | C 风格 index 循环 |
| 11 | 字符串拼接 | 字符串插值 `"hello \(name)"` | `String.init(format:)` | `"hello " + name + "!"` |
| 12 | UI | SwiftUI(声明式 + 表达力) | UIKit + Combine | UIKit + delegate(过度 OO) |
| 13 | 资源 | SwiftGen / String catalog | `NSLocalizedString` 直调 | 硬编码 "Hello" |
| 14 | Concurrency | `actor` + `async` | `DispatchQueue` + `barrier` | `NSLock` / `pthread_mutex` |
| 15 | 错误处理 | `Result<T, Error>` + `throws` | `do/catch` | 返回 `nil` 表错误(吞错) |

### Swift 反例集(已踩坑,grep lint 防再来)

- ❌ `class XxxModel: NSObject` 无理由继承 → ✅ `struct XxxModel`
- ❌ `let x = obj.value!` force unwrap → ✅ `guard let x = obj.value else { return }`
- ❌ Combine 链超过 5 层(链式可读差)→ ✅ 拆 reducer / Effect
- ❌ `@ObservedObject` + `ObservableObject`(iOS 17- 语法,iOS 17+ 已被 `@Observable` 替代)→ ✅ `@Observable`
- ❌ `class Singleton { static let shared = Singleton() }` 全局单例 → ✅ TCA `@Dependency`
- ❌ `try!` 强制 try → ✅ `try?` 或 `do/catch`
- ❌ `NotificationCenter.default.post(name: .xxxChanged)` 字符串 key 散落 → ✅ Combine `@Published` 或 `@Observable`

## Agent 写代码前自检 5 问

```
1. 这块逻辑是否已存在?复用 > 新写
   (grep 公共 UI / 公共 Spec 模块看现有抽象)

2. 我用的语法是不是该语言"首选习语"?(查上表)
   Kotlin 写 `class XxxData(val name: String)` → 改 `data class`
   Swift 写 `class XxxModel: NSObject` → 改 `struct`

3. 数据结构是否最优?
   Kotlin 类型分支 → sealed class
   Swift 类型分支 → enum + associated values

4. 异步/性能关键路径用最佳习语?
   Kotlin → Flow + 协程
   Swift → async/await

5. 命中"禁用 / 慎用"清单了吗?
   force unwrap `!` / GlobalScope / NSObject 继承 等
```

任一问 ❌ → 改了再 commit。
