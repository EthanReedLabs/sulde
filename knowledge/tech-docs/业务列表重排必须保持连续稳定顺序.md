# 业务列表重排必须保持连续稳定顺序

计划、步骤、处方等业务列表的顺序不是纯 UI 状态。重排必须在领域草稿中完成，并随版本保存和审计。

实现约束：只允许在同一 owner 内移动；按当前顺序定位元素并交换相邻位置；每次变更后将索引压实为 `0..N-1`；首项和末项的越界操作在 UI 禁用，领域层仍做无操作保护；持久化以列表顺序为准，不信任可能稀疏或重复的旧索引。

测试至少覆盖正向移动、反向恢复、边界无变化和连续索引。涉及版本化对象时，重排必须进入与其他手动编辑相同的用户审计链路。
