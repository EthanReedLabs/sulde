# 0185 — 清单显式声明与约定式自动发现双重注册

- **平台**:CLI agent 插件生态通用(宿主 = 加载插件的应用)

## ❌ 错误

插件清单里显式声明某能力入口(如 `"hooks": "./hooks/hooks.json"`),而该文件
同时位于宿主的**约定式自动发现标准路径**上——两条加载路径解析到同一文件。
旧版宿主只认显式声明,一切正常;插件随宿主生态演进从不回头清理清单。

## 为什么

宿主升级引入自动发现后,同一能力被注册两次。新版宿主为防止 hook/命令被执行
两遍,把重复注册判为配置错误并**整体拒载插件**——症状出现在"新机器首装"或
"宿主升级后",而开发机(旧版宿主/本地目录安装)毫无征兆,极易被误诊为
新机器环境问题。本质是**清单写法滞后于宿主机制演进**的兼容性债:显式声明
在自动发现落地那天就成了冗余,但它不报错,直到宿主开始严格校验。

## ✅ 正确

- **一个能力只保留一条注册路径**:宿主支持约定式自动发现的,把文件放标准
  路径并**删除清单里的显式字段**——约定优于配置,且新旧版本通常都认标准路径
- 插件发布前用**最新版宿主**做一次干净安装冒烟(开发机的本地目录安装
  验证不了分发路径)
- 宿主大版本升级公告里出现"自动发现/约定式加载"字样时,主动审计清单里
  还剩哪些显式声明——它们全是潜在的双重注册
- 同族教训:插件热更新的悬空路径(ap-0181)——插件生态里"装上时正常"
  不等于"生命周期内一直正常",加载机制本身也在演进
