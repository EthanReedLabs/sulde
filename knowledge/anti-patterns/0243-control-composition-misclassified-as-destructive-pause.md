# 0243 — 控制命令组合违规被误升级为破坏性暂停

- **平台**：协调端方法论（Agent Hook / 意图监督）
- **复发次数**：1

## 问题原型

意图监督器允许可信控制入口执行单个、精确、可审计的生命周期动作，同时禁止把这些动作与
其他 shell 片段组合。一次工具调用把两个生命周期收口动作和一个只读状态检查串在一起。
期望是整条命令在执行前被拒绝、控制状态保持不变；实际却被归类为破坏性动作，并把当前
任务 lane 写成安全暂停。随后连普通收口都只能走额外恢复决策，形成“守卫因成功阻止命令而
锁住自己”的控制面自锁。

## ❌ 错误

- 用同一个 `destructive` 枚举同时表达“命令包含不允许的组合语法”和“命令会造成破坏性
  副作用”。
- 复合控制命令未执行，却沿用真实破坏性动作的通用分支写入 `safety pause`。
- 只把组合命令从 allowlist 删除，不验证拒绝后的契约、lane、open event 和效果债务是否保持
  不变。
- 为避免误暂停而直接把复合控制命令当作普通 read 放行，使后续片段获得执行机会。

## 为什么错

“这条命令是否允许执行”与“如果执行会产生什么副作用”是两个正交维度。可信控制命令的
不可组合约束属于**调用形状违规**：PreTool 在进程启动前拒绝整条命令即可完成安全目标。
`destructive` 则是**副作用语义**，用于删除、强制覆盖、历史改写等真实高风险动作。把前者
编码成后者，会让通用决策器误以为发生了必须冻结任务的安全事件。

已验证的一手证据包括：

1. 两个可信生命周期收口命令与一个只读检查组成的调用，在进程启动前被监督器拒绝；
2. 拒绝理由却是“破坏性动作”，同一 provider/session lane 随即变为安全暂停；
3. 当时没有开放工具事件、待验证效果或外部效果干预，证明暂停不是由未决副作用产生；
4. 必须经过一次独立的原生恢复决策才能重新绑定该 lane；
5. 代码路径可确定性重放：可信控制入口先被识别，组合标记随后直接映射为
   `destructive`，最终进入通用安全暂停分支。

已排除“只是缺少完成回调”这一方向：命令在 PreTool 阶段即被拒绝，且效果账本没有新增
unknown attempt 或 pending verification。也不是可信入口失效；同一入口的单条精确命令能够
正常进入控制面审计。

## 适用边界

- 适用于已识别为可信控制入口，但因 `;`、管道、`&&`、重定向、替换或其他组合语法而必须
  整体拒绝的 PreTool 调用。
- 独立发起的真实删除、强推、清库、覆盖安全状态等破坏性动作不适用本例外；这些动作即使
  尚未执行，也应保持硬拒绝，并可按契约触发安全暂停。若危险片段被附加在可信控制调用后，
  整个 shell 仍先按 `invalid-composition` 硬拒绝且任何片段都不得启动；这不等于给予危险
  片段 read 权限。
- 不适用于来源不可信、摘要不匹配或无法证明是控制入口的同名脚本；证据不足时继续按
  unknown 或既有 bootstrap 安全边界处理，不能套用本条目的可信控制例外。
- 若组合命令已经绕过 PreTool 并产生了可观察副作用，应按实际效果和独立证据结算，不能因
  “原本应被拒绝”而抹去效果债务。

## 判定样本

### 路由正例

- **输入**：可信生命周期控制命令与只读状态检查被串成一条调用；监督器阻止执行后仍把当前
  任务标成 safety paused。
- **预期**：apply
- **原因**：同时满足“可信控制入口”“仅调用形状违规”“命令未执行”“拒绝却改写任务状态”
  四个必要条件。
- **来源**：observed

### 路由反例

- **输入**：普通 shell 调用明确请求递归删除受控目录，PreTool 将其归类为 destructive 并暂停。
- **预期**：skip
- **原因**：这里存在真实破坏性语义，不是可信控制入口的组合形状误判。
- **来源**：constructed

### 执行合格例

- **做法或输出**：组合后的可信控制调用进入独立的 `invalid-composition` 决策路由；整条命令
  `deny`、`pause=false`，当前 lane 仍 bound，open event、pending verification 和 effect
  attempt 均不增加；单条控制、无效 native 决策、伪造 Hook 与真实 destructive 的原门禁
  分别通过正反回归。
- **预期**：pass
- **原因**：调用被阻止且没有扩大执行权限，同时不再用任务暂停惩罚一个已经成功拦截的形状
  违规。
- **来源**：constructed

### 执行失败例

- **做法或输出**：把组合命令的 effect 从 destructive 改成 read，却没有独立 deny 路由；或
  返回 deny 但仍沿用 safety pause 写回。
- **预期**：fail
- **原因**：前者会执行本应禁止的后续片段，后者仍保留自锁；都没有分离“可执行性”与
  “副作用语义”。
- **来源**：observed

## ✅ 正确

1. shell 词法层只负责识别组合边界，不直接决定任务是否暂停。
2. 对摘要匹配的可信控制入口，若发现任何禁止的组合语法，生成明确的
   `invalid-composition` 控制路由；该事件仍是控制面事件，绝不能回落成普通 shell read。
3. 控制面决策对该路由固定返回 `deny`、`pause=false`，并保证没有 open event、效果 attempt
   或 pending verification；整个 shell 进程不得启动。
4. 真实 destructive、来源不可信、伪造宿主回调、无效 native 决策分别保留现有 fail-closed
   路径，不共享非暂停例外。
5. 回归使用与真实宿主相同的多段命令形状，并同时断言工具决策和持久状态；只测返回文案不算
   完成。

## 消费与防复发

- PreTool Hook、命令规范化器、控制面路由器与 lane pause 投影共同消费本规则。
- 纯词法模块负责引号、转义、管道、顺序分隔、条件执行、重定向和替换语法的机械回归；它
  不读取契约、不写文件、不决定权限。
- 集成测试必须断言复合可信控制命令 `deny` 且 `pause=false`，并回读契约确认 status/lane、
  open event、pending verification 不变。
- 安全反例必须证明真实 destructive 仍触发原有硬门禁，伪造 Hook 和无效 native 决策仍被
  非授权控制路由拒绝；不得以修复自锁为由扩大普通 shell allowlist。
