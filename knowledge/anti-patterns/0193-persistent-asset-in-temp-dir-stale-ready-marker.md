# NNNN — 持久资产存放系统临时目录且 ready 标记与本体分离

- **平台**:none

## ❌ 错误

把需要长期存在的资产(模型文件、数据集、索引等)缓存在系统临时目录(如 /tmp、系统级临时缓存目录),同时把"已就绪"标记(标志文件、配置项、数据库字段)写在资产本体之外的另一处。操作系统按自身策略清扫临时目录后,资产蒸发而标记仍为真;依赖方读到标记为真就跳过下载/构建,直接使用不存在的资产,静默失败,任务持续积压(实证场景中积压达数百条才被发现)。

## 为什么

- 系统临时目录的生命周期由操作系统与清理策略决定(macOS 周期性清扫、Linux tmpwatch/systemd-tmpfiles、移动端存储压力回收),对应用没有"下次还在"的契约;把持久资产放在那里等于把可用性交给不受控的外部策略。
- ready 标记与资产本体是两份状态,分离存放后二者的生死不再原子。标记只证明"曾经就绪",不证明"现在可用";资产被删时没有任何机制同步翻转标记。
- 失败模式是静默的:依赖方信任标记就不再验真,错误不抛出,只表现为下游产出停止或队列悄悄变长,发现延迟极长,且首个报警往往来自业务侧而非资产层。

## ✅ 正确

- 持久资产放应用自有的持久目录(如 Application Support、专属数据目录),不放系统临时目录;临时目录只放可随时重建、丢失无感的文件。
- ready 判定以资产本体为准:每次使用前验证文件存在且非空(必要时校验大小/哈希)。独立标记只能当加速缓存用,验真失败即视为未就绪,自动触发重建或重下载,而不是报错退出。
- 若确需独立标记,让它与资产同目录同生共死(标记文件放在资产旁,清扫时一起消失),或在标记中记录资产路径与摘要,读取时联合校验。
- 为"标记为真但资产缺失"的分支加显式日志/告警,把静默积压变成可观测事件。
