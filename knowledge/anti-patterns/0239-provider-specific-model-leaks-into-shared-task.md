# 0239 — 提供方专属模型泄漏进共享任务契约

- **平台**：多 Agent 宿主 / 协调端派单
- **复发次数**：2

## 问题原型

共享任务只表达能力需求，但协调端在生成给目标 Agent 的启动指令时，输出了另一宿主的模型名、
推理术语或控制命令。期望是目标宿主收到本端可执行的原生指令，实际是在任务执行前就发生
提供方漂移。

## ❌ 错误

任务元数据直接记录某个宿主的商业型号或 thinking 语法，协调端再机械拼接对应 slash command。
当目标 session 换成另一个宿主时，协调端仍输出上一宿主的型号、mode、assign 等命令。

这种错误看似只是提示词没更新，实际上同时污染了四层：任务 schema、派单生成器、接单消费者和
新项目模板。只改其中一个示例，其他消费者会继续把旧协议带回来。

## 为什么错

- 任务复杂度是稳定的跨宿主事实，模型目录和交互命令是提供方瞬时能力；把二者放进同一字段，
  等于把适配层细节提升成领域真值。
- “机器装了哪个 CLI”不能证明目标 session 正运行在哪个宿主；双宿主共存时按安装情况猜测会错。
- 当前模型可能已经高于任务最低线；无条件切到写死型号既丢上下文，也可能降级能力。
- 文档示例、schema 和消费者没有机械不变量时，历史型号会在复制模板时复发。
- 只实现正确的适配函数仍不够：若“给 Dev 发送”的自然语言生产者可以绕过函数，或 Codex
  发布件没有暴露派单 skill、安装器没有同步全局规则，模型仍会从高显著性的 Claude 示例抄写。

已验证证据包括：目标为 Codex 的派单曾输出 Claude 控制词；将任务能力档与宿主渲染分层后，
双宿主输出、安装缓存 smoke 和禁止词断言均能稳定区分两条路径。

## 适用边界

- 适用于共享 task、协调端派单、继续任务和返修指令需要跨 Claude Code/Codex 渲染的场景。
- 不适用于用户明确要求某一宿主原生命令、且输出不会进入共享契约的单宿主操作说明。
- 目标 session 的宿主或当前状态无法确认时必须停止，不得根据本机安装情况猜测。

## 判定样本

### 路由正例

- **输入**：当前在 Codex 中，协调端却给出 `/mode opus` 或 `/assign`。
- **预期**：apply
- **原因**：目标宿主与输出控制协议直接冲突，命中提供方泄漏的核心条件。
- **来源**：observed

### 路由反例

- **输入**：用户在 Claude Code 中明确要求解释 `/model opus` 的含义，且不生成共享任务。
- **预期**：skip
- **原因**：这是单宿主知识说明，没有跨宿主派单或共享契约写入。
- **来源**：constructed

### 执行合格例

- **做法或输出**：task 只保存 `capability_tier`；派单时显式选择目标 provider，并由稳定 launcher
  输出宿主原生前缀；双向测试确认互不含对方控制词。
- **预期**：pass
- **原因**：领域真值、适配层和发布消费者均形成闭环，且有机械回归证据。
- **来源**：observed

### 执行失败例

- **做法或输出**：只改一处提示词示例，但共享 schema、安装产物或其他“给 Dev 发送”生产者
  仍可手写提供方命令。
- **预期**：fail
- **原因**：绕过路径仍存在，历史示例会再次污染目标宿主输出。
- **来源**：observed

## ✅ 正确

1. task 只记录宿主无关最低能力档，例如 `light / balanced / deep`。
2. 派单瞬间读取**目标 session**的 provider、当前模型和可观察推理档，再由提供方适配层渲染。
3. 当前模型已满足最低档时保留；不足或未知时才调用目标宿主自己的模型/推理选择器。
4. 宿主不明确就停止并要求显式选择；不得因为另一 CLI 存在而静默借用。
5. 旧任务的提供方字段只在读取边界做兼容映射，取冲突字段中的更高档并报警；新写路径禁止旧字段。
6. 回归测试同时覆盖生产者、消费者、schema、模板和两条宿主输出，明确断言 A 宿主路径不含 B 宿主命令。
7. 把派单收敛成已安装宿主可发现的 skill + 稳定 launcher；发布验收必须从安装缓存真实运行
   Codex 派单，并验证全局规则已接线，不能只测源码中的纯函数。

## 消费与防复发

- 协调端派单 Skill 和任务模板消费宿主无关能力档；稳定 launcher 负责最终渲染。
- schema、安装 smoke 与双宿主禁止词测试做机械检查；目标 session 身份不明确时由人确认。
- review 时同时检查生产者、消费者和发布缓存，不能只审源码中的映射函数。

## lint 状态

- ✅ 新 task schema 可静态拒绝提供方特定 `model` / `thinking_mode` 字段。
- ✅ Codex 派单输出可断言不含 Claude 型号、mode 或 assign 命令，反向亦然。
- ✅ 双宿主共存且目标宿主未知的 fixture 必须 fail closed。
- ✅ Codex 安装 smoke 必须得到 Codex 型号与 reasoning，且机械拒绝 Claude 控制词。
- ⚠️ “当前模型属于哪一能力档”仍需宿主目录或项目策略维护，不能仅从任意模型字符串猜测。
