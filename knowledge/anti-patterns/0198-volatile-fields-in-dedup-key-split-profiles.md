# NNNN — 去重键混入易变字段导致同一主体分裂为多个 profile

- **平台**:跨端

## ❌ 错误

直接拿原始描述串做去重/唯一性键。典型如用 GPU renderer 全串做设备画像键:串里混着驱动版本号、构建日期等易变字段,驱动升级或日期变化后同一硬件生成不同键,被系统误判为新 profile。同类还有把完整 UA 串、带 build 号的版本串、带时间戳的路径当身份键。

## 为什么错

- 去重键的语义契约是"标识稳定身份",原始描述串的契约是"描述当前状态",两者的时间稳定性不同,不能直接混用。
- 易变字段(驱动/固件版本、日期、build 号、随机后缀)随环境漂移而变,不随身份变化;混入键中会让同一主体跨时间产生多个身份。
- 后果在统计与路由层放大:画像数量虚高、按画像键下发的配置命中率骤降、"新设备"监控误报,而根因藏在键构造处,排查易偏移。
- 与用可塌缩字段合成 ID(不同主体被合并,见 ap-0170)方向相反:一个是键过松导致塌缩,一个是键过紧导致分裂,同属身份键设计缺陷系列。

## ✅ 正确

1. 从原始串中提取稳定成分构造规范化键(如 SoC family / GPU family / 系统大版本),显式剥离驱动版本、日期、build 号等易变字段。
2. 规范化规则集中一处实现并配测试;发现新的易变字段模式时补规则,不在各消费端各自解析。
3. 需要保留易变信息时,作为 profile 的属性字段存储,不参与键。
4. 上线前用历史数据验证键的稳定性:同一物理设备跨时间的采样必须归并到同一键;归并率异常即键含易变成分。
