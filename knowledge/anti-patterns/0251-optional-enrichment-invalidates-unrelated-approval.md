# 0251 — 可选记忆增强被错误计入无关业务审批依赖

- **平台**：跨端

## 问题原型

用户审阅业务提案期间，可选记忆登记改变全局物质序列，导致原本不依赖图谱结果的
报告或本地任务反复要求审批。用户期待保留独立业务进度，而不是通过清除债务换取继续。

## ❌ 错误

用全局序列的任何变化失效所有提案；或仅增加一个新记忆计数器，忽略仍只写旧总序列
的生产者；或只凭 memory 标签过滤实际外部写入。

## 为什么错

审批的新鲜度范围与任务的真实依赖范围不一致。隔离回归及真实 CLI 续接组合验证
证明：显式无依赖任务可排除已证明的限定记忆增量，相关变化与旧计数者仍会失效审批。
CLI 中的人工决定使用隔离夹具，不是生产真人审批证据。此机制不是债务结算，
也不授权重试，更不能用于忽略未知效果。

## 适用边界

必须先有明确确认的无记忆依赖声明；实现验证范围仅包含 read/local_write，且没有
续行 grant 的合同。被过滤记录必须有固定 schema、请求摘要、目标能力及当前宿主/
会话身份，并能匹配权威 attempt。图谱本身是任务目标、身份不明、外部写入、破坏性
动作、控制面写入或带 grant 的维护流程均不适用。

## 判定样本

### 路由正例

- **输入**：已确认不依赖记忆的本地报告任务，在提案展示后因可选图谱登记改变总序列而再次失效。
- **预期**：apply
- **原因**：任务结果独立，冲突来自过宽的新鲜度投影，不是实际业务依赖变化。
- **来源**：constructed

### 路由反例

- **输入**：正在修复记忆图谱自身的错误实体和关系，最终结果取决于这些记忆记录。审批新鲜度必须反映图谱状态，不能把关联变化当成旁路可选增强而扣除。
- **预期**：skip
- **原因**：图谱维修的任务对象就是记忆，属于有依赖场景；保留对应记录变化造成的审批失效，禁止套用可选记忆的无依赖投影。
- **来源**：constructed

### 执行合格例

- **做法或输出**：真实 CLI 续接卡不因已证明独立的记忆登记失效；回归中相关变化及旧总序列写者仍使卡片失效，债务原样保留。
- **预期**：pass
- **原因**：只调整无关依赖的投影，没有清债、复制权限或放过实际关联变化。
- **来源**：observed

### 执行失败例

- **做法或输出**：将标有 memory 标签、但权威账本实际是 external_write 的事件直接扣除，或把全部 local_write 都视为无关。
- **预期**：fail
- **原因**：派生标签覆盖了权威事实，审批可能忽略真实风险。
- **来源**：constructed

## ✅ 正确

先验证权威 attempt，再判断事件是否属于已批准的独立记忆范围。用总量减去已证明
记忆增量构造依赖投影，保留旧写者未知增量的失效作用。第一次声明无依赖需要明确
审查；缺少声明或证明时保持保守判定。既有债务仍由原独立 verifier 结算。

## 消费与防复发

消费者是 proposal/continuation 审查与新鲜度投影。回归应覆盖可选和必需记忆、旧写者、
伪标签、身份不符、带 grant 与外部效果；组合验收必须包含提案展示后源会话发生
记忆变化的真实 CLI 链，不能只证明一个过滤函数返回正确。
