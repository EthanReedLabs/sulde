# NNNN — 真机 UI 自动化复用旧 dump 的控件坐标

- **平台**:通用(任何带控件树 dump + 坐标点击的真机自动化)

## ❌ 错误

开场 dump 一次 UI 树,把各控件 bounds 抄进脚本,后续整条流程都用这批坐标点:

```bash
<dump 控件树> > /tmp/ui.xml
# 从 ui.xml 抄出:输入框 (540,1200)、提交按钮 (540,1850)
<tap> 540 1200          # 点输入框 → 键盘弹起,页面被上推
<input text> "..."
<tap> 540 1850          # ❌ 仍用开场坐标 → 落在键盘上/别的控件上
<screenshot>            # 截到的根本不是提交后的页面
```

## 为什么

- **bounds 是快照,不是绑定**。dump 出的 `[x1,y1][x2,y2]` 是那一瞬间的绝对像素值,控件后续移动它不会跟着变。
- **键盘是系统窗口,弹起必然改变可用视口**:页面被上推、容器被压缩、滚动位置被自动调整——底部按钮位移几百像素是常态。同类改变视口的事件还有:弹窗/半屏 sheet、折叠吸顶、旋转、系统横幅/来电条、软导航栏显隐。
- **失败是静默的**,这才是真正的代价:点空白不报错,点错控件也不报错,脚本一路跑到底,产出一批看起来正常的截图和一个错误结论。比直接 crash 贵得多——错误结论会被当成真值继续用下去。

## ✅ 正确

**每次 tap 前重新 dump,按语义(text / id / desc)定位,取当轮 bounds 再点**:

```bash
tap_by_text() {           # 每次调用都重新取当前真值
  <dump 控件树> > /tmp/ui.xml
  bounds=$(<从 /tmp/ui.xml 按 text="$1" 提取 bounds>)
  [ -z "$bounds" ] && { echo "FAIL: '$1' 不在当前界面"; return 1; }   # ← 必须显式失败
  <tap> $(<bounds 算中心点> "$bounds")
}

tap_by_text "输入框"
<input text> "..."
tap_by_text "提交"        # ✅ 键盘态下重新定位,拿到位移后的真坐标
```

要点:

1. **坐标的生命周期 = 一次点击**。跨步骤复用坐标一律视为 bug,哪怕两步之间"看起来什么都没变"。
2. **定位不到必须显式 fail**,不能静默 tap 一个空坐标继续往下走——把静默偏航变成响亮失败。
3. **canvas / 自绘渲染栈 dump 不到节点**(控件树几乎为空)→ 退回按分辨率截图算坐标,则**每次键盘态或视口变化后重新截图确认**,同样不复用旧坐标。
4. 关键步骤后加一条廉价断言(目标控件是否已出现 / 页面标题是否已变),再进下一步。

**判定线**:任何可能改变视口的事件之后(键盘弹起或收起、弹窗开关、滚动、旋转、系统浮层),此前 dump 的所有 bounds 全部作废。
