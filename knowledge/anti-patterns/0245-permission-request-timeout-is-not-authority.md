# 0245 — 人工审批超时不是授权结果

- **平台**：跨宿主 Agent 控制面

## 问题原型

Agent 在执行受保护动作前展示原生人工审批请求。操作者可能暂时离开，没有在较短的配对窗口内
看到或处理请求。系统若只维护一个超时时间，常会走向两个相反但同样错误的结果：一类实现把
“长时间没有决定”解释为默认允许；另一类实现立即丢弃问题并反复要求人工重新确认，连机器已经
能够证明安全、确定和可回滚的任务也被卡住。

正确语义不是“等待多久后替人决定”，而是分开回答三个问题：是否该提醒或重新评估、这张问题
是否仍可接受决定、谁真正拥有决策权。确定性低风险任务应在展示人工问题**之前**经过受限的
Agent 策略门；一旦问题已经展示，沉默永远不是 Allow、Deny 或权限转移。

## ❌ 错误

- 用一个短 TTL 同时表示“宿主应该重评”“问题已经失效”和“可以自动继续”。
- 先展示人工审批，超时后再以“人不在”为理由把同一动作转给 Agent 自动批准。
- 把问题展示事件、普通聊天回复、计时器到期或轮询无结果当作决策 receipt。
- 晚到 Allow 不再校验当前方案、目标、会话和世界状态，直接消费旧问题执行动作。
- 机器已经能在严格门禁内决定的任务仍先弹人工框，超时后再重复弹框，制造人为卡点。

## 根因与证据

根因是把**活性、有效性和权限**压成同一个时间字段：

1. 活性时钟只说明“等待已久，应该观测、提醒或重新评估”，不说明人的意图。
2. 有效期说明“这张问题在多长时间内仍可接受决定”，到期只能让问题失效，不能创造权限。
3. 权限只能来自精确配对的人工决定，或在人工问题展示前通过独立、受限的 Agent 决策门。

问题展示和计时器都只是事件，不是授权证据。若超时后才改变决策所有者，还会与稍晚到达的
Deny/Allow 竞争：Agent 可能已经执行，人工界面却仍显示原问题，随后两个账本给出相反结论。
若简单把短配对窗口当成整个问题的寿命，又会让操作者离开几分钟后无法处理仍然有效的请求。

该根因已由双时钟审批账本、无声等待不产生 receipt、晚到决定重新校验、过期与替代状态分流、
并发人工决定优先等故障注入和 staged 宿主流程验证。安全提案在人工问题展示前走 Agent 策略门
的真实运行也已验证。真实宿主界面中故意等待超过短重评窗口再点击的长等待 canary 仍应作为
独立发布验收，不能由单元测试代替。

## 适用边界

- 适用于 Agent 宿主的 PermissionRequest、审批卡、一次性权限问题及其他异步人工决策面。
- Agent 自动决策只适用于范围精确、确定性、低风险、可回滚、无秘密外发、无持续费用且有
  机器验收的动作；必须在展示人工问题前完成资格判定。
- 破坏性操作、公开或新受众通信、秘密外发、持续费用、主观取舍和未知副作用继续等待人工；
  人离开并不会降低风险等级。
- 若策略显式选择“始终等待人工”，短重评时钟也不能改变决策所有者。
- 宿主若强制销毁过期 UI，可以创建一张绑定当前状态的新问题，但旧问题的沉默仍不构成权限。

## 判定样本

### 路由正例

- **输入**：一个精确、可回滚的本地任务被要求人工确认；操作者五分钟内没有看到弹框，系统随后
  报配对失败、反复询问，或准备把沉默当作同意。
- **预期**：apply
- **原因**：同时出现异步人工决策、短等待窗口和授权语义混用，命中本反模式的必要条件。
- **来源**：observed

### 路由反例

- **输入**：一个会删除外部数据的请求一直等待人工决定，超时后仍保持阻断且没有生成任何权限。
- **预期**：skip
- **原因**：高风险动作本就不能转给 Agent；保持等待或安全失效是正确行为，不属于无意义人工卡点。
- **来源**：constructed

### 执行合格例

- **做法或输出**：系统先对确定性任务运行严格 Agent 门禁，通过则直接记录 Agent 决策而不展示
  人工问题；确需人工时同时记录较短 `reassess_at` 和更长、有限的 `expires_at`。到达重评时间只
  标记未观察到结果；有效期内的晚到决定按问题、卡片、会话和当前状态做 CAS 重验；沉默期间
  receipt 数量保持不变。
- **预期**：pass
- **原因**：决策所有权、活性与有效期彼此独立，既不越权，也不让可机器证明的任务无谓等待。
- **来源**：observed

### 执行失败例

- **做法或输出**：只把审批 TTL 从五分钟延长到一天，但所有安全任务仍先弹人工框；或五分钟后
  自动执行，同时允许旧界面的 Deny/Allow 继续写入另一本账。
- **预期**：fail
- **原因**：前者只延长卡点，后者让时间替代权限并制造竞态，均未修复决策所有权模型。
- **来源**：constructed

## ✅ 正确

1. 为人工问题建显式状态机：`asked → reassess_due → decided/cancelled/expired`；重评到期不是终态。
2. 分离 `reassess_at` 与 `expires_at`。前者驱动观察和提醒，后者只限制晚到决定的接受窗口。
3. 在展示人工问题前运行受限 Agent 资格门；资格不满足或策略选择等待人工时，不得在超时后降级。
4. 只有精确配对的原生人工决定或独立 AgentPolicy receipt 能产生权限。普通文本、展示事件、计时器
   和“未观察到结果”均为非授权信号。
5. 晚到决定必须重新校验问题 ID、决策卡、提供方、会话、目标、方案 revision 和相关世界状态；
   已过期、已替代或已由权威效果账本结算时返回结构化结果，不重复执行。
6. 清理器只精确取消已替代方案或已结算效果对应的旧问题；并发到达的真实人工决定优先，不能被
   后台清理覆盖。
7. 监控分别披露开放问题数、到达重评点的问题数、已过期数和决策来源，不能把它们汇总成一个
   “审批是否 ready”的布尔值。

## 消费与防复发

- 审批账本、宿主原生决策桥、Agent 策略路由、readiness 投影和超时清理器共同消费本规则。
- 单元测试固定双时钟、沉默零权限、晚到 Allow/Deny、过期、替代、已结算和并发决定矩阵。
- staged 集成测试证明真实适配器协议能传递问题与决定；发布前再跑一次真实宿主长等待 canary，
  证明跨过重评时间后仍不自动授权，并且有效期内决定会重新校验后只执行一次。
- 代码审查应拒绝任何由 `timeout`、`no_response`、`prompt_shown` 或普通消息直接生成权限 receipt
  的路径，并检查“安全任务自动化”是否发生在人工问题展示之前。
