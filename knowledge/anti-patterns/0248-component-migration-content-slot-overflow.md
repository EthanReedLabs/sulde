# 0248 — 组件迁移后沿用旧内容槽布局

- **平台**：跨端 UI / 组件系统

## 问题原型

页面从旧卡片、弹窗或容器迁移到新组件。调用侧保留原有高度、padding 和垂直偏移，只替换组件名。
静态截图中每个元素都“看得见”，但新组件的标题区、图标、状态位或安全边距占用了不同内部空间，
在暗色主题、长文本或大字号下出现裁切、重叠和底部溢出。

## ❌ 错误

- 把组件迁移当成 API 名称替换，沿用旧外框高度与 magic offset。
- 只检查元素存在和截图大致相似，不检查内容槽边界。
- 只验默认主题、短文本和标准字号。
- 为单个截图加负 margin，而不修正组件内部约束。

## 为什么错

布局契约由组件内部 slot、基线、padding、状态区和父级约束共同决定。外部宽高相同不代表可用内容
矩形相同。已验证修复通过读取新组件真实内容槽，重算纵向约束，并用布局边界和双主题截图证明无
裁切。已排除“资源加载失败”——元素真实存在，错误来自几何边界。

悬浮导航迁移也出现同一根因：外部 barHeight 不等于 custom builder 的可用高度，
内层 padding 和状态区缩小了内容矩形。重新测量内槽并布局后，原双主题布局对照不再溢出。
具体槽高只对当时组件与版本成立，不能作为跨版本平台常量；只加大外框或缩小图标不能证明契约正确。

## 适用边界

- 适用于替换容器/弹窗/卡片/列表单元或跨 UI 栈迁移。
- 纯样式 token 变化且内部几何契约不变时无需重建布局。
- 动态字号、RTL、主题或状态变体存在时必须覆盖代表矩阵。
- 若无法读取组件内部边界，保持视觉验收 inconclusive，不以“可见”判通过。

## 判定样本

### 路由正例

- **输入**：迁移后默认截图正常，大字号或暗色状态下正文与操作区重叠。
- **预期**：apply
- **原因**：新组件内容槽与旧布局常量不一致。
- **来源**：observed

- **输入**：替换导航容器后图标和标签都存在，但继承旧高度的内容超出新组件内部槽。
- **预期**：apply
- **原因**：与卡片迁移相同，外框尺寸不代表内部可用空间。
- **来源**：observed

### 路由反例

- **输入**：只修改颜色 token，组件节点、slot、字体和约束均未变化。
- **预期**：skip
- **原因**：没有组件几何迁移。
- **来源**：constructed

### 执行合格例

- **做法或输出**：读取新组件标题/正文/操作 slot 的真实边界；重算约束；默认/暗色、短/长文本、
  标准/大字号截图无裁切，布局探针报告零 overlap/overflow。
- **预期**：pass
- **原因**：几何和视觉证据同时覆盖变体。
- **来源**：observed

### 执行失败例

- **做法或输出**：所有元素都能在一张默认截图中找到，因此宣称迁移完成。
- **预期**：fail
- **原因**：存在性不证明内容槽边界和变体安全。
- **来源**：observed

## ✅ 正确

1. 反查新组件内部 slot、padding、状态区和最小/最大尺寸。
2. 以内容矩形和基线重新建立父子约束，删除旧 magic offset。
3. 用布局探针检查 clip/overlap/overflow，再看截图和交互。
4. 覆盖双主题、动态字号、长文本、状态变体和安全区。
5. 将边界矩阵加入组件迁移验收，不能只检查节点存在。

## 消费与防复发

UI 迁移 Skill、设计系统组件说明、布局快照和视觉回归共同消费。回归固定长文本、大字号、双主题、
状态区出现/隐藏及边界探针；人工评审负责视觉节奏，机械探针负责几何不变量。
