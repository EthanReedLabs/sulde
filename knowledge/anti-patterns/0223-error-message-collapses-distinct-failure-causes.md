# NNNN — 异常归类不分真因,一条兜底错误消息掩盖上游故障

- **平台**:none

## ❌ 错误

调用链上有多种性质完全不同的失败(上游超时/连接中断、上游返回但内容不符合约定格式、
业务规则拒绝、内部逻辑异常),代码用一个宽泛的 `try/catch` 或一个统一的校验出口把它们
收敛成同一条错误消息:

```text
try {
    resp = callUpstream(...)        // 可能超时、可能断连
    data = parse(resp)              // 可能格式不符
    validate(data)                  // 可能业务不合格
} catch (e) {
    report("格式不合格")            // ❌ 三类真因塌缩成一句话
}
```

于是超时、断连、真正的格式错误在日志和告警里长得一模一样。排查者按消息字面含义去查
解析/校验逻辑,反复确认那段代码正确,却始终定位不到真因;故障因此被拖长(小时到天级),
而消息本身还在持续地把后来者引向错误方向。

## 为什么

- **错误消息是给未来的自己的证据,不是给当下的敷衍**。一条不区分真因的消息不是"信息量为零",
  而是**负信息量**:它主动断言了一个错误的方向,比什么都不报更糟——什么都不报至少还会去查全链路。
- **不同真因对应完全相反的处置**。超时该重试/扩容/查上游健康;格式不符该对齐契约或修解析器;
  业务拒绝该走用户提示。归成一类后,任何自动处置(重试策略、告警路由、降级开关)都只能按
  最粗的粒度做,要么把不可重试的重试到底,要么把可自愈的直接判死。
- **兜底 catch 的作用域越宽,塌缩越严重**。一个包住"调用 + 解析 + 校验"三段的 catch,
  必然把传输层故障说成语义层故障——错误分类的精度上限由 try 块的宽度决定。
- **兜底文案往往取自最常见或最后一个失败点**,于是低频但严重的上游故障永远穿着高频轻微问题的
  外衣出现,监控与人的注意力都被误导。这与"负缓存把临时故障固化"同源:一次瞬时故障被固化成一个
  长期错误答案,只不过固化的载体是错误消息而非缓存条目。

### ❌ 错误(变体):失败与"成功但无结果"塌缩成同一条记录

塌缩不止发生在多种失败之间,也发生在**失败与空结果之间**——后者更隐蔽,因为它伪装成正常运行:

```python
try:
    completed = subprocess.run(cmd, ...)        # 可能根本没启动
    results = json.loads(completed.stdout)      # 可能起了但没命中
except (OSError, TimeoutExpired, JSONDecodeError):
    results = []
log(query=q, scores=[], injected=[])            # ❌ 两种情形写出完全一样的记录
```

于是"检索跑了但没命中"与"检索进程根本没起来"在日志里长得一模一样。日志累积数百行
`scores: []`,没有任何人能从中看出功能其实从未工作过。该缺陷因此存活到下游数据大规模
积压才被发现,而**日志本身一直在场,只是不具备判别力**。

判据一句话:**空结果是一个业务事实,启动失败是一个系统故障,二者不可共用同一种表征**。

修法:给记录加一个明确的执行状态字段(如 `status: ok | spawn_failed | timeout | bad_output`),
使"跑了没命中"与"没跑成"在同一条记录里可区分;失败分支同时留下可诊断痕迹,
但**不得抛异常打断调用方**——静默的对立面是留痕,不是崩溃。

## ✅ 正确

- **区分"失败"与"成功但为空"**:空集合是有效结果,不能与异常路径共用同一条日志形态。
  一条记录要能回答"这次到底跑成了没有",而不只是"有没有产出"。
- **按真因分段捕获,不用一个 catch 包住整条链路**:调用、解析、校验各自独立捕获,各报各的因。
  try 块只包住"能产生同一类失败"的最小片段。
- **错误类型先分层再分类**:至少区分「传输/超时(不确定,可重试)」「上游明确的否定应答(确定,不必重试)」
  「内容不符合约定格式」「业务规则拒绝」「本地逻辑缺陷」。这些是不同的通道,不是同一个字符串的不同取值。
- **消息必须携带可判别的证据**:失败阶段、耗时、上游状态码/响应头、内容首片段预览、超时阈值。
  判据是——**只看这条消息,能不能唯一确定下一步该查哪里**;不能就说明分类不够。
- **禁止把"最常见的失败"当默认文案**:未识别的异常必须原样透出类型与堆栈,报成
  「未分类失败: <原始异常>」,绝不冒充某个已知失败。宁可报一个丑陋的未知错误,也不要报一个
  好看的错误答案。
- **给分类加回归**:对每一类真因构造一次故障注入(断网/超时/返回错误格式/返回业务否定),
  断言产生的错误消息各不相同且指向正确。分类正确性和功能正确性一样需要测试锁定。
