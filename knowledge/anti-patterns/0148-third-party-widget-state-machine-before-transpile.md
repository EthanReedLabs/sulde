# 0148 — 三方/复杂控件转译前必先抽状态机 + 内部数据模型 + 平台能力对照

- **平台**:跨端
- **复发次数**:1
- **lint 状态**:❌ 无法静态检查(转译判断类)→ 进 task / handoff 起草 checklist

## 现象

要求把源端(Flutter)的三方库或复杂控件"直接对齐"到目标端(ArkUI/HarmonyOS),但实施时只迁了调用处的文案、回调和分页接口,再用目标端**默认控件**包一层,结果真机体验/UI 明显不一致,反复返工。

两类典型:

1. **下拉刷新 / 上拉加载**:源端三方刷新控件有 idle/canRefresh/refreshing/completed/rebound/noMore 的多段式状态切换和柔和回弹;目标端只用系统 `Refresh` + 文案 + 外层 `setTimeout` 延迟,做不出几段式交互和回弹曲线,一闪而过。Header/Footer 的字号/高度/触发距离也和源端默认样式不一致。

2. **日期/时间等滚动选择器**:源端是 **lazy builder**(懒加载 + null-stop 边界)的选择器,目标端是**只收数组的 eager 选择器**(range 一次性收全量数组)。只看源端调用参数(`min/current/max`)就开写,直接把全量历史范围灌成一个巨大数组 → 卡顿 + 索引异常;又为修选中索引把滚动方向倒过来;再拿"当前值"当数据起点 → 列表只剩单项。

共性:多轮靠调延迟、改文案、改显示条件打补丁,始终到不了源端手感。

## 为什么

1. **把三方库/复杂控件当普通页面 UI 迁移**。只看调用处文案和回调,没抽控件级状态机。三方控件的真值不只是 `onRefresh/onLoading` 回调,而是完整的状态迁移图 + 动画时机。

2. **把目标端默认控件误判为可复用真值**。系统控件的下拉距离、回弹、完成态生命周期由系统托管,外层业务延迟接管不了系统动画。lazy builder 的懒加载/边界语义,eager-array 控件根本没有等价能力。

3. **源端没显式写的默认值被遗漏**。控件默认字号/高度/动画参数、全局配置(影响某些 tab 但不影响另一些),Flutter 没显式传≠不是真值。

4. **缺控件级验收矩阵**。只验"接口能刷新/分页能加载",没逐项验未过阈值/过阈值/释放/请求中/完成停留/回弹/短列表隐藏 footer/dark-light 等状态。

5. **只读调用参数不追内部模型**。不追到三方库/框架内部的数据模型(lazy vs eager、itemCount/null-stop、selected-index 语义、controller offset、滚动方向、边界裁剪),就无法判断目标端控件能否承载。

## ✅ 正确

遇到三方库或复杂控件转译,先做**控件级转译 gate**,再接页面:

**Gate 1 识别**:三方刷新/轮播/图表/富文本;sticky header / 自定义滚动物理;dialog/bottom sheet/popup;拖拽/长按/滑动/下拉手势;截图/进度/折叠动画 —— 任一命中即触发。

**Gate 2 追完整真值**:页面调用参数 + 项目全局配置 + 三方库默认值 + 关联 controller/callback 状态处理 + 真机截图/录屏。源端没显式写的默认值也是真值,不能用目标端默认值代替。

**Gate 3 状态机映射表**(实施前必产出):逐行列 `源端状态 | 触发条件 | 源端 UI/动画 | 目标端状态 | 目标端实现 | 是否一致`。目标端默认控件无法接管关键状态/动画时,标"不可作为真值",重做共享适配层。

**Gate 3.5 内部模型 + 平台能力对照表**(只读调用参数不算完成真值反抽):

| 项 | 源端真值 | 目标端能力 | 等价策略 | 验证 |
|---|---|---|---|---|
| 数据模型 | lazy builder / eager list / controller state | 组件是否 lazy / 是否只收数组 | 保持 lazy / 有限窗口 / 分页 / 自建适配层 | ✅/❌ |
| 数据规模 | itemCount / null-stop / 无限滚动 / 默认范围 | 最大安全 range / 初始化索引限制 | 上下限、窗口大小、默认起点 | ✅/❌ |
| 选中模型 | selected index / value / controller offset | selected / selectedIndex 语义 | 当前值仅作选中,不得误作数据起点 | ✅/❌ |
| 滚动方向 | index 增长方向 / 视觉方向 | 目标端视觉方向 | 禁为规避索引反转方向 | ✅/❌ |
| 边界裁剪 | min/max / disabled / null item | filter / clamp / disabled style | 列表首尾、时间边界 | ✅/❌ |
| 性能承载 | builder 懒加载 / 物理回弹 | 数组长度、渲染耗时、滚动帧率 | >500 项先 spike;>2000 项禁直接 range | ✅/❌ |

硬约束:
- ❌ 禁只读源端页面调用参数(`min/current/max` 等)就开写目标端。
- ❌ 禁把 lazy builder 直接转成 eager-array 控件而不做承载验证。
- ❌ 禁为修选中索引把滚动方向反过来;方向是真值的一部分。
- ✅ 数据超 500 项先做最小 spike 或复用已验证控件;超 2000 项须说明为何不卡,否则改有限窗口/分页/自建适配。
- ✅ 当前值只能作 selected/current;数据起点须来自内部模型或业务下限,不能临时拿 selected 当起点。

**Gate 4 样式默认值表**:fontSize/weight/color/lineHeight、header/footer height、触发距离、duration/curve、light/dark、empty/error/noMore/短列表等。

**Gate 5 共享适配层**:复杂控件预期 2+ 页面复用,先抽共享组件,页面只传业务回调和文案差异,禁每页复制一套状态机。

真机验完整交互(未过阈值/过阈值/释放/请求中/完成/回弹/短列表/无更多/dark-light)前,不能声明 UI 1:1 完成。

## lint 状态

- ❌ 无法静态检查(转译判断类)→ 落 task md / handoff 强制段:引用源端三方库/复杂控件但缺"状态机映射表 + 内部模型平台能力对照表 + 样式默认值表" → 禁止声明完成;review 时发现用目标端默认控件替代源端三方控件,须先证明状态机等价。
