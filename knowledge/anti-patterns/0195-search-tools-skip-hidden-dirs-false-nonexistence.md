# NNNN — 搜索工具默认忽略隐藏目录导致误判文件不存在

- **平台**:none

## ❌ 错误

用 rg / fd / glob 等现代搜索工具在仓库里搜索一无所获,就断言目标文件或配置"不存在",并据此做出后续决策(重建已有配置、误诊功能未启用、跳过状态恢复流程)。实际上文件位于隐藏目录(以 `.` 开头的目录,如 agent 工作目录、CI 配置目录、编辑器配置目录),搜索工具按默认规则跳过了它。

## 为什么

- rg、fd 等现代搜索工具**默认忽略隐藏文件/目录,且默认遵守 .gitignore**——"没搜到"只证明"默认可见范围内没有",不证明"文件系统里没有"
- 恰恰是隐藏目录最常存关键状态:版本控制元数据、CI/编辑器配置、agent/工具的工作目录、环境变量文件
- 这种误判是静默的:工具正常退出、零告警,断言者拿着"零结果"这个看似坚实的证据下否定性结论,错误随后被下游放大

## ✅ 正确

- 断言"文件不存在"之前,先加 `--hidden`(rg / fd)复查一次;必要时再加 `--no-ignore` 排除 .gitignore 规则的影响,或直接 `ls -la` 目标目录看全量
- 把"零搜索结果"定性为"默认搜索范围内未见",而非"不存在";否定性结论必须先确认搜索面已覆盖隐藏目录与被 ignore 路径
- 写自动化脚本/agent 流程时,凡以"文件是否存在"为分支条件的检查,用直接路径探测(test -f / stat)而不是内容搜索工具的命中数

## lint

无机械 lint;运行纪律——任何"搜不到即不存在"的结论,先补一次 `--hidden --no-ignore` 或直接路径探测再下断言。
