# 0152 — 图片资源对齐必须反抽渲染语义,禁止只校验 asset hash

- **平台**:跨端
- **复发次数**:1
- **lint 状态**:⏳ pending(进 task md / handoff 图片对位 checklist 强制校验)

## 现象

跨端 UI 对齐时,把某图标/贴图从源框架迁到目标端,只做了两件事:复制资源文件 + 校验 SHA256/字节 hash 一致,就判定"图片已对齐"。上线后视觉仍与源端明显不同。

排查发现:资源文件确实同源同 hash,但源框架的 `Image.asset`(或等价声明式图片 API)节点上还挂了一整套**渲染语义**,这些语义才是视觉真值的一部分,单独复制文件全部丢失:

- **scale**:源端写了 `scale: N`,同一张 `48×48` 原图逻辑视觉尺寸只有约 `16` dp;目标端不看 scale,直接把图拉满父容器,图标撑爆外层圆底。
- **fit / alignment / objectFit**:contain/cover/fill 差一档,可见区域和留白就不同。
- **color / tint(color filter)**:源端对线稿图标叠了 tint 染色;目标端只贴原图,颜色错。
- **opacity / filterQuality**。
- **父约束与叠层**:外层背景色、圆角、clip、`Positioned` 的 left/top、padding —— 透明 PNG 的可见效果是"图 + 父背景"叠出来的,漏掉父层背景/圆角/位置就还原不出。
- **dark/light/fixed 变体**:资源 getter 常有暗色/亮色/固定亮色多份,只同步 base 一份、只验一种主题就声明对齐。

典型误判:

1. 资源 hash 一致 → 判定图片已对齐。
2. 源端有 `scale` 但目标端只按容器尺寸拉满。
3. 透明 PNG 的外层背景、圆角、遮罩、clip 没一起迁移。
4. 资源 getter 有 dark/light 变体,目标端只同步 base。
5. 源端资源天然自带视觉效果(阴影/底色),目标端又额外补一层底色/边框/阴影。

## 为什么

**图片资源文件一致 ≠ 图片 UI 一致。**

字节/hash 只覆盖"这张图的像素内容",而屏幕上实际显示尺寸、透明区叠加、染色、裁剪、位置,全部由声明式图片 API 的**渲染参数 + 父容器约束**决定,这些不在文件里、也不在 hash 里。只比文件 = 只比了原料,没比成品。渲染语义是一个需要整体反抽的**闭包**:漏抽任一项(尤其 scale 和父背景),视觉就发散。

## ✅ 正确

任何图片/图标/贴图跨端对齐前,先补齐一张"资源渲染语义闭包表",逐项对照源端节点反抽,再决定目标端映射:

| 项 | 必查内容(源端) | 目标端映射 |
|---|---|---|
| 资源源头 | asset 名、getter、base/dark/fixed 变体、hash | 同步**全部**变体,不能只同步 base |
| 原始图像 | 宽高、透明区、可见像素框、是否自带背景/阴影 | 判断是否需要外层背景,或应删掉多余层 |
| 绘制参数 | `scale / width / height / fit(objectFit) / alignment / color(tint) / opacity` | 换算成目标端图片尺寸、objectFit、染色 |
| 父约束 | 外层容器 / 尺寸盒 / clip / 层叠 / 定位 / padding | 外层背景、圆角、位置、clip 一起迁移 |
| 主题矩阵 | light / dark / system / fixed 变体 | 绑主题切换策略,不是误跟系统资源模式 |
| 复验截图 | 同页同状态源端/目标端截图 | 修后看**实际像素**,不是只看构建通过 |

**scale 换算规则**:源端若写 `Image.asset(asset, scale: s)`,目标端**不能**默认把图拉满父容器,先算逻辑视觉尺寸

```
logicalSize = rawPixelSize / scale
```

再据此定目标端图片 width/height;父容器是 tight 约束时还要结合布局规则 + 实际截图确认。

禁止清单:

- ❌ 只复制图片文件,不反抽图片 API 参数。
- ❌ 只比 SHA256/hash,不查原图透明区和 `scale`。
- ❌ 透明 PNG 被父容器背景污染后,还去改资源文件。
- ❌ 源端只有图标,目标端额外加背景/边框/阴影(或反之,源端有外层背景,目标端把图标拉满外层)。
- ❌ dark/light 只验一种模式就声明对齐。

## lint 状态

⏳ 难做纯静态检查(需对照源端节点树)。落地为**流程 gate**:图片相关 UI task md / handoff 起手必附"资源渲染语义闭包表",每项标源端 file:line;复验必须同页同状态双端截图对像素,不能只看构建结果。
