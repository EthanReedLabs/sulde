# NNNN — 指挥方自宣"整体完成"不对照自建清单:近因语境压过常设指令

- **平台**:指挥/规划侧(完工判定类)

## ❌ 错误

指挥方(协调端 / 规划者 / 主 agent)自己写下了编制表、待办清单或阶段计划,过程中冒出临时问题就先修,修完凭"手头这轮做完了"的感觉宣告"整体完成"。两种形态:

| 形态 | 现象 |
|---|---|
| **A 自宣完工不对表** | 宣告"全部完成"前没有重新 Read 自己写的那张清单,未勾选项被静默跳过;下游按"已完成"继续推进,缺口在更晚的环节才暴露 |
| **B 反应式修复插队** | 刚报上来的问题占满上下文,于是插到规划序前面先做;做完后上下文里只剩"刚修完的东西",原定序列后半段被遗忘,且这次插队事后无人认领 |

两个形态常常同时发生:插队打乱了序,自宣完工又没有对表把序补回来。

## 为什么(根因)

**近因语境的权重压过常设指令。**

- 上下文里最新、最具体、最带情绪的内容(刚报的故障、刚跑完的那一步)天然抢占注意力;而"完工前对表""按规划序推进"是开场写下的常设指令,随上下文增长被稀释。**被跳过的项与近因痕迹的缺失是同一件事**——正因为它最近没被提起,它才既没做也没被想起。
- 清单是自己写的 → 产生"我知道里面有什么"的错觉,于是用记忆代替 Read。**记忆是压缩的,清单是原文**;压缩优先丢掉的恰好是从未执行、无近因痕迹的条目。
- "完成"在指挥侧没有可机械判定的定义。执行侧至少有 commit / 编译 / 测试这类硬信号,规划侧的"整体完成"若不绑定清单勾选,就退化成一句主观感受。
- 插队本身不一定错(真故障就该插队),错的是**插队无记录**:没有显式记下"偏离了原序 / 为何现在偏 / 原序停在第几项",临时决策就变成永久遗忘。

## ✅ 正确

1. **宣告即对表**——任何"整体完成 / 全部搞定 / 收工"类宣告前,重新 Read 清单**原文**,逐行标 ✅ / ❌ / N/A 并把对照表贴出来。**不贴表 = 宣告无效**;凭记忆复述清单内容不算对表。
2. **完成的定义写进清单本身**——每项在起草时就要可机械判定(有产物路径 / 有可跑命令 / 有可 grep 的标志)。不写"优化一下 X"这类无法验真假的条目,否则对表阶段只能靠主观判断,等于没有闸门。
3. **插队走显式登记**——反应式修复要插到规划序前面时,先落一行:插什么、为什么现在插、原序停在第几项。修完回到**那一项**,而不是回到"上下文里还剩什么"。
4. **未完项正面说出来**——部分完成就报部分完成:做了 A/B,C/D 未做及原因。缩小交付范围是委托方的决定权,不是执行方静默行使的。
5. **上下文压缩 / 会话切换后加倍执行**——压缩会优先保留近因、丢掉常设指令与早期清单,**压缩后的第一次"完成"宣告风险最高**。此时必须 Read 清单文件本体,不引用摘要里转述的清单。

## 自检三问(宣告完成前)

1. 我贴出逐行对照表了吗?表里的每一行是从文件里读出来的,还是从记忆里想出来的?
2. 这一轮有没有做过原计划之外的事?那次偏离登记了吗?偏离前停在哪一项、回去了吗?
3. 清单里有没有哪一项,我这一轮从头到尾一次都没提过?——**那一项就是最可能没做的那项**。
