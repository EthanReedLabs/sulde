# 0252 — 实际测试解释器的依赖预检放得太晚

- **平台**：跨端

## 问题原型

机器已有可用测试环境，但 Agent 通过 PATH 启动另一个 Python。全量套件跑很久后，
多个安装用例因缺少 `yaml` 同时失败，表现像一批无关代码回归。

## ❌ 错误

只在深层安装器预检依赖，昂贵的外层测试入口不检查实际解释器；修复时静默换环境，
却继续沿用原运行记录或把缺包失败记为可复用成功。

## 为什么错

预检未覆盖真正的测试启动入口，PATH 选择也没有绑定验收记录。实际复现确认默认
Python 缺少 PyYAML；指定既有受支持解释器后相关样本通过，无须修改被测运行代码。
外层预检能在不足一秒内报告环境失败。此证据排除了相关样本的业务逻辑根因，
不代表整个套件中的其他失败也都是环境问题，更不是 Windows 启动机制的验证。

## 适用边界

适用于依赖特定解释器和包集的测试、候选打包和发布验证。普通只读 Git 检查不应
承担 Python 依赖预检；轻量前置检查也不意味着把完整诊断扫描搬进每个成功热路径。
环境不满足时停止该测试入口，明确报告缺项，不自动安装包或偷偷切换解释器。

## 判定样本

### 路由正例

- **输入**：全量测试由未核验的 PATH Python 启动，跑到安装用例才大量报 No module named yaml。
- **预期**：apply
- **原因**：昂贵套件启动前没有预检实际执行环境。
- **来源**：observed

### 路由反例

- **输入**：只运行 git diff 查看文档差异，不执行 Python、打包或测试套件。
- **预期**：skip
- **原因**：动作不依赖 Python 包集，增加预检没有因果价值。
- **来源**：constructed

### 执行合格例

- **做法或输出**：外层入口在运行套件前拒绝缺 PyYAML 的解释器；显式选择已核验环境后相关复验通过，并记录实际解释器与依赖身份。
- **预期**：pass
- **原因**：提前暴露环境缺项，同时保留每次运行的证据归属。
- **来源**：observed

### 执行失败例

- **做法或输出**：把同一个缺包原因产生的多项失败分别归因于业务逻辑，再反复启动昂贵套件。
- **预期**：fail
- **原因**：没有消除共有的执行前置条件缺口，重复消耗时间且错误分类问题。
- **来源**：observed

## ✅ 正确

复用已有环境预检，以 `sys.executable` 或显式选定解释器为目标，在启动昂贵子进程
之前检查支持范围和必要依赖。记录解释器身份、依赖版本、源码摘要、命令与退出码。
环境失败与测试断言失败分开记录；换环境是新运行，不覆盖旧失败。依赖问题修复后
按影响范围复验，不将相关样本通过扩大成全量通过。

## 消费与防复发

消费者是任务运行器和 Agent 执行清单。回归使用缺依赖环境与已验证环境两组样本，
证明前者没有启动昂贵套件、后者能实际运行用例；同时保留失败日志和不可复用标记。
本条不修改生产依赖管理政策，也不声称单机验证覆盖所有平台。
