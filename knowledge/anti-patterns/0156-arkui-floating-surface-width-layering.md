# 0156 — 浮层不是一个宽度:遮罩 / 承载 / 视觉面板 / 内容必须拆层建模

- **平台**:HarmonyOS
- **复发次数**:1
- **lint 状态**:pending(适合扫描 `bindSheet.width`、浮层根 `.width(...)`、底部弹窗内嵌弹层 `.backgroundColor + .width(...)` 的组合)

## 现象

把一个浮层(bottom sheet / 全屏浮层 / 弹窗)当成"一个宽度"来设,结果反复返工:

- 把 `bindSheet.width` 直接设成内容宽(如统一 377vp),导致 sheet **承载层本身变窄**,而设计要的是承载区域铺满全屏、内容居中。
- 把白色背景 / 圆角 / 阴影挂到限宽的内容 `Column` 上,导致**视觉面板层跟着变窄**,而不是"全宽面板 + 内部内容居中"。
- 只改了入口第一层 sheet,漏掉点"新增 / 编辑 / 更多 / 删除确认 / 选择器"后弹出的**二级浮层**,它们有同样的分层却没被套用同一策略。
- 把"内容居中"误解成"整个面板居中限宽"。
- 机械替换 ArkUI 组件层级时破坏 `@Builder` 方法括号,导致后续 build 被解析进 UI 树内部。

## 为什么

- 浮层实际上是多层叠放:遮罩层、承载层、视觉面板层、内容约束层,还可能嵌套子浮层。这些层的宽度和背景归属各不相同,用一个 `sheetWidth()` 表达不了。
- 公共度量只暴露一个含混的 `sheetWidth()`,调用方无从区分它指的是承载层还是内容层,于是承载层被内容宽误限。
- `.backgroundColor` / `.borderRadius` / `.shadow` 无脑挂在限宽内容层,把"全宽面板"渲染成了"窄卡片"。
- 单点修一个 sheet 数字很容易,但同类浮层链路上每一级都要拆同样的层,不成体系就会漏级、复发。

## ✅ 正确

拆层建模,逐层标宽度语义,再决定背景归属:

```text
遮罩层     → 通常 100% / viewport
承载层     → sheet 是否必须铺满全屏(bindSheet.width = 承载宽,不是内容宽)
视觉面板层 → 白色背景 / 圆角 / 阴影挂这一层,width(100%) 全宽
内容约束层 → width(内容宽) + justifyContent(center) 居中限宽
嵌套子浮层 → 继承同一套分层策略
```

1. **列浮层链路**:入口浮层 + 每个二级浮层。搜 `bindSheet` / `bindContentCover` / `CustomDialogController` / `showDialog` / `Overlay` / action sheet / 新增 / 编辑 / 更多 / 删除 / 选择,逐个确认。
2. **背景归属检查**:确认设计是"全宽面板"还是"窄卡片",再决定背景 / 圆角 / 阴影挂哪一层,禁止无脑挂在限宽内容层。
3. **公共 API 命名必须分层**:禁止只保留 `sheetWidth()` 这种含混名;显式区分 `sheetContainerWidth()`(承载层) / `sheetContentWidth()`(内容层) / `dialogWidth()`,让调用方不会把承载宽当内容宽。
4. **截图两态验证**:横竖屏至少各验一个外层 sheet + 一个二级新增 / 编辑弹窗,核面板边缘、内部输入框 / 标题 / 按钮与页面内容宽度的关系。
5. **失败处理**:同一浮层宽度连续两轮不对,停止调数字,回到层级拆分图,先指出是哪一层错。

## lint 状态

- pending。适合静态扫描 `bindSheet.width` 直接绑定内容宽度度量、浮层根节点限宽 `.width(...)`、以及"限宽内容层同时挂 `.backgroundColor` + 圆角"的组合。
- 无法静态覆盖的部分进 task / review checklist:改浮层宽度前必逐层标"承载层是否全宽、视觉面板是否全宽、内容是否居中限宽、二级浮层是否同策略"。
