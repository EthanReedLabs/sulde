# XXXX — 沙箱权限噪声掩盖脚本真实行为,preflight 结论前需提升权限干净复跑

- **平台**:cross(任何沙箱/降权执行环境 + 依赖特权守护进程的工具链:adb、docker、系统服务等)

## 问题原型

受限宿主中的 preflight 或设备脚本因为 daemon、网络或远端 shell 权限不足，只得到部分输出、
占位字段或转义后的参数；上游仍把“脚本结束”解释为真实设备或生产环境结论。

## ❌ 错误

在沙箱(降权、受限)环境中运行依赖特权守护进程的 preflight/诊断脚本,输出混杂大量由沙箱拦截产生的权限报错;不加区分地基于这次运行的输出下结论——判定"脚本有 bug""功能不可用"或"检查通过"。

```text
sandbox 运行脚本
  → 守护进程连接/操作被沙箱拦截,刷出成片权限报错
  → 权限噪声与脚本自身行为产生的输出混在一起
  → 直接据此判定 preflight 结论 ❌
```

## 根因与证据

- 沙箱拦截产生的报错与脚本自身缺陷产生的报错在文本上难以区分,噪声淹没真实信号。
- 两个方向都会误诊:把环境限制误判为脚本缺陷(假阳性),或真实缺陷被权限噪声掩盖而漏判(假阴性)。
- 特权守护进程(如设备调试 daemon、容器 daemon)在降权环境下的失败模式往往是部分成功+部分报错,比整体硬失败更具迷惑性——脚本"跑完了",但行为已不代表正常环境下的行为。

一手回归显示，受限 Python 子进程启动 daemon 时会生成全 `UNKNOWN` 产物；宿主 shell 与设备端
shell 混用 quoting 时，空格、JSON 和通配符参数会发生二次解释。改为获批的宿主原生命令、
参数数组和远端层独立转义后，真实 preflight 才能与环境噪声分离。

## 适用边界

- 适用于沙箱内调用 adb、容器 daemon、系统服务或任何还会进入第二层 shell 的诊断流程。
- 若无沙箱的同配置复跑仍产生相同结构化失败，失败属于脚本或目标系统，不能继续归为权限噪声。
- 只读探针也必须报告 `unobserved`，但无需因此获得写权限；权限提升范围只覆盖必要入口。

## 路由正例

- **输入**：沙箱内设备探针生成全 UNKNOWN，获批 adb 直接调用却能读取完整字段。
- **预期**：apply
- **原因**：同一目标在权限边界两侧结果不同，且受限产物被误当成真实 verdict。
- **来源**：observed

## 路由反例

- **输入**：无沙箱、同设备、同配置运行仍返回结构化的签名不匹配。
- **预期**：skip
- **原因**：独立干净复跑已经确认真实前置条件失败，不是沙箱噪声。
- **来源**：constructed

## 执行合格例

- **做法或输出**：宿主用参数数组调用获批 adb，设备端参数单独引用；不可观测时非零且不落假产物。
- **预期**：pass
- **原因**：权限、两层 shell 和结果有效性均有独立边界，失败不会伪装成 PASS。
- **来源**：observed

## 执行失败例

- **做法或输出**：受限 subprocess 启动 daemon 后写入字段全为 UNKNOWN 的 JSON，并返回 0。
- **预期**：fail
- **原因**：格式存在不等于事实可观测，半有效产物会污染后续缓存和发布门禁。
- **来源**：observed

## ✅ 正确

- 判定 preflight 结论前,用提升权限(或无沙箱的干净环境)完整复跑一次,对比两次输出。
- 只有干净复跑中仍复现的行为,才可作为对脚本本身的结论;仅沙箱运行中出现的报错归因于环境。
- 沙箱内的运行只用于初筛与快速迭代,不用于最终判定;结论必须来自与目标运行环境权限一致的执行。
- 真机采集通过用户已批准的脚本或命令前缀在沙箱外执行；不要让受限 Python
  `subprocess` 临时启动 `adb` daemon，再把失败生成的全 `UNKNOWN` 报告当成设备实测。
- 脚本必须区分 `permission_denied` / `daemon_unavailable` / `metric_missing` 与真实度量值；
  环境不可观测时非 0 退出，缺失值不得伪装成 0 或 UNKNOWN 后继续放行。
- 主机层优先用参数数组调用 `adb`，避免多一层 shell 展开；`adb shell` 的含空格、JSON、
  通配符参数仍会进入设备端 shell，应在远端这一层做严格 quoting，或改用 stdin/临时文件
  传递。宿主 shell 和设备 shell 的转义不能混成一层。

## 消费与防复发

用 fake `adb` 覆盖 daemon 启动被拒、设备离线、远端参数含空格/引号/JSON 三类场景，
断言脚本返回非 0 或完整保真参数，且不会生成可被下游判为 PASS 的假采集产物。
