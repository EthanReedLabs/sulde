# 0174 原生客户端复用人机校验前置的 Web 通道导致渠道契约错配

- **平台**:跨端
- **复发次数**:1

## ❌ 错误

原生客户端因业务动作表面相同，直接复用人机校验前置的 Web 通道，却没有确认浏览器 challenge、cookie、脚本环境或请求凭证等前置条件。

## 为什么错

业务目的相同不代表渠道契约相同。Web 通道可能把浏览器环境和人机校验结果作为安全契约的一部分，原生客户端无法自然满足这些条件。若 endpoint 名称看似通用，渠道错配还容易被误判为普通服务端失败。

## ✅ 正确

- 为 Web 与原生客户端明确划分渠道契约；原生端调用服务端提供的原生通道。
- 将客户端渠道纳入 endpoint、请求体/header、安全策略和错误码的联合评审。
- 对需要人机校验的动作，定义原生可完成的 challenge 获取、证明提交与失败恢复流程。
- 用契约测试确认客户端渠道标识确实写入 wire，且服务端按对应策略处理。

## lint 状态

- ❌ 无法仅从 endpoint 名静态推断其安全前置条件。
- 人工 review：新增或复用高风险接口时，核对渠道、凭证来源与人机校验能力。
- 关联：业务场景错配与客户端渠道错配应分别检查；协议字段还需确保实际编码上 wire。
