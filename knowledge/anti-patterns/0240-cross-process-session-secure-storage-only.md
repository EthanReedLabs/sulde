# 0240 — 跨进程消费者只读加密凭据导致登录态分裂

- **平台**:HarmonyOS（机制可迁移到 Android/iOS 扩展进程）
- **复发次数**:1

## 问题原型

主应用仍保持登录，服务卡片、Widget、后台任务或其他 Extension 却显示未登录并要求重新
认证。期望所有进程对同一账号得出一致会话状态，实际各消费者分别读取和解释加密凭据；
历史密文不可解、系统恢复备份或密钥重建时，状态分裂尤其容易暴露。

## ❌ 错误

主应用、服务卡片、Widget、后台任务或其他 Extension 各自读取安全存储中的 token，并把空值或解密失败直接映射为“未登录”。

这种实现会出现一种反直觉状态：主应用仍显示已登录，扩展却要求重新登录。历史密文与当前密钥不匹配、系统恢复备份或密钥重建时尤其容易触发；如果主应用另有资料快照回退，而扩展没有，两边会对同一账号得出相反结论。

## 为什么错

1. **密文存在不代表可解**：密钥生命周期与持久化数据生命周期并不天然一致。
2. **恢复契约分叉**：每个进程各写优先级、回退和错误分类，修一处不会自动修复其他消费者。
3. **错误语义坍缩**：密文失效、存储 I/O、断网、服务端鉴权失效全部变成 `loggedOut`，基础设施故障被伪装成用户退出。
4. **持久消费者不会自动刷新**：即使主应用修复或恢复成功，已发布的卡片/Widget 也可能继续显示旧状态，直到下一次系统生命周期。

## 适用边界

适用于多个进程或扩展共享同一账号会话，且安全存储、资料快照或远端鉴权可能具有不同
生命周期的客户端。不适用于完全无共享会话、扩展只显示匿名静态内容，或服务端已经明确
返回当前账号凭据失效的真实退出。无法区分密文失效、I/O、断网与鉴权失效时，结果应保持
`infrastructure failure/offline/inconclusive`，不能默认 `logged out`。

## 判定样本

### 路由正例

- **输入**：主应用仍登录，但 Widget 在历史数据覆盖安装后突然要求重新登录
- **预期**：apply
- **原因**：命中跨进程会话消费者与安全存储生命周期分叉两个条件
- **来源**：observed

### 路由反例

- **输入**：服务端明确返回当前账号 token 已撤销，主应用和扩展都同步退出
- **预期**：skip
- **原因**：这是权威鉴权失效，不是本地解密失败导致的状态分裂
- **来源**：constructed

### 执行合格例

- **做法或输出**：各消费者复用共享恢复器，可信回退写回后 read-back，并刷新已发布实例
- **预期**：pass
- **原因**：恢复、错误分类、持久化验证和消费者刷新形成完整闭环
- **来源**：constructed

### 执行失败例

- **做法或输出**：只在主应用增加 token 回退，Widget 仍直接读安全存储并把空值当退出
- **预期**：fail
- **原因**：恢复契约继续分叉，同一账号仍可能产生相反会话状态
- **来源**：observed

## ✅ 正确

所有运行边界复用同一 session recovery，并返回可区分的结果：

```text
安全存储有效 token
  -> 使用
安全存储为空/密文不可解 + 当前账号作用域的可信资料含 token
  -> 重写安全存储 -> read-back 验证 -> 使用
两处都无有效 token
  -> missing session
存储/HUKS/Keychain/Keystore I/O 异常
  -> infrastructure failure
断网
  -> offline
服务端明确鉴权失效
  -> logged out
```

同时满足：

- 可信回退必须校验账号和环境作用域，不能恢复来源不明的 token。
- 写回成功后必须 read-back 全量验证。
- 日志只记录恢复来源、状态和错误类别，禁止输出 token 或密文。
- 登录、退出或自愈后主动刷新所有已发布消费者；服务卡片应枚举运行中实例并更新，而不是等待用户重加。
- 并发恢复和刷新使用 single-flight，避免重复写入和重复网络请求。

## 验证

- 单测：安全 token 正常、损坏密文后可信回退自愈、两处皆空、I/O 失败、断网、仅明确鉴权码登出。
- 真机：保留应用数据覆盖安装，证明历史密文/密钥迁移路径；全新安装不能替代此项。
- 多消费者：主应用、Extension、Widget/卡片在恢复前后得到一致状态，已有实例无需删除重建。

## lint 状态

`pending`：可扫描 Extension/Widget 网络入口是否直接读取安全存储 token 而未依赖共享恢复器；错误分类、可信作用域和真机迁移仍需单测与人工 review。

## 消费与防复发

由会话恢复设计 review、Extension/Widget 网络入口静态扫描、保留数据覆盖安装真机测试和
多消费者状态矩阵共同消费。静态检查可发现直接读取安全存储的入口；可信账号作用域、密钥
迁移和系统生命周期仍需人工 review 与真机证据，不能用单次全新安装替代。
