# NNNN — 实验特性放量单层开关,调试开关被误当生产开关

- **平台**:cross

## ❌ 错误

实验/调试特性只靠一层开关控制放量:调用方(配置项、参数、代码内 explicit opt-in)显式允许就直接走实验路径。调试期为方便打开的开关,发布后原样生效,实验特性被无门禁地放量到生产用户。

## 为什么

- 单层开关混淆了两个不同层次的控制:"这次调用想用"(调用方意图)与"当前版本是否允许真实用户用"(版本级风险决策)。合并成一个布尔,后者就消失了。
- 调试开关的默认语义会漂移:开发期图方便默认开,发布前忘记翻转;或某处 explicit allow 被原样复制进生产配置。
- 代价不对称:实验路径未经生产级验证,误放量的爆炸半径远大于"想用而没用上"的不便。

## ✅ 正确

- 做成"默认关闭的显式 policy + 独立门禁"双层:调用方必须显式声明意图(policy 默认关闭),且即使显式允许也要再过独立的生产 gate 才真正生效;gate 由版本级/放量级证据决定,不受单次调用方意图影响。
- 默认值一律保守:policy 默认关闭,gate 默认拦截;未知或未验证场景 fall through 到安全路径。
- 验收判据:任何一层单独打开都不足以让实验路径在生产生效;测试须覆盖"policy 允许但 gate 拦截"分支。
