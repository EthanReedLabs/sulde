# 0180 — 子代理暖会话无上限复用

- **平台**:协调端方法论

## ❌ 错误

为省去每轮重建上下文的成本,委托方无限复用同一个子代理(CLI agent / LLM 子进程)的
resume 会话:同域任务一轮接一轮下发,复用七八轮以上仍不换线程。

## 为什么

- resume 会话每轮**全量携带历史上下文**,长度随轮次线性膨胀;子代理单轮处理开销
  (读上下文 + 推理)随之增长,最终超过单轮时限
- 失败形态极难归因:**超时且零产出**——没有报错、没有部分改动、没有日志,
  表面看像"卡死",实际是上下文处理耗尽了时限
- 省下的重建成本是错觉:一次超时轮浪费的墙钟时间(约十几分钟)远超冷启动
  重建上下文的成本(项目地图 + 任务书,数十秒)

## ✅ 正确

- **复用设硬上限**(经验值 ≤3 轮),超限即冷启动新会话
- 冷启动的上下文重建走**结构化补偿**:任务书引用项目结构地图(如 PROJECT-MAP)
  与历史日志路径,让子代理做验证性快读而非全量重探
- 任何一轮出现超时,**不 resume 原线程重试**——先审查工作区(有无半成品残留),
  然后冷启动重发同一任务书
- 实测参照:同一任务在膨胀线程上超时(15 分钟零产出),冷启动后 4 分钟完成

## lint

无机械 lint;属委托协议纪律——委托方对每个子代理线程维护复用轮次计数,
到限即换,不凭"上一轮还挺快"续用。
