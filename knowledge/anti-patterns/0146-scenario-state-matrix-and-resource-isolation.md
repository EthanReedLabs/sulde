# 0146 — UI 还原前先建「场景 × 状态」矩阵,主题策略不同的资源必须拆名隔离

- **平台**:跨端
- **复发次数**:1
- **lint 状态**:❌ 无法纯静态检查(需 task 起草 checklist + 资源命名 grep)→ 进 UI task 契约强制段

## 现象

一个页面已经完成整体 UI 改造和安装验证,但其中的**分享卡 / 截图卡**场景仍多轮返工:

- 分享卡整体尺寸反复调整,footer 文案和图表间距不稳定。
- 页面态图表在 dark 模式出现**白色块**。
- 分享态图表在 dark 模式出现**黑色块**。
- 分割线、遮罩、模糊效果与真值源不一致。
- 用户反复追问"为什么又改了""为什么还是修改好多次才好"。

## 为什么错

### 1. 没把真值源里的 `showType/mode/from/isShare/isDarkMode/type` 分支当成 UI 状态维度

真值源里同一 widget/builder 常按分支切换标题底图、文字色、按钮色、遮罩色(如「页面态」vs「分享态」)。实施端初期把两种场景当成**同一个组件复用**,后续再用局部资源补丁修黑/白块 —— 状态之间互相污染。

### 2. 资源命名没体现场景,导致「跟随主题」与「固定主题」两种策略挤在同一个资源名上

多数移动端资源目录会按 `base` / `dark` 限定目录**自动选图**。当同名资源被两个场景共用,而这两个场景的主题策略互斥时就冲突:

- **页面态**需要跟随 dark/light 自动切换。
- **分享态 / 截图态**在真值源里固定浅色白卡,**不应**跟随 dark 目录切换。

继续用同一个 `<资源>.png` 会导致:
- 页面态误用浅色分享图 → dark 页面出现**白色块**。
- 分享态误用 dark 页面图 → 浅色卡片出现**黑色块**。

### 3. 先调视觉、后补状态矩阵

前几轮先改尺寸、footer、线条、遮罩,却没先建 `场景 × 主题` 矩阵。结果每修一个可见问题,又暴露另一个状态下的资源或颜色问题,陷入"修一处坏一处"。

### 4. 真值 1:1 与「用户覆盖项」没分层

如真值源分割线为某固定黑色半透明,用户要求"再淡一些"。这类需求应单独记为**用户覆盖项**,而不是继续混在「真值 1:1 还原」里反复判断。

## ✅ 正确

只要同一 widget/builder 存在 `showType/mode/from/isShare/isDarkMode/type` 等分支,**先产出状态矩阵,再改代码**。

### 强制状态矩阵(至少列出)

| 维度 | 示例 |
|---|---|
| 场景 | page / share / dialog / capture / finish |
| 主题 | light / dark / system |
| 数据态 | loading / empty / content / error |
| 交互态 | selected / disabled / pressed / final step |
| 资源态 | base 资源 / dark 资源 / 分享固定浅色资源 / tint |
| 覆盖项 | 真值之外用户明确调整的点 |

### 资源隔离命名

场景不同且**主题策略不同**的资源,必须拆名:

| 场景 | 命名示例 | 主题策略 |
|---|---|---|
| 页面态 | `<资源>.png` | base/dark 自动切换 |
| 分享态 | `<资源>_share.png` | base/dark 目录都放浅色同源图 |

**禁止**同一资源名同时承担「跟随主题」和「固定浅色/固定暗色」两种职责。

### 实施顺序

1. 先读真值源分支,标出每个 `showType/mode/type` 的 UI 语义。
2. 建 `场景 × 主题 × 资源 × 颜色 × 尺寸` 矩阵。
3. 决定哪些 builder 复用,哪些必须拆成 page/share 独立实现。
4. 先落资源命名和 theme 策略,再改布局。
5. 最后处理用户覆盖项,并在说明中明确「真值」与「用户覆盖项」的差异。

### UI task 提交前必答

1. 这个 widget 是否有 `showType/mode/type/from/isDarkMode` 分支?
2. 每个分支是否有独立的资源/颜色/尺寸/行为表?
3. 是否把 page/share/dialog/capture 误复用为同一个 builder?
4. 是否有同名资源同时承担「跟随主题」和「固定主题」?
5. dark/light 下每个场景是否都走了正确资源?
6. 偏离真值的点是否标成覆盖项?

任一答不上来,禁止开始改 UI 细节。
