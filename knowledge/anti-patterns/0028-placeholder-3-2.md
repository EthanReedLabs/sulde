# 0028 — 提交身份和分支不匹配

- **平台**:协调端 / Dev 协作纪律
- **lint 状态**:难静态扫描，人工 review

## ❌ 错误

```bash
git checkout dev/devA/featureX
# 在 featureX 分支上修了属于 Dev B 模块的代码
git as-a -m "feat: Dev B 模块改动"  # ❌ 这个改动应该是 Dev B 的身份
```

同一错误在跨模块任务中的表现，是把属于多个 Dev 的改动一次性用同一身份提交：

```text
某次 UI 修复同时涉及 Dev A 与 Dev B 负责的模块
全部用 Dev A 身份提交  # ❌ Dev B 模块失去归属与审计边界
```

## 为什么错

违反“谁的分支谁的代码”原则，破坏开发者身份、分支与代码归属的一致性。单块改动会让
提交身份直接错配；跨多个 Dev 的改动不拆分，还会让 handoff 与 git log 无法准确追溯
各段代码的责任和验收结果。两者是同一不变量在单块与批量场景中的表现。

## ✅ 正确

- 改某 Dev 的模块 → 切到该 Dev 的分支 → 用该 Dev 的身份提交
- 一次改动跨多个 Dev 的模块 → 按模块归属拆成独立提交，分别使用对应分支与身份
- handoff 按拆分后的提交列出范围与验证证据，不能用一个总提交掩盖多归属改动

## lint 状态

- ❌ 无法仅靠源码静态扫描；提交前核对“改动模块归属 ↔ 当前分支 / 提交身份”一致
- ⚠️ 可做提交门禁：跨多个已登记归属模块时，要求提交拆分清单与对应 handoff 证据
