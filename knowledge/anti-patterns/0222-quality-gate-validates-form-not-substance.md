# NNNN — 质量门禁只校验形态而不校验实质

- **平台**:跨端
- **复发次数**:1

## ❌ 错误

给自动化流程(红队评审、文档校验、产出物 lint)写死形态型合格判据:

```text
合格要求:输出必须包含至少 N 条列表项(以 "- " 开头)
→ 一份用加粗小标题 + 成段论述写成的高质量分析,列表项数为 0
→ 判定:不合格,打回
```

形态规则被当成质量规则:检查的是"长什么样",声称验的是"写得好不好"。

## 为什么错

1. **形态与质量之间没有因果关系。** 同一份内容用列表、段落、表格或代码块承载,信息量完全相同。以形态为判据,等于在质量维度上引入了一个与质量正交的随机变量。
2. **误杀方向是系统性的,不是随机的。** 越是需要展开因果链、条件与取舍的深度内容,越难塞进短列表项;形态门禁优先淘汰的恰好是高价值产出,留下的是形式合规的浅层清单。
3. **失败模式是无声的。** 被误杀的产出方不会去修门禁,而是绕开或干脆不再运行该流程。此时指标上看不到"不合格率上升",只看到"零拦截"——与"质量完美"在数据上无法区分。曾出现门禁上线后整整一天从未被真正执行过,而无人察觉。
4. **门禁的成本被外部化。** 写规则的一方只承担一次编写成本,误杀成本全部落在产出方身上,缺乏反馈回路时这个偏差不会自我纠正。

## ✅ 正确

**校验实质的可观测代理量,而不是表现形态。**

- **要素存在性**:规定必须回答哪些问题(现象是什么 / 根因是什么 / 正确做法是什么 / 如何验收),不规定用什么排版承载。要素可由列表、段落、表格或代码块任一形式满足。
- **规模下限**:用篇幅、要素数量等粗粒度阈值挡住空壳产出,阈值只做"明显过短"的兜底,不做质量分级。
- **可执行性**:检查产出中是否含有可被下一环节直接消费的内容(具体判据、可复现步骤、明确的接受/拒绝条件)。
- **形态一律放行**:任何形态检查降级为提示或建议,绝不作为拒绝理由。

**并配套误杀反馈回路**:

- 被拒产出必须保留原文样本与拒绝理由,而不是只记一个失败计数。
- 定期人工抽查被拒样本,判定其中形态误杀的比例;误杀率非零即视为门禁缺陷,优先于产出方的问题处理。
- 监控"该流程的实际运行次数",而不只是通过率。运行次数塌陷是门禁失效的首要信号——**零拦截必须先按"没人在跑"排查,再按"质量达标"解释**。

## lint 状态

- ✅ 可自动检查:门禁规则中是否存在形态型硬性判据(要求特定标记、固定模板、固定条数)。
- ✅ 可自动检查:流程的实际运行次数是否长期为零或骤降。
- 人工 review:每条硬性判据都要能回答"它验的是内容的哪个实质属性";答不上来的判据必须降级为建议。
- 关联:与"判据过弱、只验存在不验语义"是一对相反的失败方向——判据既不能弱到只看有没有,也不能强到只看长什么样;两者的正解都是"验语义实质"。
