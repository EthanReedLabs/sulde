# 0242 — 只读 MCP 中断被升级为外部效果干预

- **平台**：协调端方法论（Agent Hook / MCP 监督）
- **复发次数**：1

## 问题原型

Agent 宿主用 PreTool、PostTool 和 Stop 一类生命周期事件监督 MCP。一次明确声明为只读的
查询、截图或状态读取在完成回调到达前被中断。期望是保留“本次读取未完成”的审计事实，
实际却生成“外部副作用结果未知”的验证债务，并要求人判断一个本来没有写入效果的动作是否
成功。

该误判会把普通读取变成控制面阻断：后续安全动作被同一执行通道的 pending/intervention
拦截，人只能复制事件标识或重复确认，最终形成“为了证明没有发生写入而必须人工批准写入
结果”的自锁循环。

## ❌ 错误

- 只要未闭合事件的能力类型是 MCP，就一律进入外部效果账本，而不再检查其
  `read / write / destructive / unknown` 效果分类。
- 把“没有收到完成回调”直接解释为“可能已经产生外部副作用”。
- 对历史误判债务只提供人工成功/失败选择，或直接删除旧事件来恢复运行。
- 只修改批准文案和提示卡，却不修正产生错误 attempt、pending 与 intervention 的投影条件。

## 为什么错

“调用是否完成”和“调用是否可能改变外部状态”是两个正交维度。缺少完成回调只能证明
执行结果未知，不能凭空把一个读取动作变成写入动作。能力属于 MCP 也只是传输/工具分类，
不是副作用证据；真正的控制依据必须是经过参数和工具契约归一化后的效果类型。

已验证的一手证据包括：

1. 一次中断的只读媒体读取曾同时产生 unknown attempt、pending verification 和开放干预；
2. 将终态投影改为“只对实质写入效果升级”后，同一只读中断不再产生三类外部效果债务；
3. 遗留只读 attempt 通过追加 `abort` 裁决关闭，历史事件仍可重放，派生 pending 被清除；
4. 单元回归覆盖只读中断、遗留对账和实质写入保守分支；真实恢复会话中的只读命令通过，
   SessionStart、Prompt、Pre/PostTool、Stop 与 MCP 初始化观察均正常闭合。

已排除“插件没有安装成功”这一方向：新会话加载的新运行时代码能够通过完整宿主能力观察；
若只有旧会话继续执行旧逻辑，应按 [ap-0181](0181-live-session-plugin-hot-update-dangling-path.md)
处理会话快照问题，而不是扩大本条目的效果分类规则。

## 适用边界

- 适用于工具契约或参数已经明确证明 `effect=read`，但因取消、超时、宿主退出或回调丢失而
  留下未闭合事件的场景。
- 不适用于提交、发布、远端更新、数据库写入、文件覆盖等真实写操作；这些操作缺少完成回调
  时必须保持 unknown，并通过独立读回或补偿动作闭环。
- 工具名称看似只读但参数可触发保存、导出、刷新远端缓存等效果时，不能仅凭名称降级；应先
  完善参数级分类，证据不足继续保持 unknown。
- 新会话正常而旧会话仍报旧规则时，优先诊断运行时代际和会话快照，不把旧字节行为误归为
  当前规则回归。

## 判定样本

### 路由正例

- **输入**：只读 MCP 截图调用被取消后，监督器要求确认“外部操作是否成功”，并阻断后续读取。
- **预期**：apply
- **原因**：调用契约明确为 read，却进入外部效果干预，命中“能力类型覆盖效果类型”的核心条件。
- **来源**：observed

### 路由反例

- **输入**：向远端发布内容后宿主退出，既没有成功回调，也没有从远端独立读回结果。
- **预期**：skip
- **原因**：这是可能已发生的实质外部写入，保留 unknown 和效果干预是正确的安全行为。
- **来源**：constructed

### 执行合格例

- **做法或输出**：只读中断只追加未完成审计，不创建外部效果 attempt；历史误判通过追加式
  `abort` 对账关闭并清除派生 pending；真实写入的 unknown 与独立验证门保持不变，回归和真实
  宿主旅程均通过。
- **预期**：pass
- **原因**：同时恢复流畅读取、保留历史可追溯性，并未放宽真实副作用的证据要求。
- **来源**：observed

### 执行失败例

- **做法或输出**：取消人工事件摘要，但只读中断仍会创建 unknown attempt；或为清零状态直接
  删除历史干预 JSONL。
- **预期**：fail
- **原因**：前者只隐藏了错误控制面，后者破坏追加式审计；两者都没有修正效果分类不变量。
- **来源**：observed

## ✅ 正确

1. 在进入监督账本前先归一化效果类型；工具族、能力名和传输协议只能辅助分类，不能覆盖
   明确的参数级 `read` 证据。
2. Stop/取消对未闭合读取只记录“执行未完成”或 inconclusive 审计，不创建外部效果 attempt、
   pending verification 或人工干预。
3. 只有可能改变受控外部状态的操作才进入效果真值链；缺少回调时保持 unknown，随后使用与
   原写入通道独立的读回证据验证。
4. 对已存在的只读误判债务做追加式迁移：追加系统 `abort`/不适用裁决，删除可重建的派生
   pending，但不删除、覆盖或伪造旧 attempt 与干预事件。
5. `abort` 只撤销继续执行和重试资格，不声称历史外部效果成功或失败；因此恢复入口不得反过来
   要求那条旧事件先具备 effect replay authority。否则“缺少重放权”会同时成为必须 abort 和禁止
   abort 的理由，形成无法追加修复事件的控制面死锁。
6. 运行时升级后按 provider、session、call identity 和运行时代际配对回调；旧会话仍执行旧
   快照时保留旧字节并提示重启，不把跨代回调拼成同一次效果事实。
7. 回归矩阵至少覆盖：正常只读、只读中断、真实写入成功、真实写入缺回调、遗留只读债务
   对账、旧会话/新会话代际隔离。

## 消费与防复发

- Pre/PostTool 与 Stop Hook、MCP 适配层、效果投影器和人工干预生成器共同消费该规则。
- 机械门禁断言任何 `effect=read` 事件都不能进入外部效果 attempt/pending/intervention；同时
  断言真实写入缺少独立证据时仍保持 unknown。
- 对账测试必须从 append-only 事件重放投影，证明历史仍在、开放债务归零；禁止只检查最终
  JSON 状态。
- 恢复回归必须覆盖“历史 source event 不具备 replay authority，但系统仍可追加 non-effect
  abort 并停止重试”；若 abort 尝试重新生成或认领外部结果，测试必须 fail closed。
- 发布验证必须在新宿主会话跑真实只读旅程，并区分源码测试通过、安装产物就绪和当前会话已
  加载三种不同事实。

## lint 状态

- ✅ 可对“read 事件进入效果 attempt”建立静态/投影不变量测试。
- ✅ 可对遗留只读干预执行重放测试，要求 `interventions_open=0` 且历史事件数量不减少。
- ✅ 可用真实宿主能力矩阵验证 Prompt、工具前后置、Stop 与 MCP 初始化均来自当前会话。
