# 0149 — 页面同步只对齐可见像素,漏掉业务副作用链路

- **平台**:跨端
- **复发次数**:1
- **lint 状态**:pending(待 task md / handoff 模板强制校验)

## 现象

页面从真值端(如 Flutter)同步到目标端时,UI 节点树、颜色、字号、资源、主题已多轮对齐,肉眼验收看着"这页做完了"。但一条业务逻辑始终没实现——因为它不是单页静态 UI,而是一条跨 controller / 完成页 / 接口 / 详情页 / 列表页 / 全局事件的完整业务闭环。

典型:某提交动作在真值端 controller 里会弹一个"是否同步 / 是否推送"确认框,真正的副作用发生在完成页的一个推送接口里,列表 / 详情还依赖查询状态接口 + 撤销接口 + 事件刷新回显。只看页面 widget 完全看不到这条链路。

更隐蔽的一层:该逻辑被**账号状态门控**——只有某绑定状态(如 `status == 1`)的账号才会触发那个确认框;未绑定的账号跑一遍完全不出现,导致肉眼 UI 验收误判为"本页无隐藏逻辑"。

这不是某个功能的专项事故,而是所有页面同步的通用风险:任何页面只要存在动作、接口、副作用、状态回显、跨页刷新或隐藏账号状态,都可能在只看 UI 时被整段漏掉。与 **反模式 0083**(视觉对齐 task 误改业务链路)互为镜像——0083 是"改视觉时误删已有链路",本条是"对齐视觉时漏抽本该移植的链路"。

## 为什么

1. **UI sweep 没覆盖提交链路**:只对齐可见页面 / 按钮 / 弹窗样式,没逐个追 `submit / save / finish / more` 等动作后的分支。

2. **只读 page,没追 controller / service / event**:弹窗逻辑藏在 controller 的提交方法里,副作用藏在完成页,状态回显藏在列表 / 详情的查询与撤销接口,刷新靠全局事件——这些页面 widget 层全看不到。

3. **测试路径没覆盖隐藏状态**:逻辑被账号 / 登录 / VIP / 绑定 / 授权范围等状态门控,验收时恰好用了不触发分支的账号,肉眼就当"无逻辑"。

4. **接口域没反向校验到目标端**:真值端 `HttpUrl` 里明明有 push / revoke / 查询状态等一组接口,没用接口关键字反搜目标端实现,所以整个功能域被漏。

## ✅ 正确

页面同步任务在 **UI 真值 sweep 之后**,必须再跑一遍 **业务副作用链路 sweep**。只要页面或其子级场景存在以下任一行为,都按此 gate 执行,禁止把"当前页面肉眼可见 UI 已对齐"当作功能同步完成:

- 提交 / 保存 / 完成 / 编辑 / 删除;
- 收藏 / 点赞 / 反馈 / 同步 / 取消同步;
- 分享 / 举报 / 评价 / 支付 / 登录态跳转;
- 更多菜单 / bottom sheet / popup / dialog;
- 上传 / 生成报告 / 查看结果 / 进入完成页;
- 列表刷新 / 详情回显 / 全局事件刷新 / 本地缓存草稿。

**Gate 1 入口与状态源**:列全 page / controller / binding / service / model + 路由参数 + 全局状态 + 本地缓存 / 草稿 / crash restore + 影响分支的用户状态(登录 / VIP / 绑定 / 授权范围 / 新建 vs 编辑 / 历史记录)。

**Gate 2 动作链路**:逐个追所有主动作,每项标真值端 file:line——
| 动作 | 必追链路 |
|---|---|
| submit / save / finish | 校验 → 弹窗 → 上传 → 接口 → 完成页/返回页 |
| more / menu | 展开项 → 条件分支 → 接口 → 事件刷新 |
| share / feedback / sync | 弹窗 → 选择结果 → 接口副作用 → UI 状态回显 |
| back / close | 草稿/缓存/路由栈/键盘/未保存状态 |

**Gate 3 接口与事件闭环**:每个 endpoint 回答——谁调用 / 请求参数 / 成功后改哪些状态 / 失败怎么 toast·loading / 是否发全局事件 / 哪些列表·详情·完成页要刷新。

**Gate 4 状态矩阵**:至少覆盖 数据(loading/empty/content/error)× 用户(登录/未登录/VIP/绑定/未绑定)× 记录(新建/编辑/历史/已同步/未同步/不可同步)× 时间(当前/未来/超授权范围/解析失败)× 主题(light/dark)。

**Gate 5 目标端反搜**(核心):真值端每发现一个业务关键词,必须在目标端反搜同义实现——类名 / 工具名、接口路径、字段名、文案、事件名。搜不到 = 在 task md 里明列为缺口纳入验收,**不能靠肉眼 UI 验收跳过**。这是"链路真被移植"与"只是布局像"的唯一分界。

## lint 状态

- ❌ 无法纯静态检查(跨端链路补全属判断类)→ 进 task 起草 / 完工 checklist:
