# 会话隔离与显式任务续接必须组合验收

## 问题原型

同一目录的新会话按新规则拥有独立合同，但旧续接入口要求它已经属于源合同的
review lane。隔离本身正常，用户却无法展示旧任务的续接选择；手工把新 lane
塞回旧合同只会隐藏两个状态模型缺少转换的问题。

## 根因与证据

新入口已经采用分会话合同，续接还依赖旧共享合同前置状态。发现阶段的真实 CLI
失败与修复后的隔离 CLI 正反链支持该根因；已排除 Hook 未执行和复制 token
才能续接的解释。修复验证经过实际宿主入口，但 Allow/Deny 使用隔离人工输入
夹具，因此不能冒充生产真人批准或当前生产安装状态。

## 适用边界

适用于用户明确要求续接同一物理工作区的旧任务。全新任务应保持独立，不得自动
挑一个历史合同。已确认或忙碌的目标任务先处理显式任务边界；不同工作区的迁移
属于另一协议，不能直接复用同目录续接结论。

## 判定样本

### 路由正例

- **输入**：同目录新 session 已独立建合同，但继续旧任务时，预览仍要求目标 lane 预先存在于源合同。
- **预期**：apply
- **原因**：隔离入口与迁移入口采用不兼容的归属前置条件。
- **来源**：observed

### 路由反例

- **输入**：同目录新 session 要开始完全不同的任务，自己的独立合同已经正常建立，并未请求继承旧任务上下文。
- **预期**：skip
- **原因**：独立归属正是期望行为，不应发起旧任务续接。
- **来源**：constructed

### 执行合格例

- **做法或输出**：真实 CLI 经过双合同审查后原子切换路由；隔离 Allow 绑定当前任务，Deny 保持原路由，旧 grant 和债务均不复制。
- **预期**：pass
- **原因**：同时保留用户的续接选择与新会话隔离边界。
- **来源**：observed

### 执行失败例

- **做法或输出**：测试先手工创建源合同 lane，再把 Hook completed 当成续接成功；或复制旧 token 使测试通过。
- **预期**：fail
- **原因**：绕开了真实归属转换和当前会话授权，不是协议组合验收。
- **来源**：constructed

## 正确做法

只读选择明确的源任务，冻结源与目标合同及路由前驱；展示当前宿主的原生审查。
决定只绑定当前 provider/session、revision 和任务 epoch。Allow 后由可恢复事务
发布路由，Deny 保持原路由；不能复制 grant、旧批准回执、open event、待验证效果、
债务或 continuation token。

## 执行流程

`独立入口 → 显式选源 → 双合同只读审查 → 当前会话决定 → 原子路由提交 → 回读`。
模型摘要和目录相同只能帮助找回任务，不能代替批准。

## 验收与失败处理

覆盖新旧合同、Allow/Deny、来源漂移、重放、中断恢复及后续工具正负例。中断后
恢复同一事务，不手工造 lane；证据不足保持未绑定。隔离和续接各自单测通过，
不能替代它们组合后的真实入口验证。

## 消费与防复发

消费者是会话路由、原生审批与集成验收清单。检查源合同未被赋予新的目标权限，
目标合同没有继承历史效果，并让并发与回执验收覆盖新的双合同所有权模型。
