# 事实基线入库必须与下游产出同步交付

## 原则

以事实基线为源的文档工作流（挖掘事实 → 生成定制文档 → 生成问答/演练材料），三个环节必须同步推进、同批交付。只执行「事实入库」这一环，流程状态会显示为已推进，但用户手上没有任何可用产出——库本身不是交付物。

## 为什么

- 入库环节最容易单独完成：它输入明确、产出结构化、看起来像一个自洽的步骤，因此常被当成「先做完这步」的自然切点。
- 但事实基线的价值只在被下游消费时兑现。停在入库，等于把一个只读资料库当成了工作成果。
- 事实与下游产出脱节还会引入二次成本：下游生成时上下文已冷，需要重新读库、重新判断哪些事实可用，而这份判断在挖掘当时是免费的。

## 正确做法

1. 把「挖掘—定制产出—问答准备」定义为一个不可拆的交付单元，而不是三个可独立排期的步骤。
2. 每次新增事实后，立即在同一轮内产出至少一份下游文档，验证这批事实确实可用。
3. 若确因信息不足只能先入库，必须显式记录「下游未产出」的未完结状态，不得让流程标记为完成。
4. 下游产出暴露出的事实缺口，回写进事实基线，形成闭环而非单向管道。

## 验收

- 流程结束时，除库变更外至少有一份面向使用者的产出文件。
- 下游产出中引用的事实都能追溯到基线条目。
- 只入库、无下游产出的执行被判为未完成，而不是部分完成。
