# 失败触发诊断与串行返修范围冻结

## 问题原型

低频异常暴露后，最直觉的修法是在每次成功执行前加入更多检查；连续返修又把新发现的环境、报告、
优化问题全部并入当前任务。结果是高频成功路径变慢，验收面不断扩大，每轮修复都产生新的“必须项”，
任务失去可完成定义。

## 根因与证据

根因一是未比较诊断放在预检还是失败后的成本；根因二是没有把功能缺陷、验证环境、报告协议和
非阻断优化分层。已验证案例中，原始异常链和确定性读回足以在失败后确认根因，成功路径无需持续
检查；建立机器可读冻结清单和停止线后，只有既定验收或安全问题能解冻，普通优化进入后继任务。
已排除“从此不允许新发现”——新问题仍记录，只是不自动扩大当前交付。

## 适用边界

- 适用于低频失败、高频成功路径，且失败后证据仍可保留和重探测。
- 若失败会不可逆破坏数据或销毁唯一证据，必要预检仍必须位于热路径。
- 安全漏洞、数据损坏和当前验收阻断可以解冻；仅更优设计、报告美化或相邻问题不能自动解冻。
- 新发现证据不足时登记 `inconclusive`，不在当前轮盲修。

## 判定样本

### 路由正例

- **输入**：每次修复核验后又把相邻问题纳入，成功路径也累积越来越多持续检查。
- **预期**：apply
- **原因**：同时出现热路径膨胀和交付范围无停止线。
- **来源**：observed

### 路由反例

- **输入**：写入前必须校验唯一备份存在，否则失败会造成不可恢复数据丢失。
- **预期**：skip
- **原因**：这是必要的破坏性前置门禁，不应移到失败后。
- **来源**：constructed

### 执行合格例

- **做法或输出**：冻结当前缺陷与验收清单；成功路径无新增持续开销；失败时保存原异常并触发有界
  诊断；新发现按 blocker/deferred/inconclusive 分类，只有 blocker 经显式解冻进入当前轮。
- **预期**：pass
- **原因**：任务可终止，诊断能力仍保留。
- **来源**：observed

### 执行失败例

- **做法或输出**：口头说“冻结”，但每次发现都继续追加测试和修复；或为了性能删除所有诊断证据。
- **预期**：fail
- **原因**：前者没有停止线，后者让低频问题不可定位。
- **来源**：constructed

## 正确做法

1. 对每项检查记录频率、成本、失败后证据是否仍可取得及不可逆风险。
2. 必要安全预检留在热路径；可确定性重探测的重诊断只在失败后触发并有时间/次数上限。
3. 冻结清单分为功能、环境、报告、优化四层，每项写完成证据和 stop line。
4. 新发现先登记影响与证据；仅安全或既定验收 blocker 可申请显式解冻。
5. 宣告完成前重新读取冻结清单逐项对表，不能凭最近一轮修复的记忆判断。

## 执行流程

`classify → freeze → implement → normal-path gate → failure diagnostics → triage discovery → final checklist`。
插队修复必须记录原序位置，完成后回到冻结清单的下一项。

## 验收与失败处理

通过要求成功路径成本预算未回退、失败证据可定位、冻结清单零未解释项。后继优化有明确 owner/入口；
证据不足项保持 inconclusive，不阻断当前已声明交付。

## 消费与防复发

任务总纲、恢复监督器、性能评审、失败注入和最终验收共同消费。机械检查应比较冻结清单、实际变更
路径和最终报告，并拒绝没有解冻记录的新验收项。
