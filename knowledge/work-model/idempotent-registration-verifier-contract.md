# 幂等登记与独立验证共享契约

## 问题原型

Agent 已获准登记限定本地关系，相同输入多次出现后却触发次数授权门；或者存储端
把重复行忽略，验证器却要求本次新写入来源，导致成功响应后债务不能结算。
完成回调丢失时，再执行写入还可能进一步污染来源和审计。

## 根因与证据

授权、规范化、`INSERT OR IGNORE` 及精确 verifier 对“同一请求已经完成”的定义不同。
真实隔离 CLI 中十次相同登记只保留一条关系和事务回执；模拟丢失 Post 后，由新进程
只读验证并结算，没有重放原写入。来源不符被拒绝，既有来源没有被重复请求覆盖。
这是限定幂等本地能力的证据，不是任意外部 MCP 写入的自动授权。

## 适用边界

适用于已授权、输入有界、目标明确且存储可独立验证的本地登记。重复次数不是风险
类别，但仍须验证当次身份和范围。外部效果、破坏性操作、未知结果或来源冲突不能
借“幂等”豁免；工具成功响应也不是独立效果证明。

## 判定样本

### 路由正例

- **输入**：同一已授权记忆关系第十次登记被次数门拒绝，或重复行被忽略后 verifier 无法认可原来源。
- **预期**：apply
- **原因**：请求幂等性、来源和效果验证缺少一致定义。
- **来源**：observed

### 路由反例

- **输入**：外部付款、控制面改写或破坏性动作声称重复调用无害，要求复用本地记忆登记豁免。
- **预期**：skip
- **原因**：不属于有界、可独立证明的已授权本地登记能力。
- **来源**：constructed

### 执行合格例

- **做法或输出**：真实 CLI 多次相同请求只有一条存储关系和回执；丢失完成回调后只读结算，原来源不变，写者没有再次执行。
- **预期**：pass
- **原因**：持久存储、请求身份与独立验证闭合，重复请求不新增副作用。
- **来源**：observed

### 执行失败例

- **做法或输出**：仅凭工具返回成功消除未知债务，或为了匹配 verifier 把旧关系的来源改成本次会话。
- **预期**：fail
- **原因**：前者缺效果证明，后者伪造来源历史。
- **来源**：constructed

## 正确做法

版本化请求规范与摘要，令授权入口、writer 和 verifier 消费同一语义。事务内检查
重复及来源冲突，原子持久化业务结果与回执；冲突时整批回滚。独立只读 verifier
逐项核对目标、请求、来源和实际存储，不将摘要相等本身当成执行成功。

## 执行流程

`检查当前权限和身份 → 规范化请求 → 事务去重与写入 → 回执 → 独立只读验证`。
完成回调缺失进入验证恢复，不进入自动写入重试。

## 验收与失败处理

同输入多次请求、跨来源、冲突批次、丢失 Post、损坏回执均有正反例。无法独立证明
时保留 unknown；是否重试由原授权与风险边界决定，不能由模型自行宣布“肯定没写”。

## 消费与防复发

消费者是登记能力、MCP writer、独立 verifier 与验收清单。检查数据库实际行数、
事务回执和来源，不以输出计数代替存储证据。真实 CLI 夹具、人工决定夹具及生产
观察必须在报告中分别标明。本知识不自行授予任何执行权限。
