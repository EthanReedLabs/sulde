# 迁移切流前的最终备份验证

## 问题原型

迁移脚本和预演均通过，团队准备释放旧数据库或切换流量，却没有在最终时点重新生成并验证备份。
切流后才发现源连接已经释放，最新数据无法再导出，只剩较早的备份，恢复点和数据缺口不明确。

## 根因与证据

根因是把历史备份、迁移预演和最终可恢复性当成同一事实。已验证做法是在切流门前重新执行备份、
记录源水位与摘要、对隔离目标做恢复探针，再允许释放源。若源已不可用，只能选择最后一份已验证
备份，并把恢复点与可能丢失窗口作为显式风险；不能伪造“最新备份”。已排除“迁移成功即可不要备份”——
迁移正确性不覆盖切流、回滚和最后写入窗口。

## 适用边界

- 适用于数据库、状态库、账户资料和其他有写入窗口的数据迁移。
- 可完全从不可变上游重建的缓存不需要业务备份，但应有重建验证。
- 源仍可访问时不得因为已有旧备份而跳过最终备份。
- 源已释放时禁止重新声称实时一致，只能降级到已知恢复点并要求风险决策。

## 判定样本

### 路由正例

- **输入**：迁移准备切流，但最后一次备份早于当前写入水位，且尚未做恢复读回。
- **预期**：apply
- **原因**：最终恢复能力没有被当前证据证明。
- **来源**：observed

### 路由反例

- **输入**：纯派生缓存可从内容寻址源完整重建，重建探针已通过。
- **预期**：skip
- **原因**：没有不可重建业务状态。
- **来源**：constructed

### 执行合格例

- **做法或输出**：切流前备份绑定源身份、水位、时间和 SHA-256；在隔离目标恢复并验证关键计数；
  只有通过后释放源。源已释放时明确使用最后 verified 备份、恢复点和缺口。
- **预期**：pass
- **原因**：回滚资产真实可用，风险被准确披露。
- **来源**：observed

### 执行失败例

- **做法或输出**：只检查备份文件存在，未恢复；或源已释放后把旧文件重命名为 final/latest。
- **预期**：fail
- **原因**：存在不等于可恢复，命名不改变恢复点。
- **来源**：constructed

## 正确做法

1. 冻结切流水位和源身份，停止或界定最后写入窗口。
2. 生成最终备份，记录时间、水位、大小和内容摘要。
3. 在隔离目标执行恢复，核对 schema、关键计数和代表性记录。
4. 把恢复证据接入切流 gate；失败则保留源并阻断切流。
5. 源已释放时只使用最后 verified 备份，披露恢复点和潜在缺口，由相应权威决定是否继续。

## 执行流程

`freeze watermark → backup → hash → isolated restore → verify → cutover → post-cutover readback`。

## 验收与失败处理

备份生成失败、摘要漂移、恢复失败或计数不符均阻断切流。源已不可用且备份未验证时保持 blocked，
不得用迁移脚本 PASS 替代。

## 消费与防复发

迁移 runbook、切流 gate、备份工具和灾备演练共同消费。回归覆盖空备份、截断、旧水位、恢复 schema
不兼容、源释放后降级和成功切流后的读回。
